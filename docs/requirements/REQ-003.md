## Context

The heart of DevSteward is a content-agnostic loop: resolve the next eligible step in
dependency order, invoke `claude -p` headless, classify, verify, commit, advance. It
knows nothing about requirements — everything domain-specific is injected through seams.

## Decisions

| # | Decision | Rationale |
|---|----------|-----------|
| 1 | Ledger = `state.yaml` (cursor) + `events.jsonl` (append-only) | Git-friendly text; REQ stays the spec |
| 2 | Four seams: StepSource, Verifier, DecisionGate, AccountProvider | Keep the core generic and testable |
| 3 | Eligibility = status pending + all deps done, in id order | Deterministic, reproducible runs |

## Requirement

The ledger reads/writes `state.yaml` and appends events. The executor computes eligible
steps, runs a step (invoke → classify → verify → commit → advance), and exposes attended
(`advance_once`) and unattended (`run`) drivers.

```yaml acceptance
- id: AC1
  text: The ledger round-trips state and appends events; step status transitions persist.
```
