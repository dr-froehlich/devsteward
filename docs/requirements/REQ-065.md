## Context

FlowSteward REQ-045 surfaced two engine-level defects that interact badly:

**Defect 1 — land gate fires after the session.** The `CompositeLandGate` (concept-artifact
gate + plan-artifact gate) lives inside `mechanical_land()`, which runs only after the
validation session has finished and all manual sign-offs have been collected. A formality
failure — missing concept doc, missing plan — therefore wastes a full paid session and every
human oracle it contained. The gate's job is to guard the land commit; it should never
require spending a session to discover a pre-existing red.

**Defect 2 — no recovery path for a gate-refused validate.** REQ-056 established that a
land-gate refusal sets the step `FAILED` (not `BLOCKED`) so `steward repeat` can recover it.
But `steward repeat` re-arms the step for a complete re-run, which for a validate step means
re-spawning the session and re-collecting every sign-off. When the refusal was a formality
error the developer can fix in two minutes, losing the session's work is disproportionate.

**Root cause of the FlowSteward incident:** a concept session wrote `docs/concepts/REQ-045/concept.md`
(directory style) while the gate and the manual both specify `docs/concepts/REQ-NNN.md` (flat
file). The session had no in-context guidance — `CLAUDE.md.tmpl` (the template stamped into
consumer projects) does not mention the concept path convention. `STEWARD.md` does, but only
in the middle of the gate description; a session driving a concept phase is less likely to
read the gate spec than a high-level CLAUDE.md note. Both documents need the path called out
explicitly in the concept-phase context, and the CLAUDE.md.tmpl must carry it so consumer
project CLAUDEs inherit the rule automatically.

FlowSteward's own CLAUDE.md cannot be updated mechanically by this REQ — it was stamped at
onboard time and the template is not re-applied automatically. The operator must update it by
hand after this REQ lands (see Notes).

## Decisions

| # | Decision | Rationale |
|---|----------|-----------|
| 1 | Move the full `CompositeLandGate` check into `start()` | One rule: `start()` is the pre-flight checkpoint. Any gate that would refuse land must refuse before the session. Both the concept-artifact and plan-artifact gates move together — there is no reason to split them. |
| 2 | `steward reland REQ-NNN` replays `mechanical_land` from the last green `validation` event | The session ran; the sign-offs are durable in the event log. Replaying the land without re-running the session is strictly correct — it re-certifies the same green that was already recorded, now that the formality is satisfied. |
| 3 | Concept path convention: flat `docs/concepts/REQ-NNN.md` (not directory) | The gate, `STEWARD.md`, and `_02-engine.qmd` all specify the flat path. Canonicalise this in `CLAUDE.md.tmpl` so consumer CLAUDEs inherit the rule. The directory-style file in FlowSteward REQ-045 is a session error, not an alternative convention. |
| 4 | `steward reland` refuses gracefully for any step that does not match the exact shape: FAILED step + last validate event ok=True + last land_refused event | The command has narrow, safe preconditions. Anything outside that shape — a red validation, a rework, a develop step — is a hard refusal with a diagnostic. |

## Requirement

### 1. Pre-flight gate in `start()`

`ValidateRunner.start()` (in `devsteward/profiles/req/validate.py`) runs the full
`CompositeLandGate` before setting the step to `RUNNING` or spawning any session. A gate
refusal returns a terminal `StepResult(step, RunOutcome.REFUSED, refusal)` and leaves the
ledger and tree unchanged. The gate is not called a second time inside `mechanical_land` for
the same step — the pre-flight check is sufficient.

### 2. `steward reland REQ-NNN`

New CLI command (parallel to `steward repeat`, `steward revalidate`). Preconditions:

- The step `REQ-NNN:validate` is `FAILED`.
- The most recent `land_refused` event is more recent than (or co-timestamped with) the most
  recent `validation` event with `ok=True`.
- That green `validation` event exists.

On success:
- Flips the step back to `RUNNING` (same bookkeeping shape as `start()`).
- Calls `mechanical_land` using the `detail` reconstructed from the saved results in the green
  `validation` event. Carries the signoffs forward — no re-prompting.
- The normal `mechanical_land` path then runs the (now-fixed) gate, commits, and advances
  the cursor to `DONE`.

On precondition failure: clear diagnostic (`steward reland` only applies to a validate step
FAILED by a land-gate refusal — for a red validation use `steward revalidate`, for a develop
step use `steward repeat`).

### 3. Documentation: concept path in `CLAUDE.md.tmpl`

`devsteward/templates/CLAUDE.md.tmpl` gains a concept-phase note in its house-conventions
section: the concept doc **must** be written at the flat path `docs/concepts/REQ-NNN.md`
(not a subdirectory). The gate enforces this at land; creating the file at a different path
will cause the develop land to fail with a formality error.

## Notes

**FlowSteward CLAUDE.md**: cannot be updated mechanically by this REQ. After this lands, the
operator must manually add the concept path convention to FlowSteward's `CLAUDE.md`. Suggested
addition under house conventions:

> Concept doc path: when a REQ declares `process.concept: true`, the concept document **must**
> be written at `docs/concepts/REQ-NNN.md` (flat file, not a subdirectory). The develop land
> gate enforces this; a file at `docs/concepts/REQ-NNN/concept.md` will not be found.

**FlowSteward REQ-045**: the existing `docs/concepts/REQ-045/concept.md` must be moved to
`docs/concepts/REQ-045.md` and `concept_refs` updated before `steward reland REQ-045` will
succeed. That is a FlowSteward-side action, not part of this DevSteward engine REQ.

**Scope boundary**: this REQ does not change what the gate checks — only when it runs (pre-flight
vs. post-session) and adds the recovery command. The gate's pass/fail logic (flat file exists,
`concept_refs` names it) is unchanged.
