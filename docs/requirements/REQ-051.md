## Context

Stage D of REQ-047 (plan `docs/plans/0026-single-source-of-truth-trunk-based.md`),
layered on the trunk-based foundation REQ-048 established. Implemented **by hand**, not
under `steward` — the engine has not yet earned the right to drive its own repair.

This closes REQ-047 Decision 6 (it absorbs the old REQ-045): **lab fixtures are committed
upstream, and the System Tester never improvises.** The trigger that fed the firefighting
loop's dirty tree was a System Tester that needed a fixture the lab lacked, created one to get
the validation moving, and left it uncommitted — an uncommitted improvised fixture is exactly
the divergence the single-source-of-truth model forbids. The fix is two teeth, the oracle for
both being *git cleanliness* (not the session's word):

- A **missing** declared fixture (no committed file under the path) is a hard red that names
  the gap — the validation stops; committing the fixture upstream is a human's call.
- An **untracked** file under a declared fixtures path means the Tester improvised — the
  validation is refused and the improvised file is discarded, so no uncommitted fixture is
  left in the tree.

The guarantee is narrow: it keeps validation reproducible (every fixture a validation rests on
is captured by the commit it was validated against) and removes the dirty-tree trigger; it does
not author fixtures for anyone.

## Decisions

| # | Decision | Rationale |
|---|----------|-----------|
| 1 | **Declared in `process.fixtures`** (repo-relative paths), alongside `process.lab`. The schema is widened to accept the new array; `ReqFile.process` defaults it to `[]`. | A REQ already declares its lab needs in the `process:` block; the fixtures it rests on belong with them, machine-readable, defaulting to empty so every existing REQ is unaffected. References are paths (not REQ ids), so the linter needs no new resolution rule. |
| 2 | **The engine enforces it in the artifact gate** (`ReqValidateRoutine._check_fixtures`, folded into `_artifact_gate`): for each declared fixture, git classifies tracked vs untracked. Untracked → improvised (hard red, file discarded); no tracked file → missing (hard red, gap named). The result rows ride into the dated evidence event. | The "no artifact captured → hard red" teeth already live there and already record into the evidence event; extending them keeps one gate, one place the gap is captured durably. The session's report carries zero gate weight (REQ-030 D2) — only git state does. |
| 3 | **The improvised file is discarded by the engine.** REQ-049's rollback (`reset --hard`) restores tracked state only — it leaves an untracked improvised fixture in place. So the gate unlinks the untracked file itself, scoped to the declared fixtures pathspec, before recording the red. | "No uncommitted fixture is left in the tree" must hold by construction, not by hoping the operator cleans up; the deletion is surgical (only the exact declared path's untracked files), so it cannot touch anything the validation legitimately produced. |
| 4 | **Real-git, fail-open safety net.** A no-op when there are no declared fixtures or no repo (the in-memory fake), mirroring the REQ-050 self-check. | A reproducibility guard must not brick a legitimate validation; with nothing declared there is nothing to enforce, and the in-memory loop has no git state to read. |
| 5 | **The skill makes the human contract explicit.** `system-test/SKILL.md` (and its hardlinked template) and the handbook tell the Tester: a missing fixture is a hard red you stop on — never write, generate, or improvise one. | The engine catches improvisation after the fact; the skill prevents it up front and routes the decision (commit it upstream) to the human, where it belongs. |

## Requirement

- A REQ names the fixtures its validation requires in `process.fixtures`; the System-Test
  phase refuses to certify green if any declared fixture is missing (not committed) or if an
  untracked file sits under a declared fixtures path (the Tester improvised).
- A refusal is a hard red with the gap captured in the dated evidence event; the REQ does not
  flip `done`, and the tree carries **no uncommitted fixture** (an improvised file is
  discarded).
- A fixture committed upstream clears the gate — the check raises no false positive.
- The System Tester skill and handbook state the contract: a missing fixture is a
  hard-red-and-stop; never improvise one.

## Notes

- **Why git cleanliness is the oracle.** The whole REQ-047 thesis is single-source-of-truth:
  the committed tree is the only state that counts. A fixture that is not committed cannot be
  reproduced by a later checkout of the validated commit, so a green resting on it is a false
  green — symmetric with REQ-050's commit integrity (a develop green the commit doesn't
  capture). REQ-051 is the validation-side analogue.
- **AC5 is `check: artifact`** (per REQ-047) — but the artifact whose self-sufficiency it
  proves is the *fixture*, and the oracle is real git, so the test is real-git teeth (a
  throwaway `git init` repo, only `claude` faked), in the family of
  `tests/test_commit_integrity.py` / `tests/test_transaction_boundary.py`.
- **Id note.** The plan reserved REQ-051 for this Stage D, and the landed REQ-049/050 already
  reference "REQ-051 (lab fixtures)" as the remaining stage. A later raw stub had taken the
  REQ-051 id; it was renumbered to REQ-052 (draft) so this REQ keeps the reserved id and those
  cross-refs stay honest.
