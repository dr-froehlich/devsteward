## Context

The package ships `req.schema.json` twice: `devsteward/schema/req.schema.json`, which
`steward lint` actually reads (`files("devsteward") / "schema"`), and
`devsteward/templates/docs/requirements/schema/req.schema.json`, which `steward new` stamps
into a consumer's `docs/requirements/schema/`. The second copy has drifted two REQ-cycles
behind the first:

- **REQ-048** widened `supersedes` to accept a list of ids. The stamped copy still carries
  the pre-REQ-048 shape (`type: [string, null]` + pattern), so a REQ retiring a stack —
  exactly what REQ-048 exists to express — reads as invalid against it.
- **REQ-051** added `process.fixtures`. The stamped copy lacks it, and the `process` block is
  `additionalProperties: false`, so a REQ declaring lab fixtures reads as invalid against it.

Both drifts have the same cause, and it is not carelessness about an unknown obligation:
**REQ-021's own Requirement text names both paths explicitly** ("in both
`devsteward/schema/req.schema.json` and `devsteward/templates/...`"). The obligation was
written down, understood, and then silently forgotten twice, because nothing mechanical
enforced it. That is precisely the failure REQ-094 diagnosed for the shipped manual — a
hand-remembered same-commit duty with no derived guard.

The natural reflex is to fix the two fields and add a guard. The evidence says the copy
should not exist at all:

- **No Python reads it.** `grep` over the package finds no reader of the stamped path;
  `lint` reads the packaged schema regardless of which project it is run in.
- **No shipped doc points at it.** `STEWARD.md` and `CLAUDE.md.tmpl` mention schema-validity
  only as a property `steward lint` enforces — neither sends a consumer agent to the file.
- **`steward sync` does not track it.** The tracked set is engine-derived (REQ-066/086) and
  is skills + `STEWARD.md` + `_templates/req.md`. So the copy is not merely stale — it is
  *unmaintainable*: no verb can ever update it in a project that already has one.
- **Half the fleet lives without it.** It is present in flowsteward, docsteward, DriveSteward
  and clauder and absent from memzy, THermo, examengineer and sarah — and nothing has ever
  distinguished the two groups.
- **It has been wrong since REQ-048 with no reported consequence**, which is the strongest
  available evidence that nothing depends on it being right.

The decisive observation is structural. Every *other* artifact this package ships in two
places has been deliberately unified so that drift is impossible: `_templates/req.md` is one
**inode** shared with its stamped twin, the root `STEWARD.md` is a **symlink** to the
template, the bundled skills are inode-shared with theirs, and DevSteward keeps **no own
schema copy** at all — it dogfoods against the packaged one. The schema is the single
genuine two-file duplicate in the package, and it is the one that drifted. The house pattern
for "one artifact, two locations" here is already *one file*; this is the one place that
pattern was never applied.

So the fix is subtraction, in the shape REQ-083 and REQ-095 established: delete the
reader-less artifact rather than build a synchronizer to keep an unread file honest.

## Requirement

1. **`devsteward/templates/docs/requirements/schema/`** — the directory and its
   `req.schema.json` — is deleted from the package. `steward new` stamps the template tree
   with a generic `rglob` copy, so no stamping code changes: the directory simply stops
   existing and stops being copied.
2. The package ships **exactly one** `req.schema.json`, at `devsteward/schema/`.
3. A project stamped by `steward new` contains **no** `docs/requirements/schema/` directory
   and still lints with **no schema problems** — the deletion removes nothing `lint` needed,
   because `lint` never read the stamped copy.
4. **DevSteward's own `/CLAUDE.md`** records the invariant under House conventions: an
   artifact shipped in two locations is unified at the filesystem (inode-shared or
   symlinked), never duplicated as a second file. It is **not** added to
   `CLAUDE.md.tmpl`, `STEWARD.md`, the handbook, or any bundled skill.
5. `tests/test_req095_develop_key_retired.py::test_no_live_develop_declaration_in_package`
   asserts the retired-`develop:` description over the surviving schema only.

## Notes

- **Process declarations:** none — defaults apply (no concept phase, no lab). Every criterion
  is a filesystem or lint assertion writable at intake, so no concept phase is warranted, and
  with no `artifact`/`manual` check there is no System-Test phase.
- **Drift detail, for the record.** Stamped copy vs packaged: `supersedes` is
  `{"type": ["string", "null"], "pattern": ...}` instead of REQ-048's
  `oneOf[null, string, array]`; `process.properties` is `{develop, concept, lab}` instead of
  `{develop, concept, lab, fixtures}`. Both files carry the same `$id`. Git history shows the
  pair moving together through REQ-021, REQ-027, REQ-093 and REQ-095, and apart at REQ-048
  (`8eecd5c`) and REQ-051 (`befc1a5`).
- **Consumer state left as found (decision 4):** flowsteward, docsteward, DriveSteward and
  clauder each keep an inert stale `docs/requirements/schema/req.schema.json`. memzy, THermo,
  examengineer and sarah have none. Neither group's `lint` is affected.
- **Out of scope:** any change to the packaged schema's content. This REQ deletes a
  duplicate; it does not revisit what the schema says. The `develop:` property stays declared
  and retired exactly as REQ-095 left it.
- **Out of scope:** a general "no un-linked twin" guard over the package. Rejected at intake
  (decision 2): after this deletion every twinned artifact is inode-shared or symlinked, so
  such a guard would police an empty set; the invariant is carried by doctrine instead.
- **Localization:** schema and doctrine text is technical English; no user-facing strings.
- **Surfaces (expected):** delete `devsteward/templates/docs/requirements/schema/`; edit
  `/CLAUDE.md` (House conventions); update
  `tests/test_req095_develop_key_retired.py`; add `tests/test_req096_single_schema.py`.
