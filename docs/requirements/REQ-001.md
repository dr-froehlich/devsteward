## Context

Peter starts each new project by copying the most recent one as a reference, so the
method drifts and good ideas don't propagate (e.g. two near-duplicate `run_batch*.py`
copies that have already diverged). He wants a single controlled baseline that captures
his proven, evolved house style and makes it reproducible — covering the dev process,
tech-agnostic scaffolding, and a bootstrap that brings a new project to life.

This is the frozen north star. Every other DevSteward REQ either advances it or is out
of scope. Change direction by superseding it, never by weakening it.

## Decisions

| # | Decision | Rationale |
|---|----------|-----------|
| 1 | One public, pipx-installable package bundling engine **and** scaffolding | Mirrors the proven `material-core` pattern; nothing to keep in sync across repos |
| 2 | Generic executor core + swappable REQ-workflow profile | Run any Claude automation; ship one sharp opinion on top |
| 3 | The engine owns verification and fork-handling | Unattended automation must not be talked into a false "done" |

## Requirement

DevSteward delivers a reproducible house style — a machine-readable requirement format,
a dependency-ordered roadmap, and an attended/unattended automation engine — that takes
a new Claude Code project from a raw idea to landed, test-verified requirements.

```yaml acceptance
- id: AC1
  text: The package imports and exposes the `steward` CLI with the documented commands.
  test: "python -m pytest tests/test_cli_smoke.py"
  status: pending
- id: AC2
  text: DevSteward's own requirements lint green in the format it ships.
  test: "python -m pytest tests/test_dogfood_lint.py"
  status: pending
```
