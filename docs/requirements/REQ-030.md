## Context

The nine-hollow-REQs failure was code and tests sharing one set of hallucinated
assumptions — a coupled oracle cannot disconfirm. The one place a session boundary buys
correctness is here: a System Tester that **never sees the builder's diff**, consuming
only the lab's pass/fail signal, cannot re-couple the oracle. REQ-027 ships the routing
key (`check: artifact | manual`); this REQ builds the phase it routes to. The working
pattern already exists in the successful corpus: ExamEngineer's `verified_by` records
dated smoke runs against real systems — validation as a **recorded evidence event**, not
a regression-suite member. That dissolves the skip paradox structurally: the regression
suite stays the always-green offline floor; validation runs in the lab, where a skip is a
hard failure, and produces a dated record.

## Direction (provisional decisions)

| # | Decision | Rationale |
|---|----------|-----------|
| 1 | The System-Test phase **exists only** when the REQ declares at least one `artifact` or `manual` AC (REQ-027 Decision 4). REQs with only `regression` ACs are untouched. | No system tests ⇒ no system-test phase; the taxonomy is the router. |
| 2 | The phase runs as a **fresh session** (the System Tester skill) that never sees develop's diff; it consumes only the lab's pass/fail **signal** and the captured observable. | Context independence is the decoupling — spend the orientation tax here gladly. |
| 3 | Validation produces a **dated evidence record**: a ledger event, the captured artifact (hashable output, fetched mail, produced report), and a `verified_by` entry — the ExamEngineer smoke-run pattern, formalized. It must be able to **fail** (a lab skip is a hard failure). | Evidence, not suite membership. "Run once for this REQ" means *prove the behaviour happened, recorded* — not weaker tests. |
| 4 | `manual` ACs are a **decision stop** for the human (park-and-surface when unattended). | A human oracle is validation; the engine records the sign-off, it does not simulate it. |
| 5 | Re-run policy (adopted, plan 0011): `steward validate REQ-NNN` re-runs a REQ's validation on demand and **appends** a fresh evidence event; at the release gate (dev → main PR) a human decides which `artifact` REQs to re-run. **No auto-staleness detection.** | Evidence rots; declared judgment beats brittle detection for a single-developer project. |
| 6 | To settle at flesh-out: evidence-event schema (where the artifact lives, hashing); how lab availability is declared/located (the lab dependency recorded at intake, REQ-027 D6b); behavior when the named lab REQ isn't built yet (honest deferral surfaced, not silent green). | Mechanics that need the REQ-029 step model on the table. |

## Requirement (sketch)

Add the conditional System-Test (validation) phase to the step model: routed by
`check:`, executed by a fresh-context System Tester skill against the declared lab,
recording evidence (ledger event + captured artifact + `verified_by`), with `manual`
checks as decision stops and `steward validate REQ-NNN` as the on-demand re-run that
appends fresh evidence.
