## Context

The nine-hollow-REQs failure was code and tests sharing one set of hallucinated
assumptions — a coupled oracle cannot disconfirm. The one place a session boundary buys
correctness is here: a System Tester that **never sees the builder's diff**, consuming
only the lab's pass/fail signal, cannot re-couple the oracle. REQ-027 ships the routing
key (`check: artifact | manual`); this REQ builds the phase it routes to. The working
pattern already exists in the successful corpus: ExamEngineer's `verified_by` records
dated smoke runs against real systems — validation as a **recorded evidence event**, not
a regression-suite member. That dissolves the skip paradox structurally: the regression
suite stays the always-green offline floor; validation runs in the lab, where a skip is a
hard failure, and produces a dated record.

Fleshed out 2026-06-10 (intake interview, plan 0011 step 4): the stub's provisional
direction is confirmed and its row-6 open mechanics are settled in Decisions 6–10 below.

## Decisions

| # | Decision | Rationale |
|---|----------|-----------|
| 1 | The System-Test phase **exists only** when the REQ declares at least one `artifact` or `manual` AC (REQ-027 Decision 4). REQs with only `regression` ACs are untouched. | No system tests ⇒ no system-test phase; the taxonomy is the router. |
| 2 | The phase runs as a **fresh session** (the System Tester skill) that never sees develop's diff. Division of labor (interview): the session orients, brings the lab up, drives the validation procedure, and captures the artifacts — then the **engine** runs each `artifact` AC's named test command itself and consumes only that pass/fail signal. The session can never talk the gate green — symmetric with the develop gate (north star D3, REQ-028). Model/effort come from the per-step-kind config (REQ-029 D4), default opus/high. | Context independence is the decoupling — spend the orientation tax here gladly; engine-owned verification keeps it from being marker trust. |
| 3 | Validation produces a **dated evidence record** (interview): captured artifacts are committed under `.devsteward/evidence/REQ-NNN/<timestamp>/`; the `events.jsonl` event carries timestamp, REQ id, per-AC pass/fail, and each artifact's relative path + sha256; `verified_by` gets the dated summary line. It must be able to **fail**: a lab skip or a missing artifact is a hard red, never a pass. | Evidence, not suite membership — durable, greppable, survives lab teardown. "Run once for this REQ" means *prove the behaviour happened, recorded*. |
| 4 | `manual` ACs are a **decision stop**: unattended, the step parks (REQ-005 machinery) naming the pending human oracle; attended, `steward validate` presents the AC and records the sign-off — date, reviewer, what was reviewed (the REQ-027 D12 provenance convention) — as the evidence event. This **replaces** the interim hand-flip of REQ-027 D12; the provenance convention survives. | A human oracle is validation; the engine records the sign-off, it does not simulate it. |
| 5 | Re-run policy (adopted, plan 0011): `steward validate REQ-NNN` re-runs a REQ's validation on demand and **appends** a fresh evidence event; at the release gate (dev → main PR) a human decides which `artifact` REQs to re-run. **No auto-staleness detection.** | Evidence rots; declared judgment beats brittle detection for a single-developer project. |
| 6 | **Gate position (interview): validation gates the land.** Step order is develop → validate → mechanical land; the validate step runs on the feature branch, and REQ-029's land routine stays atomic (flip + index sync + commit + `--no-ff` merge) and fires only after validation is green. `done` keeps meaning *verified and validated*; nothing unvalidated reaches the integration branch. | The open-branch cost while a `manual` AC waits is no extra serialization — dependents are blocked on done-status anyway. Splitting the land would need a new intermediate ledger state for no gain. |
| 7 | **Lab availability (interview): `process.lab` is an eligibility dependency** for the validate step — the step is ineligible until every named lab REQ is `done`, exactly like `depends_on`, and `steward status` surfaces "validation waiting on REQ-NNN". No red event, no parked decision. | Honest deferral surfaced, not silent green — and not a question parked at a human that has no answer except "build the lab", which the registry already records. |
| 8 | **Red validation parks immediately (interview): no repair loop.** The red evidence event is recorded, the step parks with the failure brief. A red here means the develop was hollow or the lab is broken — both are human questions; re-entry is repair-by-hand, then `steward validate` again. | Each automated cycle would cost a repair + a full regression gate + a fresh Opus validate session, and the fix usually needs the human anyway. |
| 9 | **Single entry point (interview):** `steward validate REQ-NNN` is the one code path for the phase. On an in-flight REQ it executes the pending validate step (green → the land proceeds); on a `done` REQ it appends a fresh evidence event without touching status; `steward run` calls the same routine. Provenance records who drove. | One behavior, one code path; interactive driving gets the phase without waiting for REQ-018's checkpoint integration. |
| 10 | **The e2e proof is a `manual` AC (interview, REQ-029 D10 precedent):** one scratch REQ carrying a trivial-but-genuinely-decoupled `artifact` check (produced file golden-compared against a copy authored at the scratch REQ's intake, not by the builder) plus a `manual` stop, driven develop → validate → decision stop → land by the real engine; a human reviews `events.jsonl`, the evidence dir, and the merged commit, and signs off. | "The phase works end-to-end" going done without ever being observed doing one is the hollow-green shape. The miniature oracle is real (decoupled), not a faked lab; the first **real** lab evidence stays REQ-031's. |

## Requirement

Add the conditional System-Test (validation) phase to the REQ profile's step model:

- A REQ with at least one `artifact` or `manual` AC gets exactly one **`validate`** step
  between develop and the mechanical land; REQs with only `regression` ACs get none.
  The land fires only after validation is green (Decision 6).
- The step runs as a **fresh System Tester session** whose context contains no develop
  diff; the session preps the lab and captures artifacts, then the **engine** runs each
  `artifact` AC's named test command and consumes only its pass/fail signal (Decision 2).
- A green validation appends a dated **evidence event** — committed artifacts under
  `.devsteward/evidence/REQ-NNN/<timestamp>/`, per-AC results and sha256 hashes in
  `events.jsonl`, a `verified_by` summary (Decision 3). A lab skip or missing artifact
  is a hard red; a red validation parks with no repair loop (Decision 8).
- `manual` ACs are a decision stop: park when unattended, recorded sign-off when
  attended (Decision 4).
- The validate step is **ineligible** while any `process.lab` REQ is not done, surfaced
  in `steward status` (Decision 7).
- `steward validate REQ-NNN` is the single entry point: it executes the pending validate
  step in-flight and appends fresh evidence on done REQs without disturbing status
  (Decisions 5, 9).

## Notes

- **Out of scope (own REQs / elsewhere):** the first lab itself (REQ-031 — the IMAP
  fixture and the FlowSteward re-drive, which produces the first **real** evidence
  event); `steward checkpoint` (REQ-018 — it will call the same validate routine, so
  keep it a clean shared function); full concept-phase mechanics; the release-gate
  re-run half of Decision 5, which is a documented human step in the handbook's release
  section, not engine automation; auto-staleness detection (rejected, plan 0011).
- **AC8 / honest deferral:** the proof run needs no owned lab (a scratch project with a
  golden file authored at the scratch REQ's intake suffices), so `process.lab` stays
  empty here. The miniature oracle is decoupled for real — authored before the builder
  session, compared after — which is what distinguishes it from the inline-double
  antipattern.
- **Hand-flip retirement:** REQ-027 D12's interim hand-flip for `manual` checks is
  replaced by the attended decision stop (`steward validate`); the provenance convention
  (date, reviewer, scope in `verified_by`) survives unchanged.
- **Sign-off authorship (Decision 4, pinned from the REQ-018 close-out, 2026-06-10):**
  the human supplies only the **verdict** plus an optional one-line scope (e.g.
  "reviewed proof run against D1-5"); the **engine composes the full evidence detail**
  — date, commit shas, test counts, artifact paths/hashes — mechanically from the ledger
  and events. The REQ-018 sign-off showed why: the dense `verified_by` string was only
  writable by the session that had the whole close in context — a human cannot author it
  by hand, so a "manual flip" that demands it isn't manual. The checkbox is the human's;
  the bookkeeping is the engine's.
- **Process declarations:** defaults — fused develop, no concept phase, no lab — driven
  interactively per plan 0011.
- **Localization:** engine/skill/handbook text is technical English; no user-facing
  localized strings.
- **Surfaces (expected):** `devsteward/profiles/req/source.py` (validate step emission,
  lab eligibility), `devsteward/core/executor.py` (gate ordering, red-park, land
  deferral), a shared validate routine (e.g. `devsteward/profiles/req/validate.py`),
  `devsteward/cli.py` (`steward validate`), the System Tester skill (repo
  `.claude/skills/` + stamped `devsteward/templates/.claude/skills/`, kept identical),
  evidence-dir handling + ledger event kinds (`devsteward/core/ledger.py`), handbook
  02/03.
