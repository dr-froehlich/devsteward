## Context

REQ-027 defined the lab: a shared, versioned fixture/harness whose **provenance** —
reality-derived, owned, built by its own REQ — is what gives an `artifact` check
trustworthy decoupling. The canonical anti-pattern it replaces is FlowSteward REQ-003
AC1's "fixture IMAP server" that was the build agent's own in-memory double, authored in
the same step as the code it certified. This REQ builds the first real lab — IMAP,
because FlowSteward is the consumer whose postmortems drove the whole repositioning —
and then uses it: FlowSteward becomes the proving ground again, re-driving its
REQ-003a/006/007 surface through the new validate phase. The live-socket proof is the
perfect first evidence event.

## Direction (provisional decisions)

| # | Decision | Rationale |
|---|----------|-----------|
| 1 | A dedicated IMAP test server as an **owned, versioned fixture** (e.g. a containerized server plus a seed mail corpus), with **documented provenance**: the corpus is derived from real mail shapes, not authored to match the code under test. | Provenance is the difference between a lab and a mock. The fixture is an asset with its own lifecycle, version, and docs. |
| 2 | The lab exposes only what the System Tester consumes: a way to run the declared `artifact` checks and a pass/fail signal plus captured observables (the fetched mail, hashable). | The engine never inspects lab internals (REQ-027 Decision 3). |
| 3 | **Re-drive FlowSteward:** the REQ-003a/006/007 surface (connect, read credentials, fetch real messages over a live socket) is validated through the new phase, producing the first dated evidence events in a consumer ledger. | The repositioning is measured by consumer outcomes; this is the acceptance test of the whole plan-0011 arc, not just of the lab. |
| 4 | To settle at flesh-out: where the lab lives (a DevSteward-shipped lab template vs a FlowSteward-owned asset DevSteward documents the pattern for); server choice (Greenmail/Dovecot container vs recorded-session replay); how credentials/endpoints are injected in the lab environment where a skip is a hard failure. | Ownership and tooling decisions need FlowSteward's repo state on the table. |

## Requirement (sketch)

Build the IMAP lab as an owned, versioned fixture with documented reality-derived
provenance, integrate it as the lab dependency the System-Test phase locates, and
re-drive FlowSteward's REQ-003a/006/007 surface through the validate phase so that live
evidence events (captured artifacts + `verified_by`) exist for behaviour that previously
landed green without ever being run.
