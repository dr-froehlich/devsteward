## Context

Nine REQs were built green and were, in reality, hollow: code and tests shared one set of
hallucinated assumptions, so the tests confirmed the code's behaviour against itself rather
than against reality. The canonical specimen is FlowSteward REQ-003 AC1 — *"reads credentials
from config/.env and connects to a fixture IMAP server"* — marked `passing` while: (a) no
`.env` loading, entry point, or template exists; and (b) the "fixture IMAP server" is the
build agent's own in-memory double, authored in the same step as the code. In V-model terms
**verification of a narrow sub-claim passed; validation against the user requirement was never
attempted** — a module-level double was used to discharge a system-level acceptance criterion,
and nothing in the AC's wording or status revealed the mismatch.

The root cause is not "AI vs human." Every acceptance criterion in the *successful* legacy
corpus (ExamEngineer) was also Claude-authored, yet it stayed reliable. The difference is
**house style**: ExamEngineer's ACs are granular and bound to named, greppable artifacts
(`_extract_yaml_files()` extracts `.yaml` files; null answers are silently skipped), and its
strongest tests produce **observable artifacts with a decoupled oracle** (output that can be
hashed/compared, signed off once). DevSteward's hastily-seeded house style produced abstract,
artifact-less ACs whose only oracle was a self-authored mock. **A coupled oracle cannot
disconfirm.**

The leverage point is the **seed**: the `/intake` interview is the one moment a human shapes
the REQ before the headless Autobahn. If intake institutionalises system-level, artifact-bound
acceptance criteria and a machine-readable test classification, the downstream engine inherits
a house style that can fail honestly. This REQ fixes the seed and makes the classification
first-class and lintable. It deliberately does **not** yet build the independent System Tester
phase or any lab harness — those are the follow-on REQs this one enables.

## Decisions

| # | Decision | Rationale |
|---|----------|-----------|
| 1 | Each acceptance criterion carries a required `check:` field, enum `regression \| artifact \| manual`. | One field, three values that match the test *kinds actually observed in a working corpus* (ExamEngineer) — encodes scope+oracle+headless-capability without a classification matrix nobody will maintain. |
| 2 | The three values are defined by their **oracle**: `regression` = module scope, coupled/mock oracle, headless; `artifact` = system scope, **decoupled** oracle (a captured/golden/hashable observable result), headless; `manual` = system scope, human oracle, **not** headless. | The oracle's coupling — not the test's name — determines whether a test can disconfirm. A self-authored mock is `regression` even if its AC text says "system". |
| 3 | An `artifact` check must compare an **observable, captured result** (a produced file/report/captured message, hashed or golden-compared), not merely assert against an inline double. | This is the decoupling that made ExamEngineer's "build" tests powerful; "connect and find mails" becomes "fetch *this* captured mail and compare". |
| 4 | A REQ tagged externally-facing (touches a real channel, the filesystem, money, or destructive ops) must carry **≥1 `artifact` check** OR an explicit, logged **deferred-validation waiver** naming the follow-on REQ that will close it. | The REQ-003 failure mode becomes structurally impossible: a system claim cannot be discharged by mocks alone, and an honest deferral is tracked debt rather than a silent hallucination. |
| 5 | `steward lint` rejects an AC with no `check:`, and an AC whose text names no concrete/greppable artifact (granularity gate); it warns when an externally-facing REQ declares only `regression` checks. | Artifact-bound granularity is itself an anti-hallucination control — it would have caught the `.env` gap mechanically, cheaply, before any test ran. |
| 6 | The engine **never auto-passes a `manual` check** under headless: it surfaces it as a decision/waiver, never "marker trust". | Retires the trust hole (`no acceptance tests declared (marker trust)`); a human-oracle check that cannot run headless must be visibly parked, not silently blessed. |
| 7 | `/intake` is updated to seed all of the above: interrogate acceptance toward **end-to-end, system-level chains with measurable deliverables**, tag each AC's `check:`, enforce the ≥1-artifact-or-waiver rule, and decide two things while the human is present — (a) whether an **optional concept phase** is warranted (risk buy-down / spike, where final test specs and lab needs are pinned), and (b) any **lab dependency** the System Tester will need. | Intake is the only human-in-the-loop seed; fixing house style here propagates to every headless step. The concept phase and lab are declared where the human is, not improvised headless later. |
| 8 | The **lab** (shared, versioned test fixtures / harness for `artifact`/`manual` checks) is declared as an **owned asset built by its own REQ**, not an inline double — fixture *provenance* defines a test's level. This REQ declares the model; building the System Tester phase+skill and the first lab (IMAP) are named follow-on REQs. | Independence (separate test department + lab) maps to context independence + reality-derived fixtures; making the lab a first-class, owned, depended-on artifact is what gives `artifact` checks a trustworthy provenance. |

## Requirement

The REQ frontmatter/acceptance schema and `steward lint` gain a per-criterion `check:` field
(`regression | artifact | manual`) and enforce: every AC declares one; externally-facing REQs
carry ≥1 `artifact` check or a recorded deferred-validation waiver; an AC must name a concrete
artifact (granularity gate); a `manual` check is never auto-passed headless but surfaced.

`/intake` is rewritten to seed this house style: its interrogation drives acceptance toward
measurable, system-level, end-to-end deliverables; it tags each criterion's `check:`; it
applies the ≥1-artifact-or-waiver rule; and it records, in the REQ, whether an optional
**concept phase** is taken and which **lab** assets the System Tester will require. The
handbook documents the taxonomy, the oracle definition, the waiver, and shows one fully
tagged example acceptance block.

## Notes

- **Out of scope (own REQs this one enables):** the independent **System Tester phase + skill**
  (runs `artifact`/`manual` checks in a context that never sees Build's diff); the first **lab
  harness** (a real/recorded IMAP server + seed corpus for the FlowSteward channel) as an owned,
  versioned asset; full engine support for the optional **concept phase** beyond its intake-time
  declaration.
- **Concept phase:** optional, decided at intake (human present) and recorded in the REQ; it is
  the risk-buy-down/spike where final test specs and lab needs are frozen before the headless
  Autobahn. This REQ only adds its intake-time *declaration*, not engine phase mechanics.
- **Oracle (glossary):** the part of a test that decides correct vs incorrect — distinct from the
  fixture (inputs/environment) and the system under test. `regression` oracles are coupled to the
  code (mock assertions); `artifact` oracles are decoupled and durable (golden/hashed observable
  output); `manual` oracles are human judgment.
- **Localization:** all schema/lint/skill text is technical English; no user-facing localized
  strings introduced.
- **Surfaces touched:** `schema/req.schema.json` (or the acceptance linter — the `yaml acceptance`
  block is linter-validated, not schema-validated), the lint module, `core/executor.py` (manual-
  check surfacing, retiring marker-trust for declared acceptance), the `/intake` SKILL.md, and
  the handbook.
