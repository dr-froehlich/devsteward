## Context

`STEWARD.md` is the black-box manual a consumer agent drives the engine from — `CLAUDE.md.tmpl`
names it "**the authoritative `steward` reference** — the full command…" and REQ-057 built it as
"the Claude-targeted manual". It is an engine-owned stamped artifact: `steward sync` tracks it
(`skillsync.MANUAL_FILENAME`), consumers hold byte-identical copies, and the consumer is *not*
supposed to edit it — a consumer edit buckets as `customized` and `sync` then **refuses** to
refresh it, stranding that project on a forked manual. So the manual can only ever be kept
current here, in the engine repo, by the REQ that changes the engine.

That did not happen. REQ-093 shipped a whole layer above the REQ — six `backlog-*` verbs, a
`backlog_refs:` frontmatter field, a take-up ordering rule — and updated `cli.py`, `config.py`,
`lint.py`, the schema, the stamped `/intake` skill and two handbook chapters, but **not the
manual**. A consumer agent reading the authoritative reference finds zero occurrences of
"backlog". The end-to-end cycle is broken at the one surface that documents it.

Investigation found the drift is not one REQ, and not where it was first suspected:

* **The manual is missing ten consumer-facing verbs, from three REQs.** The six `backlog-*`
  (REQ-093), `gate` and `reland` (REQ-089, undocumented since 2026-08-06 — the same REQ *did*
  update the manual for its `validate-start`/`decision-list` renames, then shipped two new verbs
  without them), and `sync`/`sync-skills` (REQ-036/066, never documented at all). It also never
  mentions `backlog_refs:`, though it documents `concept_refs:`.
* **`steward sync` is not defective.** `STEWARD.md` is tracked, is in FlowSteward's
  `stamped.lock`, and FlowSteward's copy is byte-identical to the template; `steward status`
  there reports no drift. Sync did its job — the template it syncs *from* is what is stale. The
  stamped `/intake` skill reached FlowSteward correctly and does know about the backlog.
* **A missing `docs/BACKLOG.md` in an existing consumer is not a defect either.** A backlog is
  project content, not engine behaviour — tracking it would let `sync` clobber real user needs —
  and `steward backlog-add` creates the file on demand. Absence is the designed empty state, as
  `/intake` §1 already says. No sync machinery is warranted here, and adding some would be the
  "string of fixes that each *add* structure" smell CLAUDE.md warns against.

**The root cause is a guard that cannot fail the right way.**
`tests/test_steward_manual.py::test_docs_and_skills_use_current_verbs` is the only standing check
on the manual's command coverage, and it is a **hand-enumerated two-verb allowlist** (`repeat`,
`revalidate`) plus a one-verb denylist (`steward recover`). It structurally cannot detect a verb
that never arrived, so it stayed green through REQ-089 and REQ-093. Every other doc guard in the
repo is per-REQ and hand-picks its own surfaces — REQ-093's `test_req093_doctrine_surfaces.py`
picked the intake skill and two handbook chapters; STEWARD.md is optional by construction, every
time.

The cure this codebase already invented for this exact disease is one layer down, in
`skillsync.py`: *"The tracked set is **engine-derived** (REQ-066): read off whatever the installed
template actually ships … never a hand-maintained list that can fall out of step."* The click
command registry is that same free, authoritative source for verbs.

## Decisions

| # | Decision | Rationale |
|---|----------|-----------|
| 1 | Repair the **whole** manual, not just the backlog gap | The derived guard goes red on all ten verbs the moment it exists. A backlog-only fix means someone repairs the other four later, under a red gate, with less context than this session has. |
| 2 | Coverage is **derived from the click registry**, never a hand list | The failure mode is a *missing* verb, which only a derived allowlist can see. Same principle, same words, as REQ-066's engine-derived tracked set. |
| 3 | **Every** shipped verb is documented — no exclusion set | Rejected an `OPERATOR_ONLY`-style exclusion list: it is a list someone can quietly grow to silence a red, and it would delete the very information an agent needs. `cache`'s docstring says running it from a second shell "never touches the session or its cache, **which asking inside the session would**" — that is a *warning* for the agent, not an omission. Each verb instead carries a one-line "run by / when" annotation. |
| 4 | The manual gains a **command-reference table** | Verbs are currently woven into prose, which is not mechanically checkable. A table is the structure that makes both coverage and the per-verb annotation testable, and it is what an agent looking up a verb actually wants. |
| 5 | The reverse check (a documented verb that no longer exists) runs **over the table only** | The manual deliberately carries negative prose — "There is no `steward degrade`" (REQ-068) — which a whole-file reverse scan would flag. The table is the authoritative list; prose stays free. REQ-057's `steward recover` prose denylist is retained unchanged: a bounded denylist for one retired verb is a different thing from a hand-maintained allowlist of current ones. |
| 6 | The standing obligation goes in **DevSteward's own `CLAUDE.md`**, never in `/advance` | `/advance` is inode-shared with its shipped template — an edit there ships to every consumer. Worse, it would instruct consumers to edit `STEWARD.md`, which buckets their copy `customized` and makes `sync` refuse it forever. This obligation is DevSteward's alone; a dogfooding project must not use its reach to push its own needs into the shipped tool set. `CLAUDE.md`'s "House conventions" section already holds the sibling rule (same-commit discipline). |
| 7 | No `backlog_refs` schema-coverage guard | The schema and `_templates/req.md` are already the field reference. Mirroring them in prose creates a duplicate that drifts on its own axis and forces a manual edit for every internal field an agent never authors. `backlog_refs` is documented by hand as part of the acute repair. |
| 8 | The consumer sweep is **out of scope** | REQ-094 stops at the engine boundary. Syncing consumer repos is an operator act that writes commits into repos with their own in-flight cycles; coupling this REQ's green to another repo's working tree is a coupling that has bitten before. The operator runs `steward sync` where and when they choose. |
| 9 | Manual **sufficiency** is an attended develop obligation, not a `manual` AC | A derived guard proves every verb is *mentioned*, not that the manual is *usable* — REQ-057 recorded the same limit. But routing that judgment to the System-Test phase gives it no repair loop: the System Tester never sees the diff and cannot fix anything, so a wording quibble costs a whole rework cycle. The operator reads the repaired manual during the develop session and it is fixed in place. |
| 10 | `develop: fused`, `concept: false` | The acceptance criteria are honestly writable at intake — this is a bounded repair plus one derived guard, with no risk to buy down. |

## Requirement

### The acute repair

`devsteward/templates/STEWARD.md` gains a **command reference** covering every command the
`steward` CLI registers, each row carrying the verb, what it does, and a **"run by / when"**
annotation. The ten currently-undocumented verbs — `backlog-add`, `backlog-list`,
`backlog-accept`, `backlog-deny`, `backlog-hold`, `backlog-retire`, `gate`, `reland`, `sync`,
`sync-skills` — are among them, and the four verbs an in-project agent does not run in the normal
cycle say so explicitly:

* `new`, `init` — run by the operator, outside/at the start of a project.
* `seed-ledger` — run by the `/onboard` skill, which is `OPERATOR_ONLY` and never stamped into a
  consumer.
* `cache` — run from a **second shell**; an agent must not run it in-session, because measuring
  the session's cache warmth from inside the session warms what it measures.

The manual also documents `backlog_refs:` as the single stored record of backlog take-up, and the
backlog verbs' place in the cycle (capture in the user's words, take up at intake, an acceptance
verdict that is advisory to the REQ and blocking to the item).

### The root-cause fix

The hand-enumerated verb allowlist in `test_docs_and_skills_use_current_verbs` is **removed** and
replaced by a check derived from `devsteward.cli.main.commands`: every registered command must
appear in the manual's command-reference table, and every verb the table names must be a
registered command. Adding a verb to the CLI without documenting it must turn the develop gate
red, with no list for anyone to edit.

DevSteward's own `CLAUDE.md` gains a House convention, sibling to same-commit discipline: a REQ
that changes anything a consumer agent observes — a verb, a flag, a behaviour, a frontmatter
field — updates `devsteward/templates/STEWARD.md` in the **same commit**. This covers the residual
class the derived guard cannot see (REQ-089's "rework carries green ACs forward", REQ-075's
`DEVSTEWARD_EVIDENCE_DIR` injection: consumer-visible changes that add no verb). It is prose in a
non-shipped file, deliberately: nothing about this obligation reaches a consumer project.

During the develop session the operator reads the repaired manual end-to-end and it is corrected
in place — the sufficiency judgment a shape test cannot make (Decision 9). This is a session
obligation, not an acceptance criterion.

## Notes

**Out of scope, deliberately.**

* *The consumer sweep* (Decision 8). FlowSteward and the other consumers keep the stale manual
  until the operator runs `steward sync` in each. The engine-side fix is what makes that sync
  worth running.
* *Any `docs/BACKLOG.md` sync machinery.* Investigated and rejected — a backlog is project
  content, `sync` would clobber it, and `backlog-add` creates the file on demand (verified live:
  `Created docs/BACKLOG.md`).
* *A schema-coverage guard for frontmatter fields* (Decision 7).
* *Documenting CLI flags/options.* Coverage is at verb granularity; `--help` is the authoritative
  flag reference and cannot drift.

**No known defect is deferred without a home.** The three surviving loose ends are recorded
above as scope decisions, not as unfiled defects: the consumer sweep is an operator act, the
BACKLOG.md seed is designed behaviour, and manual *sufficiency* is a develop-session obligation
(Decision 9).

**Implementation hazard.** The reverse check must read the table, not the whole file: the manual
deliberately says "There is no `steward degrade`", and a whole-file scan for ``steward <token>``
would flag it (Decision 5).

**Why this REQ carries no `backlog_refs`.** DevSteward keeps no backlog of its own
(`steward backlog-list` → "this project keeps none") — a valid state per `/intake` §1. This REQ
originates from an operator-reported engine defect, not from a captured user need.
