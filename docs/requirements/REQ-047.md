## Context

DevSteward has entered a firefighting loop: roughly one crash-recovery session plus one
"engine improvement" REQ per *productive* step in the consumer project (FlowSteward). That
ratio is not survivable and is not professional. This REQ stops patching symptoms and fixes
the structure.

**The pattern.** Every recent engine REQ traces to one root — engine state lives in two
branch-locations (the ledger on `dev` via a worktree, the code on a feature branch) and the
engine performs destructive `git checkout` to move between them:

| REQ | What it patched | Topology-induced? |
|-----|-----------------|-------------------|
| 037 | ledger-on-dev, "atomic" topology ops | the two-location model itself |
| 040 / 041 | read commands must resolve the *live* dev ledger, not HEAD's stale `.devsteward/` | yes — ledger ≠ HEAD's tree |
| 043 | close-out switch must not crash on a dirty **ledger** tree | yes — a switch happens at all |
| 044 | supersede a branch without a false merge-by-hand recovery | yes — branches exist |
| 046-F1 | switch must not crash on a dirty **non-ledger** tree (today's crash: `config/profiles.yaml` modified on `req-032-action-ribbon`) | yes — a switch happens at all |
| decision-stranded | recovery blocked because a parked decision sat on the wrong branch; no command could recover | yes — branches exist |

REQ-037 promised "atomic / transaction-safe git operations," but the approach was
**defensive enumeration**: check the one dirty condition we thought of, then switch. REQ-043
checked `.devsteward/`; today's crash is the *same bug* for a file one directory over. The
next file will crash the same way. That is whack-a-mole by construction.

**Two distinct failures, two distinct fixes.**

1. *Divergence* — two locations that must be kept in sync across a switch. You cannot
   enumerate every precondition; you *can* delete the second location. Collapse to **one
   branch (`dev`), one co-located ledger, no switching** and the entire table above stops
   *existing* rather than being *guarded against*. This is the only way to get the guarantee
   "state inherently cannot diverge" — a single source of truth has nothing to diverge from.

2. *Stranding* — when an *un-enumerated* precondition is violated, a raw
   `CalledProcessError` escapes (`git.py:24`/`switch` `:46`) and leaves a half-state with no
   recovery path (the `steward decision` stalemate). The fix is a **universal transaction
   boundary**: any mutation is fully applied or fully rolled back, and an unanticipated edge
   becomes a *clean abort + one-line recovery*, never a stalemate.

**Why drop feature branches.** The engine runs one REQ at a time, sequentially — there is
almost no parallel work to isolate. The System-Test decoupling (REQ-030) is enforced by the
*fresh session not reading the diff*, not by the branch (the tester could always `git show`
the merged commit), so dev-only loses nothing there. Branches bought ~6 REQs of topology
firefighting and almost nothing this workflow uses. Trunk-based DevSteward is also *closer*
to the proven hand-tracked process (ExamEngineer: Requirements + Plans + Implementations on
one history) — it narrows the gap to that fallback instead of betting against it.

## Decisions

| # | Decision | Rationale |
|---|----------|-----------|
| 1 | **Trunk-based: all work on `dev`.** No implementation feature branches, no ledger worktree, no engine-initiated `git checkout`/`switch`. Implementation commits land directly on `dev` under same-commit discipline. | Eliminates the divergence bug-class by construction (037/040/041/043/044/046-F1/decision-stranded). One location cannot diverge from itself. |
| 2 | **`dev → main` release merge stays** — the one real, human-gated, infrequent merge — wrapped in the same transaction boundary (Decision 3). | Release isolation is genuine and rare; it is not the per-REQ topology that caused the pain. |
| 3 | **Universal transaction boundary** on every mutating command: resolve canonical state → assert invariants (typed `PreconditionError(recovery=…)` *before* any mutation) → execute → on any escaping exception, restore the captured pre-command snapshot (`ORIG_HEAD`/saved ref) and re-raise as a `RecoverableError` with recovery text. No raw `CalledProcessError` ever reaches the user. | Converts un-enumerated edges from *stalemate* to *clean abort*. This is the resilience guarantee guards alone can't give. |
| 4 | **Invariants defined once, centrally, run by every command** — not per-call-site guards. INV-1 single source of truth (one ledger, every command incl. *writes*; the decision-stranded bug is INV-1 unenforced on writes). INV-2 no mutation rides an unexpected dirty/conflicting tree. INV-3 atomic: fully applied or fully rolled back. | Replaces enumeration with enforcement; new commands inherit the guarantees for free. |
| 5 | **Commit integrity** (absorbs REQ-046-F2): the land/commit step refuses to certify a develop green whose passing state the recorded commit does not capture (`.gitignore`d / excluded / post-verify working-tree state). | A recorded commit must reproduce its own green; survives dev-only, so it stays as a Layer-2 concern. |
| 6 | **Lab fixtures committed upstream; the System Tester never improvises** (absorbs REQ-045): a missing fixture is a hard-red-and-stop, never create-and-don't-commit. An uncommitted improvised fixture is precisely the divergence this REQ forbids. | Removes the trigger that produced today's dirty tree; keeps validation reproducible. |
| 7 | **Supersede the topology stack** (037/040/041/043/044): this design obsoletes their machinery rather than layering a 7th patch on it. | Net *less* engine code; deletes the worktree/switch/branch-recovery surface entirely. |

## Requirement

To be hardened and very likely **split** by `/intake` (this is a large design; candidate
sub-REQs noted below). The `TBD` tests are placeholders.

- The engine never creates an implementation feature branch and never performs a branch
  switch as part of develop/land/validate/park; implementation commits land on `dev`.
- The ledger and code are always co-located on `dev`; no worktree is spun up; every command
  (read and write) resolves and mutates the single live ledger regardless of incidental
  repo state.
- Every mutating `steward` command is atomic: on any failure the repo + ledger are left in
  the pre-command state with a legible recovery message; no command can leave an
  unrecoverable half-state, and no other command is blocked by a parked record's location.
- `steward decision` (and all recovery commands) operate correctly irrespective of HEAD —
  there is no "wrong branch" for a decision to strand on.
- Land refuses to certify a green not captured by the commit it records.
- A missing lab fixture stops validation as a hard red; the tester never writes an
  uncommitted fixture.
- `dev → main` release merge remains, guarded by the transaction boundary.
