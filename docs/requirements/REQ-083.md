## Context

The owner's ruling (2026-07-17, from the FlowSteward session that exposed it): a
roadmap's purpose is to lay out **future** REQs — written or intended — so a product
evolves strategically toward a target. The stamped `ROADMAP.md` served that function for
one instant at bootstrap, then drifted into something nobody asked for: an append-only
*intake chronicle*, filled per-REQ by the intake skill, read by nothing.

The evidence from FlowSteward, the heaviest consumer: the engine never consumes
`roadmap_path` (the config property has zero readers in the package — `steward lint`
checks index ↔ frontmatter, the land touches frontmatter + index, no verb ever opens the
roadmap); nothing guards the file, so an entry silently went missing at a REQ's intake
(FlowSteward REQ-118) and no tool noticed; and at 119 REQs the file had grown to ~900
lines / ~75k tokens — un-readable in one pass even by the agent maintaining it. Every
per-intake fact in it is duplicated from REQ frontmatter (deps) and REQ prose (rulings);
the historic narrative has no operational value to the owner.

The roadmap's *actual* function is served better by an existing pattern: when a mission
is bigger than one REQ, a **concept bundle** (`docs/concepts/REQ-NNN/`) carries an
alternatives paper plus a **frozen slicing plan** that names the downstream REQs — a
document written once, read and updated only while the fanout it structures is in active
use, then naturally dormant (the FlowSteward folder-lifecycle and Signal-channel
precedents). No standing whole-project file is needed on top of that.

This is the "minimal topology / prefer subtraction" design principle applied to our own
scaffolding: the artifact is deleted, not documented-as-deprecated. FlowSteward has
already executed its consumer-side subtraction by hand (its ROADMAP.md, skill steps,
config key, README pointer — 2026-07-17); this REQ retires the artifact at the source so
no future consumer receives one.

## Decisions

| # | Decision | Rationale |
|---|----------|-----------|
| 1 | **Delete, don't deprecate.** The template, the config seam, the skill steps, and the doctrine sentences are removed entirely — no "deprecated" markers, no explanatory residue in the places the roadmap used to be named. | Owner's explicit instruction ("subtracting, not adding wording why it's not needed anymore") and the no-compat-shims house rule. Git history is the archive. |
| 2 | **Legacy consumer configs stay loadable by construction.** `from_dict` reads known keys via `data.get(...)`; once the `roadmap_file` field is gone, a consumer config still carrying the key parses fine and the key is simply never read. No warning, no migration verb. | Lenient parsing already gives the tolerance; adding machinery to complain about a dead key would violate decision 1. Consumers subtract the key when they next touch the file (FlowSteward already has). |
| 3 | **Foreign-project roadmaps remain foreign data.** The onboard skill / `convert_reqs.py` operate on projects that may legitimately contain a ROADMAP.md of their own; conversion continues to leave such files untouched as the target's living docs. Fixture data mentioning ROADMAP in converter tests stays — it is input corpus, not doctrine. | Onboard's "merge, never overwrite" boundary is about the target's property; retiring *our* artifact doesn't license deleting *theirs*. |
| 4 | **DevSteward's own `docs/requirements/ROADMAP.md` (616 lines) is deleted in the develop step.** | Same doctrine applied to ourselves; the engine repo is also a consumer of its own scaffolding. |

## Requirement

1. **Templates:** `devsteward/templates/docs/requirements/ROADMAP.md` is deleted; the
   stamped skill templates (`intake`, `bootstrap`, `onboard` under
   `devsteward/templates/.claude/skills/`) carry no roadmap step or mention — intake's
   emit is REQ + index row in one commit; onboard's "richer artifacts" and out-of-scope
   wording name living docs generically, not ROADMAP. A `steward new` project therefore
   never receives a roadmap.

2. **Config seam:** `Config` has no `roadmap_file` field and no `roadmap_path` property;
   loading a consumer config that still contains a `roadmap_file:` key succeeds with the
   key ignored (decision 2).

3. **Package hygiene:** no source file under `devsteward/` (code, templates, profile
   docstrings) references the roadmap; a meta-test pins this so it cannot creep back via
   a template edit.

4. **Doctrine text:** DevSteward's own `CLAUDE.md` and `README.md` no longer describe a
   roadmap (the status-one-source bullet keeps its index ↔ frontmatter content; the
   intake/branching descriptions name frontmatter + index only) — pure subtraction, no
   replacement prose about the retirement.

5. **Own tree:** `docs/requirements/ROADMAP.md` is deleted (decision 4); existing tests
   that asserted roadmap wording (`tests/test_onboard_skill.py`) are updated to the new
   skill text; converter fixtures keep their foreign ROADMAP strings (decision 3).

## Notes

- **Scoping against REQ-001 (frozen):** the north star promises "a dependency-ordered
  roadmap". That promise is delivered by the `depends_on` graph in REQ frontmatter — the
  machine-readable DAG the engine derives step eligibility from — which this REQ does not
  touch. `ROADMAP.md` was one (unread, drifting) *view* of that graph, not the graph.
  REQ-001's text stands unedited; this REQ is not license to reword it.
- **Consumer rollout is self-serve:** FlowSteward is already subtracted (2026-07-17);
  other consumers lose nothing if they keep a stale ROADMAP.md — nothing reads it — and
  subtract whenever they next touch the scaffolding. `steward sync`'s customized-refusal
  already handles the skill-template delta on its normal path.
- **Out of scope (genuine non-goal):** any replacement "future work" artifact. The
  concept-bundle slicing plan is the sanctioned pattern and already documented by the
  concept-phase doctrine in STEWARD.md / the intake skill; it needs no new file type.
- The full-suite land gate covers the updated `test_onboard_skill.py` assertions; no
  separate AC needed for test edits.
