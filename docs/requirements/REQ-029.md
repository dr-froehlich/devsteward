## Context

The three-session-per-REQ split (design / build / land as separate `claude -p` sessions)
tripled the fixed cost of every requirement while two of the three gates verified nothing.
The FlowSteward run: 29 headless Opus sessions for 8 small REQs, orientation-dominated
(0.5–7 min each), with roughly two thirds being design/build checkpoints the engine
accepted on marker trust. None of the postmortem failures were prevented by the session
boundaries; all are closed by gate semantics (REQ-028) and intake quality (REQ-027). Cost
≈ sessions × (orientation tax + work), and no cache survives across cold `claude -p`
sessions — so the fix is **fewer, larger, verified sessions**, not less tooling.

## Direction (provisional decisions)

| # | Decision | Rationale |
|---|----------|-----------|
| 1 | The REQ profile's step source emits **one `develop` step** per REQ (replacing design + build). The plan artifact in `docs/plans/` remains **required** — plan-first discipline survives inside the session; only the session boundary is dropped. | The design→build handoff forced build to re-ingest through the plan file what design already held in context. The plan survives as an artifact, the boundary doesn't. |
| 2 | On a green develop gate, **land is engine code** — status flip, index `DONE`-sync, one commit, `--no-ff` merge (REQ-020 machinery). **Zero Claude tokens.** | Keeping a Claude session at land pays Opus to watch pytest run. REQ-028 made the verifier the authority; the flip/commit/merge are deterministic. |
| 3 | On a red gate, the executor spawns a **bounded repair session** — budget **2** attempts (adopted, plan 0011), then the step parks for a human. The repair session inherits land's real historical function (both FlowSteward "failed lands" were environment problems a repair loop would have surfaced immediately). | Full-cost cold retries on every red were a major cost driver; a bounded repair loop with an explicit park is cheaper and honest. |
| 4 | **Per-step-kind model/effort config:** develop/validate default Opus-high; repair defaults to **Sonnet** (adopted, plan 0011); CLI/config overridable. | Uniform Opus-high for mechanical work was the third cost driver. |
| 5 | A REQ whose intake declared **split** (REQ-027 Decision 6c) runs an attended design review step before develop; fused is the default. | Default fused, exception declared while a human is present. |
| 6 | To settle at flesh-out: how the verifier asserts the plan artifact exists (gate addition vs lint); ledger migration for in-flight REQs holding design/build steps; whether `--resume <session-id>` is used for the repair session to keep develop's cache/context. | Open mechanics; decide with the code on the table. |

## Requirement (sketch)

Rework `profiles/req/source.py` and the executor loop: one `develop` step per REQ
(attended design review prepended only when intake declared split); on green, the engine
performs the mechanical land without invoking Claude; on red, up to two engine-spawned
repair sessions (configured model/effort, default Sonnet) before parking; model/effort
configurable per step kind. Do this **before** REQ-030 so the System-Test phase plugs
into the final step model.
