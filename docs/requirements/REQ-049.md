## Context

Stage B of REQ-047 (plan `docs/plans/0026-single-source-of-truth-trunk-based.md`),
layered on the trunk-based foundation REQ-048 established. Implemented **by hand**, not
under `steward` — the engine has not yet earned the right to drive its own repair.

REQ-048 deleted the *divergence* bug-class by subtraction (one branch, one co-located
ledger). This REQ closes the second failure mode — *stranding*: an un-enumerated precondition
let a raw `CalledProcessError` escape a mutating command and leave a half-state with no
recovery verb (the historical `steward decision` stalemate). The fix is a **universal
transaction boundary**: every mutation is fully applied or fully rolled back, so an
unanticipated edge becomes a *clean abort + one-line recovery*, never a stalemate.

The guarantee is *fail-safe*, not *bug-free*: it changes the failure mode from "stalemate +
new REQ" to "clean abort + recover + continue" — the exit from the firefighting loop.

## Decisions

| # | Decision | Rationale |
|---|----------|-----------|
| 1 | **Two typed errors** (`core/errors.py`), each carrying `.recovery`: `PreconditionError` (a mutation refused to start; nothing touched) and `RecoverableError` (a mutation failed and was rolled back). **No raw `CalledProcessError` ever reaches the user** — the swallow-and-return-`None` handlers in `_commit`/`_commit_ledger_close` are removed so failures propagate to the boundary. | A legible recovery line on every failure; one escaping raw error is itself a bug (a mutation that dodged the boundary), surfaced loudly by the CLI. |
| 2 | **The boundary** (`core/transaction.py`): `transaction(git, *, label)` snapshots `HEAD` → runs → on any escaping exception restores the snapshot (`git reset --hard <orig>`, byte-identical for tracked state) and re-raises as a `RecoverableError`. Owns **INV-3 (atomic)**. `reset_hard` rejoins the trunk-based git seam — the one method the boundary needs. | Converts an un-enumerated edge from a half-state into a clean abort. The git seam grows by exactly one read-restore method, justified by a present need. |
| 3 | **Central invariants** (`core/invariants.py`): `check_invariants(ex)` runs *before* any mutation. **INV-1** single source of truth (the one root `.devsteward/`; no stray linked worktree) — enforced on writes *and* reads (the decision-stranding bug was INV-1 unenforced on a write). **INV-2** no mutation on the production branch (folds in the old `branch_guard`) or mid-merge/mid-rebase. | Replaces per-call-site enumeration with enforcement defined once; new commands inherit the guarantees for free. |
| 4 | **Recovery/decision verbs are exempt from the branch/tree gate** (`allow_any_head=True` → INV-1 only): `steward decision`, `recover`, `rework`, `activate` succeed *regardless of HEAD*. A `reset --hard` is **not** applied to a graceful refusal (`LifecycleError` passes through), since those verbs deliberately leave uncommitted work the rollback would destroy. | Realises REQ-047 AC3: there is no "wrong branch" for a parked decision to strand on. The historical stalemate is unreachable by construction. |
| 5 | **One top-level CLI handler** catches `PreconditionError`/`RecoverableError`, prints `.recovery`, exits non-zero. | A single, uniform failure surface; no traceback ever reaches the operator. |

## Requirement

- Every mutating command path (`advance_once`, `run`, `checkpoint`, validate's land/park,
  `rework`, `recover`, `activate`, `decision`) checks the central invariants, then runs its
  body inside the transaction boundary.
- On any failure mid-mutation the repo + ledger are left **byte-identical** to the
  pre-command state, and a `RecoverableError` (with a recovery line) is surfaced — never a
  raw `CalledProcessError`, never a half-state.
- `steward decision` and the recovery commands operate correctly **irrespective of HEAD**;
  no command is left unrecoverable by a parked decision's location.
- A `PreconditionError` (production branch, mid-merge/rebase, stray ledger) refuses the
  mutation *before* any write, with a legible recovery; nothing is half-applied.

## Notes

- Folds the old `branch_guard()` into INV-2: an on-`main` mutation now raises a typed
  `PreconditionError` (was a returned `RunOutcome.REFUSED`). The two REFUSED-on-production
  tests were updated; the graceful REFUSEDs (lab-waiting, CLAUDECODE nesting, already-done
  idempotency) are unchanged.
- Unit loop tests (`test_executor`, `test_classify_limit`, `test_claude_permissions`) now use
  the in-memory `FakeGitTopology` seam consistently (the conftest pattern), so removing the
  git-error swallow does not regress them. Real-git teeth live in
  `test_transaction_boundary.py` and `test_ledger_close.py`.
- REQ-050 (commit integrity) and REQ-051 (lab fixtures) are the remaining REQ-047 stages and
  build on this boundary.
