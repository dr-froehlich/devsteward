## Context

[[REQ-017]] shipped `scripts/convert_reqs_prose.py` on 2026-08-01 and deliberately stopped at the
tool: *"This REQ ships the tool + fixtures; the retrofit is a separate act."* This is that act —
the same split [[REQ-010]] → [[REQ-062]] drew for memzy (converter proven on fixtures; live run
tracked separately). It is not, however, only that act, and the reason is the whole point of this
REQ's Context.

**REQ-017 was built against a snapshot that was already stale, and the corpus has kept moving.**
Its field census — the load-bearing evidence for "this is a parser, not a heuristic salvage job",
and the stated reason no concept phase was needed — was taken over **12** THermo REQs. As of
THermo `e45f4ac` (2026-08-02) the corpus holds **28**. The 8-field grammar *does* still hold
**28/28**, so the census was short rather than wrong and REQ-017's core judgement survives. But
the sixteen REQs added since carry **four grammar constructs the parser has never seen**, and a
trial conversion of the live corpus **aborts on five files, writing nothing** ([[REQ-017]] AC6's
atomic guard working exactly as designed — the tool fails loudly and safely, which is why this
REQ can be written from evidence rather than guesswork):

```
aborted — 5 file(s): corpus not converted, nothing written:
  REQ-011.md: content before the first field bullet: '> **SUPERSEDED by [REQ-026](REQ-026.md)** (2026-07-04): the '
  REQ-012.md: content before the first field bullet: '> **SUPERSEDED by [REQ-027](REQ-027.md)** (2026-07-04): the '
  REQ-017.md: duplicate 'notes' field bullet
  REQ-026.md: 'depends_on' carries prose beyond its bullet line
  REQ-027.md: 'depends_on' carries prose beyond its bullet line
```

The four constructs:

1. **A blockquote banner between the header and the first field bullet.** THermo's superseded
   REQs open with `> **SUPERSEDED by [REQ-026](REQ-026.md)** (2026-07-04): …` — an editorial
   banner the parser reads as stray content before the field block.
2. **`Depends on:` carrying prose.** It is no longer a bare comma list:
   `REQ-011 (supersedes it)` and `REQ-026; exercises REQ-016, REQ-019, REQ-020, REQ-022,
   REQ-023, REQ-024`.
3. **A repeated field bullet.** THermo's REQ-017 grew a *second* `- **Notes:**` bullet today
   when the REQ-025 work prepended a superseding-detail note rather than editing the existing
   one.
4. **A ninth field.** `- **Implementation plan:** [doc/plans/REQ-026-thermoctl-fleet.md](…)`
   on two REQs — pointing into a real 22-file `doc/plans/` tree. This one does not abort; it is
   silently treated as body prose, which is benign today and fragile forever.

Two further deltas that change no code but change the plan:

- **Title drift went from 2-of-12 to 11-of-28.** [[REQ-017]] Decision 5 (the REQ file's header
  title wins, every conflict reported) now rewrites **eleven** index rows. The index rows are
  systematically the shorter, more editorial wording — e.g. file `Device-level rooms-set must
  merge, not clobber; device routes must survive a rooms rebuild` vs index `Rooms-set merge
  semantics + device routes survive rebuild`. Decision 5 stands, but the operator should expect
  a long conflict report and read it, not skim it.
- **The corpus is now entirely terminal.** REQ-011/012 flipped from active to `SUPERSEDED`, and
  REQ-025 — the last `OPEN` one — closed at `e45f4ac` **during this very intake session**. All 28
  are `DONE` or `SUPERSEDED`. This retires two things REQ-017 wrote down: onboarding parameter #2
  ("REQ-011/REQ-012 are carried as-is and stay active", so the gate reads *no terminal REQ has an
  active step") is **obsolete** — the ordinary globally-empty-queue gate applies; and
  [[REQ-017]] **Decision 10** (an active REQ with no runnable criteria imports as `draft`) has
  **nothing to fire on**. Decision 10 stays in the tool — it is the correct rule and the next
  prose corpus may well need it — but it is not exercised by this retrofit. THermo lands exactly
  as memzy did: a caught-up project whose next act is a `/intake`.

**The lesson underneath all of this is the one worth keeping.** Every construct above arrived in
the ~24 hours between REQ-017's census and this intake. A converter specced against a snapshot of
a *live* corpus is specced against a moving target; the fix is not a better snapshot but a tool
that tolerates a **class** of variation and fails atomically and legibly when it meets something
outside that class. REQ-017's abort behaviour is what made today's diagnosis a five-line report
instead of a half-converted directory, and it is not weakened here.

## Decisions

| # | Decision | Rationale |
|---|----------|-----------|
| 1 | **One REQ** extends the converter *and* drives the live retrofit, rather than splitting tool from run a second time | The [[REQ-017]] → retrofit split is precisely what let the tool go `done` against a corpus that had already moved past it. The live corpus is the only honest source of the grammar, and the §2b live-proof screen applies with full force: the risk here is *corpus-shaped*, so the proof belongs in an attended develop session where it is **fixable in place**, not routed to a validator that cannot fix anything. Rejected: two REQs (re-opens the same stale-snapshot gap); amending the landed REQ-017 (cuts against the ledger's terminal-status model) |
| 2 | The live run is a **develop-session obligation**, not an acceptance criterion; the `manual` AC covers only the human's post-hoc inspection of the end state | [[REQ-071]]/§2b: a proof routed to the System-Test phase has no repair loop — on a red it bounces back a whole session later. The conversion *will* turn up something (it did twice already, today), so it must be performed where iteration is possible. What genuinely needs a fresh pair of eyes — "is THermo correctly under the engine?" — has no fixing loop and is properly a `manual` sign-off. Contrast [[REQ-062]], which routed the whole proof to validation and whose sign-off is still pending a day later |
| 3 | The four new constructs are handled by **enumerated rule**, never by tolerance | Straight inheritance of [[REQ-017]] Decision 7 ("confidently parse or report" means an *enumerated* mapping). A parser that shrugs at anything it does not recognize will silently mangle the next corpus. Anything outside the enumerated set still aborts the whole run |
| 4 | `Depends on:` prose yields **every `REQ-NNN` token in source order** as `depends_on`, and the **raw source line is preserved verbatim** in the converted body | The ids are unambiguous and mechanically extractable; the qualifiers (`(supersedes it)`, `exercises …`) are human judgement the converter may not adjudicate ([[REQ-017]] Decision 2, archivist). Preserving the raw line honours "the source is never silently shortened" (Decision 4) so no qualifier is lost, and reporting the carry lets the operator check the extraction. Rejected: dropping the qualifiers silently; abstaining from `depends_on` entirely (loses a real, resolvable relation the linter checks) |
| 5 | Repeated field bullets **merge in source order** into one section; they do not abort | Two `- **Notes:**` bullets are two notes, not a malformed file — losing either would violate the non-destructive guarantee, and aborting would block a retrofit over a maintainer's ordinary editing habit. Merge preserves both, in order, and the merge is reported so nobody discovers it by diff |
| 6 | `- **Implementation plan:**` becomes a **known ninth field rendered as prose** in the body; no `plan_refs:` schema field is added | Recognizing it means it can never be mistaken for a body bullet or dropped; rendering it as prose means the link survives verbatim. DevSteward's plans gate finds `<plans_dir>/REQ-NNN*.md` **by convention**, so the pointer is already redundant to the engine — adding schema + lint surface for one migration's convenience is exactly the machinery-for-one-case the prefer-subtraction principle forbids. Rejected: dropping it with a report (loses a link for no gain); a `plan_refs:` field |
| 7 | `supersedes:` **is populated** on the superseding REQ, from either encoding — the `> **SUPERSEDED by [REQ-NNN]**` banner or a `(supersedes it)` qualifier in `Depends on:` — with every extraction reported and a disagreement between the two aborting | This is not the converter *inferring* a relation (which Decision 2 forbids); the relation is **stated**, unambiguously, in two places, and the schema has a field for exactly it. It also rescues information the conversion would otherwise destroy: `build_index` regenerates every row, so the index's `SUPERSEDED (by REQ-026)` annotation is dropped — with `supersedes:` populated the fact survives in frontmatter, where the linter resolves it. Note the direction: REQ-011's banner says *superseded by* REQ-026, so `supersedes: REQ-011` lands on **REQ-026** |
| 8 | Fixtures are **re-captured from THermo's HEAD at conversion time**, all 28, replacing the 12 | Same reasoning as [[REQ-017]] Decision 9 (the corpus-shaped risk *is* the real corpus; capture it wholesale, hermetically, so the suite never reads a THermo checkout) — but applied to a corpus now known to move. The commit that lands this REQ records the THermo SHA the fixtures came from, so the next drift is diagnosable rather than mysterious |
| 9 | THermo's **REQ-001 stays as it is** — a plain ArduinoJson feature that `infer_kind` types as `spec` purely because of its id — and no north star is authored | Onboarding is *migration*, not authoring. THermo has no north star; inventing one during a retrofit puts words in the project's mouth, and correcting the `kind` by hand is a cosmetic edit to a lint-clean, functionally inert field (lint's north-star rule keys on the **id**, not the kind — [[REQ-017]] Notes). The gap is real and is stated in the onboarding report as THermo's own later act |
| 10 | THermo's onboarding parameters from 2026-08-01 stand **except** #2, which is retired by events | Doc paths remain `doc/requirements`, `doc/requirements/REQUIREMENTS_INDEX.md`, `doc/plans`, `doc/concepts` (`doc/`, singular — a hand-maintained tree, not a generated one; [[REQ-084]]'s seams carry it). CLAUDE.md's drifted Phase-5 status table is still subtracted in favour of a pointer (one-source-of-status). Parameter #2 assumed two active REQs; there are now none, so the ordinary empty-queue gate applies |

## Requirement

Extend the legacy-prose converter to the grammar THermo's live corpus actually uses, then drive
THermo end-to-end under the engine and have a human sign off on the result.

### Part 1 — the converter extension (verified in this repo's suite)

`scripts/convert_reqs_prose.py` gains four enumerated capabilities, each reported to the operator
and each leaving [[REQ-017]]'s atomic-abort guarantee intact for anything outside the set:

- **Header banner** — a blockquote block between the `### REQ-NNN:` header and the first field
  bullet is body prose: it rides through verbatim into the converted body and is never a field.
- **Prose `Depends on:`** — `depends_on` takes every `REQ-NNN` token in source order; the raw
  source line is preserved verbatim in the body; the carry is reported (Decision 4).
- **Repeated field bullets** — merged in source order into one section, no text lost, reported
  (Decision 5).
- **`Implementation plan:`** — a ninth known field, rendered as a prose line in the body, never
  dropped and never parsed as a body bullet (Decision 6).

Plus `supersedes:` population from the two stated encodings (Decision 7).

The [[REQ-017]] reuse boundary is unchanged: `normalize_frontmatter`, `infer_kind`,
`dump_frontmatter`, `parse_acceptance_checkboxes`, `transcode_acceptance_block`, `splice_index`
and `build_index` are imported from `convert_reqs.py` and are neither duplicated nor modified.

### Part 2 — the live retrofit (an attended develop-session obligation, Decision 2)

Run the shipped `/onboard` skill ([[REQ-024]]) against the THermo checkout — convert the corpus
in place, seed the ledger, stamp the scaffold merging into THermo's existing `.claude/`, and
reconcile its `CLAUDE.md` — each step gated by `steward lint` / `steward status`, with
[[REQ-086]]'s commit-before-seed ordering in force so no gate has to be waved through. The run is
**attended and iterative**: it mutates another repo under live operator judgement, and anything
the real corpus turns up is fixed **in this session**, against the real corpus, with fixtures and
regression criteria updated to match. THermo's own repo changes are committed in **THermo's**
git; what lands here is the converter extension, the re-captured fixtures + goldens, and a short
onboarding report under `docs/reports/`.

THermo must end as a caught-up steward project: 28 terminal REQs, `steward lint` clean and
`steward status` reporting an empty work queue from THermo's root, with its `.claude/`,
`CLAUDE.md` domain guidance and `doc/` tree merged into rather than clobbered.

### Out of scope

- **Re-adjudicating any imported verdict** ([[REQ-017]] Decision 2), including the two SUPERSEDED
  REQs and REQ-025's deferred bench validation.
- **Authoring a north star** for THermo, or correcting REQ-001's `kind` (Decision 9).
- **Authoring acceptance-test ids** for any imported REQ. All 28 are terminal, so nothing needs
  arming; if a REQ is re-opened later that is THermo's own `/intake`-grade act.
- **Scenario / `ROADMAP` / non-REQ doc conversion** — the boundary [[REQ-010]] and [[REQ-017]]
  both drew. THermo's `doc/` holds a dozen design documents (`MQTT.md`, `Software_Architecture.md`,
  the PRDs) which stay living docs, untouched.
- **Fixing the onboarding machinery** — that is [[REQ-086]], upstream. A machinery defect
  surfaced *during* this run routes back there as rework; a **converter** defect is in scope and
  is fixed here, in session (Decision 2).
- **Adding a `plan_refs:` schema field** (Decision 6).

## Notes

**Symmetry, and the one deliberate asymmetry, with [[REQ-062]].** Same shape: a tracked REQ, a
live retrofit of a foreign repo, a `manual` sign-off, the substance landing in the other repo's
git. The asymmetry is Decision 2 — REQ-062 routed its *entire* proof to the System-Test phase and
that sign-off is still pending a day later, while the corpus it was proving against moved on. Here
the run itself is a develop obligation and only the end-state review is deferred.

**The moving-corpus hazard is live during the build.** THermo's REQ-025 closed *during this intake
session*. Re-run the trial conversion against THermo's HEAD at the **start** of the develop
session and treat any new construct as in-scope work, not as a surprise: capture the fixtures from
that same SHA and record it in the commit message (Decision 8). Ensure THermo's tree is clean and
`dev` is up to date before converting.

**Two known best-effort misses carried forward from [[REQ-017]], unchanged and not worked around.**
`infer_kind` maps `id == "REQ-001"` to `kind: spec`, so THermo's ArduinoJson REQ arrives as `spec`
(schema-valid, lint-clean, functionally inert — Decision 9); and Decision 4's preserved
`### REQ-NNN:` header leaves a level-3 heading above the generated level-2 sections. Both are
documented as deliberate in REQ-017's Notes; neither is in scope here.

**[[REQ-017]] Decision 10 is dormant, not dead.** With all 28 THermo REQs terminal, the
active-REQ-without-test-ids demotion has nothing to fire on. The rule stays in the tool for the
next prose corpus (ExamEngineer remains its second known consumer, if and when its upscale
concludes); it is simply not exercised by this retrofit.

**AC1–AC8 are `check: regression` and fully hermetic** — captured fixtures plus `steward lint` and
committed goldens as oracles, so no service, secret, network or THermo checkout is required by
the suite (the §2b environment-bound screen is clean). AC9 is the single `manual` criterion and
is the only thing routed to the System-Test phase. Per [[REQ-068]] every pytest command is
authored as `python -m pytest …`.

**`process:` is omitted** — every value is the default (`develop: fused`, `concept: false`,
`lab: []`). No concept phase: the four new constructs are enumerated from a live trial run above,
the oracles already exist, and the acceptance criteria are writable today ([[REQ-071]]'s decision
rule). The develop session is nonetheless **attended** by nature — it drives another repo under
operator judgement — so start it explicitly with `/advance REQ-085 develop`, not headlessly.
