## Context

Stage A of REQ-047 (plan `docs/plans/0026-single-source-of-truth-trunk-based.md`).
Implemented **by hand**, not under `steward` — the engine had lost the right to drive its own
repair until structurally incapable of diverging.

The divergence bug-class (REQ-037/040/041/043/044, `046-F1`, the `steward decision`
stranding) all traced to one premise: engine state lived in two branch-locations — the ledger
on `dev` via a worktree, the code on a feature branch — bridged by a destructive
`git checkout`. You cannot enumerate every precondition for that switch; you *delete the
second location*. This REQ collapses to **one branch (`dev`), one co-located ledger, no
switching** — so the entire firefighting table stops *existing* rather than being guarded
against. It is the foundation the universal transaction boundary (REQ-049) then layers on.

This is **subtraction**: ~18 methods removed from `core/git.py`, the worktree/branch lifecycle
removed from `core/executor.py` and `core/seams.py`, lint rule 8 (feature-branch ledger-diff)
deleted, the `feature_branch` config dropped, and two whole test files retired
(`test_branch_lifecycle.py`, `test_plane_split.py`). Net less engine code.

## Decisions

| # | Decision | Rationale |
|---|----------|-----------|
| 1 | **All work on `dev`.** No feature branch, no worktree, no engine `checkout`/`switch`/`merge`. The per-step flow is: run on `dev` → commit code → commit the ledger advance. | Eliminates the divergence bug-class by construction — one location cannot diverge from itself. |
| 2 | **Two commits per landed step, kept separate** — the work commit (code + REQ `done`-flip + index `DONE`-sync, same-commit discipline) **excludes** `.devsteward/`; the cursor advance is its own trailing `.devsteward/`-only commit. | Clean code history independent of the cursor, and the precondition REQ-050 (commit integrity) checks against. Minimal change from today — just drop the worktree indirection. |
| 3 | **Supersede the topology stack** (037/040/041/043/044): their machinery is removed, not patched. The schema's `supersedes` is widened to accept a list so this REQ names all five. | Net less code; deletes the worktree/switch/branch-recovery surface entirely. |
| 4 | **The `dev → main` release is human-gated (a PR), not an engine command** — so `merge_no_ff`/`fetch` have no engine caller and are removed too. A future engine release path is its own REQ. | Prefer subtraction; there is no caller to keep. |

## Requirement

- The engine never creates an implementation feature branch, never switches branches, and
  never spins up a worktree during develop/land/validate/park; every commit lands on `dev`.
- The ledger is the single `.devsteward/` at the repo root; reads and writes resolve the same
  source from any state.
- A green land leaves `dev` clean: the work commit (no `.devsteward/`) then the trailing
  ledger commit; a park commits its ledger close on `dev`; no empty commits.
- The `supersedes` frontmatter field accepts a single id, a list of ids, or null.
