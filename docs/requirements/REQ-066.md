## Context

REQ-057 shipped `STEWARD.md` — the Claude-targeted black-box `steward` manual — into the
templates and had `steward new` stamp it into the consumer root, where the consumer
`CLAUDE.md` points at it as the authoritative `steward` usage doc. Like the four bundled
skills, it is **pure engine behaviour meant to track the engine**: it documents the current
command surface and recovery model, so when the engine advances the stamped copy goes stale
exactly the way a stamped skill does (REQ-036 Finding 50). Unlike `CLAUDE.md`/settings —
which REQ-036 Decision 1 deliberately excluded because they are filled *per project* and
overwriting them clobbers the consumer's own content — `STEWARD.md` is never customized
per project; it is engine-owned text the consumer should keep current.

But REQ-036's drift machinery is **scoped to `.claude/skills/<name>/SKILL.md`**:
`bundled_skill_names()` enumerates skill directories, the lock is `skills.lock`, the verb
is `sync-skills`, and the `steward status` signal says "skills". `STEWARD.md` falls outside
that set entirely, so it has **no provenance record, no drift signal, and no refresh path**
— the precise gap REQ-036 closed for skills, left open for the manual.

The concrete trigger: **FlowSteward did not have `STEWARD.md` at all.** It was onboarded
before REQ-057 existed, so the manual was never stamped, and nothing surfaces or fixes the
absence — `steward sync-skills` only knows about skills. The agent driving DevSteward from
FlowSteward therefore has no black-box manual and is pushed back toward reading engine
source, the exact leak REQ-057 set out to close. The drift mechanism already has a `MISSING`
bucket that `sync` refreshes; `STEWARD.md` just isn't in the set it scans.

The mechanism in `skillsync.py` is already a general content-hash drift tracker (stamped
**S** / lock **L** / template **T**, with `MISSING`/`STALE`/`CUSTOMIZED`/`BOTH_MOVED`
buckets). Only its *scope* is skills-specific. The honest move is to **generalize the scope
to "engine-owned stamped artifacts"** (the four skills + `STEWARD.md`) rather than bolt on a
parallel one-off path — subtracting the skills special-case, in the spirit of preferring
subtraction over added machinery.

## Requirement

Bring `STEWARD.md` under the same drift-tracking, signalling, and refresh that REQ-036 gave
the bundled skills, by generalizing the mechanism's scope to all engine-owned stamped
artifacts:

- The tracked set is **engine-derived** and comprises the bundled `.claude/skills/<name>/
  SKILL.md` files **and** the root `STEWARD.md` the template ships; no hand-maintained list.
- The provenance manifest is `.devsteward/stamped.lock`; a legacy `.devsteward/skills.lock`
  is still read when `stamped.lock` is absent (transparent forward migration), so no existing
  consumer's recorded provenance is lost.
- `steward new` seeds the manifest with every tracked artifact's source template hash,
  including `STEWARD.md`, so a freshly-stamped project reports every artifact in-sync.
- Drift detection classifies `STEWARD.md` by the same three-hash buckets as a skill
  (in-sync / stale / customized / both-moved / **missing**); `steward status` reports any
  non-in-sync artifact as a non-blocking warning naming the artifact and the bucket, pointing
  at `steward sync`.
- `steward sync` refreshes every **stale** or **missing** tracked artifact (so a consumer
  lacking `STEWARD.md` acquires it) to byte-match the installed template and updates the lock;
  a **customized** artifact is left untouched and reported unless `--force` (which backs the
  local copy up to `.orig` first). `steward sync-skills` remains a working alias.
- The `onboard` skill's scaffold-stamp step seeds the generalized lock by running
  `steward sync`, so a retrofitted project ends with `STEWARD.md` present and a populated
  `.devsteward/stamped.lock` — the same provenance baseline a `steward new` project gets —
  while `sync`'s customized-refusal preserves any same-named artifact the project already
  owns (merge, never overwrite).

## Notes

- **Out of scope:** syncing `CLAUDE.md` / settings / non-engine scaffolding (REQ-036
  Decision 1 stands — those are per-project content); a 3-way prose merge of a customized
  artifact (`--force` + `.orig` backup instead, as for skills); broadening the set to any
  further files beyond the skills + `STEWARD.md` (add them only when a concrete need appears).
- **Implementation shape.** `skillsync.py`'s mechanism is reused verbatim; only its *scope*
  generalizes. Skills are discovered as `<name>/SKILL.md` directories; `STEWARD.md` is a
  fixed root file — so the "tracked artifact" enumeration covers both a discovered-directory
  form and a named root-file form, both still derived from what the template actually ships
  (no hand-maintained list, preserving REQ-036's engine-derived guarantee).
- **Onboard path (Decision 6).** FlowSteward was onboarded, not `steward new`'d — and
  `onboard` never seeded the lock (it merges into a non-empty project rather than running
  `steward new`), which is the root reason it had neither provenance nor a manual. This REQ
  has `onboard`'s scaffold-stamp step run `steward sync`, so a retrofitted project ends with
  the full engine-owned artifact set stamped and a populated `stamped.lock` baseline. The
  `MISSING`→refresh path (Decision 4) still independently rescues any *already-onboarded*
  consumer (like today's FlowSteward) on its next `steward sync`, regardless of how it was
  created — so both the future onboard path and the existing fleet are covered.
- **Verb/lock naming churn.** The `sync-skills`→`sync` and `skills.lock`→`stamped.lock`
  renames touch the black-box manual and handbook prose that name the old verb; those docs
  are refreshed to `steward sync` as part of this REQ (and themselves become a tracked
  artifact kept current by it). The `sync-skills` alias keeps older stamped copies working
  until they are synced.
- **Process declarations:** fused develop, no concept phase, **no devsteward lab**
  (`lab: []`) — AC5 reuses FlowSteward, a real consumer repo (the REQ-036 AC5 precedent),
  not a DevSteward-owned lab asset; AC1–AC4 run headless on synthetic stamped projects in a
  temp dir.
- **Localization:** engine/CLI/manifest/doc text is technical English; no user-facing
  localized strings (house rule).
