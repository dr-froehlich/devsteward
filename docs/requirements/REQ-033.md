## Context

The first real lab validation did exactly what the V-model promised: FlowSteward
REQ-012 AC4's live IMAP choreography caught a fake-vs-real defect (live Dovecot returns
`MODSEQ` as a tuple; the fake QRESYNC server behind the regression AC returns a scalar)
plus a credential-stem mismatch in the validation test itself. The engine recorded the
red evidence event and parked, per REQ-030 Decision 8 — and then the process dead-ends.

The V-model's return edge is missing. After a red validation the only verbs are:

- `steward decision answer` — re-pends the **validate** step only, re-running validation
  against the same broken code;
- `steward recover` — **refuses**: it re-arms `FAILED` steps (REQ-026 D4), and a red
  validation leaves no `FAILED` step (develop is `DONE` on the still-unmerged req
  branch; validate is `BLOCKED` behind the parked decision).

So the genuinely expected outcome — *the lab found a defect, go fix it, revalidate* —
can only happen off the books: an ad-hoc interactive session on the branch, then ledger
surgery or a re-pend that loses the findings. REQ-030 Decision 8's rationale ("a red
here is a human question") is right and **stays**: the engine must never auto-loop on
red. What is missing is the verb that records the human's *answer* to that question when
the answer is "the code (or the validation test) is wrong — fix it and revalidate".

## Decisions

| # | Decision | Rationale |
|---|----------|-----------|
| 1 | **`steward rework REQ-NNN`** is a new operator verb, a sibling of `recover` in `lifecycle.py`: it finds the REQ's red-validation state, flips `REQ-NNN:develop` `DONE → RECOVER` and `REQ-NNN:validate` `BLOCKED → PENDING`, and answers any open decision parked on the validate step as reworked. | One verb = one intent ("human reviewed the red, orders a fix"). It must work whether or not a decision row exists (an attended red parks too, but future red paths may not), which rules out overloading `decision answer`; and `recover`'s precise contract (re-arm what *failed*) stays unmuddied — its help text already misled once. |
| 2 | **Findings travel through the ledger, not the command line:** `rework` appends a `rework` event carrying the red validation's evidence dir and failure brief; the `/advance` skill, on finding its step in `RECOVER` with a `rework` event, orients from that event and reads the evidence dir (including the System Tester's findings write-up) as its repair context. | Orientation-from-ledger is already the skill contract (REQ-009/026); the System Tester already wrote the diagnosis (`SYSTEM-TEST-FINDINGS.md`, logs) — the human should not re-type it, and step commands stay derived from the source with no command-override plumbing. |
| 3 | **Scope: in-flight reds only, both kinds.** Rework covers an artifact-AC red *and* a declined manual sign-off on an in-flight REQ — same mechanism, same still-open req branch. A red on re-validating a **done** REQ (REQ-030 D5 re-runs) is out of scope: done is never weakened (REQ-001) — change direction by superseding. | The declined-manual case is the same shape ("human looked, code is wrong") and excluding it forces ledger surgery; the done case crosses the one invariant `activate`/`recover` both already enforce. |
| 4 | **No engine cycle bound.** Every rework cycle costs an explicit human verb — that *is* the bound. This **amends REQ-030 Decision 8** without weakening it: the park stays, the engine still never spawns a repair session on red; `rework` is the recorded human answer, not a repair loop. | D8 rejected *automated* cycles (repair + full gate + fresh Opus validate per attempt, and the fix usually needs the human anyway). A human-authorized cycle has the human in exactly the position D8 demands. |
| 5 | **The verb touches no git** (the `recover` D6 precedent): the req branch is still open with develop's work on it; the reopened develop step runs through the existing executor path, whose branch machinery (REQ-020) checks the req branch out again, and a green re-validation lands through the unchanged REQ-030 D6 topology. | Rework is a pure ledger mutation; the branch lifecycle already knows how to resume an open implementation branch, and reusing it keeps one land topology. |

## Requirement

`steward rework REQ-NNN` is the human-authorized return edge from a red validation back
to develop:

- On an in-flight REQ whose latest validation event is red (artifact red **or** declined
  manual sign-off), it flips `REQ-NNN:develop` to `RECOVER` and `REQ-NNN:validate` to
  `PENDING`, answers any open decision parked on the validate step, and appends a
  `rework` event carrying the red validation's evidence path and failure brief. It
  touches neither git nor the REQ file.
- It **refuses** (non-zero, with a pointing message) when the REQ has no red validation
  to rework — in particular on a `done` REQ (supersede instead) and on a REQ whose
  validate step is not blocked-red.
- The reopened develop step is eligible again through the normal executor path: the
  `/advance` skill orients from the `rework` event, reads the evidence dir as its repair
  context, fixes on the same req branch, and the develop gate re-runs in full; the
  validate step then re-runs as a fresh System Tester session producing a fresh evidence
  event, and a green re-validation lands through the unchanged mechanical-land topology.
- REQ-030 Decision 8 is amended, not repealed: a red validation still parks immediately
  and the engine never spawns a repair session on its own; `rework` records the human's
  verdict and re-arms the loop, one explicit verb per cycle.

## Notes

- **Out of scope:** reworking a **done** REQ's red re-validation (supersede — REQ-001);
  any engine-spawned repair session on red (REQ-030 D8 stands); auto-staleness or
  rework-count limits (the explicit verb is the bound); changes to the System Tester
  skill (it already writes the findings the loop consumes).
- **Surfaces (expected):** `devsteward/lifecycle.py` (the `rework` verb beside
  `activate`/`recover`), `devsteward/cli.py` (`steward rework`), `devsteward/core/ledger.py`
  (the `rework` event kind; reading the latest validation event for a REQ), the
  `/advance` skill's orientation section (repo `.claude/skills/` + stamped
  `devsteward/templates/.claude/skills/`, kept identical), handbook 02/03 (the V-model
  return edge), and the `steward recover` help text (point red-validation cases at
  `rework`).
- **Why develop reopens as `RECOVER`, not `PENDING`:** `RECOVER` is already the
  executor-runnable "re-attempt with assessment" status (REQ-026 D4) and `/advance`
  already carries the resume contract; reusing it means the fix session assesses the
  branch's existing work instead of starting blind.
- **Localization:** operator-verb and event text is technical English; no user-facing
  localized strings.
