## Context

On 2026-06-23 a **green, correct, paid-for develop session was discarded** by the engine.
FlowSteward's `steward run` built `REQ-043:develop`, the per-step acceptance gate went
green, the engine recorded the work commit (`b15ab0e`) — and then DevSteward's REQ-050
commit-integrity gate `git reset --hard`'d that commit away and refused, reporting "nothing
was certified." The implementation was sound; the work survived only as a dangling reflog
commit with **no surfaced SHA**, no branch, no tag, no stash. Salvaging it cost a manual
reflog recovery. (Source: FlowSteward `docs/postmortems/2026-06-23-req-043-capture-gate-discarded-session.md`,
Defect 2 — filed here as that project asked.)

**The chain.** REQ-050's `_assert_green_captured` (`devsteward/core/executor.py`) re-runs a
develop step's named acceptance tests against a *clean `git archive` extract* of the work
commit — only tracked content. FlowSteward's AC file is entirely `pg_required`; the lab
Postgres is selected by a **gitignored `.env`**, which is not in the extract, so the test
bootstrap fell back to in-memory SQLite and both tests **skipped**. `_reproduces_green`
treats `skipped or failed or errors` as a gap (mirroring the land gate's `skip ≠ green`), so
the gate declared the commit's green unreproducible, `reset --hard`'d the work, and raised —
with recovery text ("commit them, or fix `.gitignore`") that is **actively wrong** for the
secrets case (you must *not* commit `.env`).

**Provenance — the owner's fear is correct.** This came in *with* the trunk-based migration:
REQ-050 is, by its own Context, "Stage C of REQ-047." So the destructive behaviour is a
REQ-047-era construct, not pre-existing.

**The fatal conflation (the owner's "atomic commit" instinct, named).** The post-REQ-047
engine carries two distinct "atomicity" ideas, and REQ-050 fused them wrongly:

1. **Mutation atomicity** (REQ-049, INV-3, `transaction.py`): a *write* is all-or-nothing —
   on a mid-write failure, `reset --hard` to the pre-command snapshot. Sound: it forbids a
   *half-applied* mutation.
2. **Commit self-sufficiency** (REQ-050): a recorded commit should reproduce its own green —
   a *quality judgment about content*, made *after* a fully successful write (work done,
   verify green, commit succeeded).

REQ-050 treated a **failed quality judgment on an already-successful mutation** as if it were
a **failed mutation**, and to force the rollback it *deliberately reached around* the
transaction boundary (a `PreconditionError` normally passes through *without* a rollback — so
REQ-050 Decision 3 hand-codes `reset_hard(snapshot)` *first*, then raises, on the premise that
"a stranded work commit is the half-state Stage C forbids"). **That premise is the bug.** There
is a third outcome that is neither "certified" nor "half-state": *work committed, certification
withheld, operator told where the work is and why.* By bundling the `done` flip **into** the
work commit (same-commit discipline) and then rolling the whole commit back, REQ-050 made
"withhold certification" mean "**destroy verified work**."

The correct model: **certification is the atomic unit — the `done` flip + index DONE-sync +
cursor + ledger advance, all-or-nothing. The work commit is durable the moment `verify` goes
green and must never be in the rollback set.** (The engine already proves this shape exists:
`commit_deferred` commits pure code and defers the flip to a later validate land.)

**Two gaps, confirmed as DevSteward defects** (FlowSteward's all-`pg_required` AC riding a
gitignored `.env` is a real co-contributor — Defect 1, theirs to fix — but it does **not**
exonerate the engine: no capture verdict licenses destroying verified work, and consumers
*will* write environment-bound checks):

1. **It destroys recoverable work with no affordance.** On a gap it `reset --hard`s the work
   away, prints no SHA, creates no ref, and gives wrong recovery advice.
2. **It cannot tell an *environment* skip from a *source-capture* gap.** A `pg_required` skip
   in the bare extract means "the required service isn't wired into the capture run" — the
   *same* category as a lab-backed artifact AC, which the engine **already exempts** in the
   validate phase (`_assert_green_captured` returns early for `phase == "validate"`, for this
   exact reason). Applying the tracked-content reproduction to an environment-bound develop AC
   is the category error that exemption was written to avoid.

This REQ does **not** supersede REQ-050: its guarantee — *a recorded commit reproduces its
green* — is retained for genuine source/test gaps. What changes is the **consequence**
(withhold, never destroy) and the **gap definition** (a skip is excluded).

## Requirement

- The named-AC **capture check** runs against a **pure-code work commit** (no `done` flip /
  index sync baked in); **certification** — the REQ `done` flip, the index DONE-sync, the
  cursor advance, and the ledger advance — is a separate, atomic step that runs **only** when
  the capture check is clean. No engine land path performs a `reset --hard` (or any deletion)
  that discards a committed, `verify`-green work commit.
- On a **capture gap**, the engine **withholds certification without destroying the work**:
  the pure-code work commit remains on `dev`, the REQ does not flip `done`, the step fails to
  a **repeatable** state, and the engine **surfaces the work-commit SHA** and the named gap.
  The tree is left clean at rest (the ledger close is committed).
- A named test that **passed `verify`** but only **skips** in the bare extract (its runtime
  environment — DB/secret/service — is absent) is **not** a capture gap: the land **certifies**
  normally. Only **fail / error / zero-collection** in the extract is a gap.
- A genuine **source/test capture gap** (an uncaptured source or test file → fail / error /
  zero-collection in the extract) is **still refused**, with the gap named and the work
  preserved + surfaced (REQ-050's guarantee, made non-destructive).
- The surfaced recovery **names the preserved work-commit SHA** and the environment cause; it
  does **not** instruct committing a gitignored secret as the remedy.
- A self-sufficient green (depending only on committed source) certifies normally — the
  re-architecture raises no false positive.
- The Claude-targeted `steward` black-box manual and the handbook note the non-destructive
  withhold behaviour and the environment-bound recovery path.

## Notes

- **Residual narrow edge (accepted).** Treating an extract skip as not-a-gap means a test that
  *self-skips* on a missing **gitignored data fixture** would no longer be caught by this gate.
  This is narrow and already covered upstream: REQ-051 (lab fixtures upstream; the System Tester
  never improvises) and the artifact/lab taxonomy say fixtures live in-repo or are owned by a
  lab REQ, and FlowSteward's Defect-1(b) note ("don't ship all-skip AC files") addresses the
  consumer side. A genuinely missing *source/test* file still surfaces as error/failure, which
  remains a gap.
- **Not the validate land.** This is and stays a *develop*-land invariant; the validate phase
  remains exempt (`_assert_green_captured` early-returns for `phase == "validate"`) — its
  integrity is the captured-evidence contract, not commit-extract reproduction.
- **Editable-install caveat unchanged** (REQ-050 Notes): re-running tests against the archive
  imports the package from the extract unless it is pip-editable-installed and shadows it on
  `sys.path` — bites only a project testing its own editable-installed code (DevSteward
  dogfooding); consumers (FlowSteward) aren't editable-installed, so the extract is authoritative.
- **Out of scope:** the FlowSteward-side fix (an all-`pg_required` AC riding a gitignored
  `.env` — Defect 1, theirs), and any intake/taxonomy left-shift to flag environment-bound
  `regression` ACs (re-intake separately if wanted — Decision 6).
