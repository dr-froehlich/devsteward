## Context

`core/claude.run_claude` invokes `claude -p "<command>" --output-format stream-json
--verbose` with **no permission mode**. A headless session has no interactive approver, so
every `Edit`/`Write`/`Bash` either stalls waiting for an approval that can never come or is
denied — the session produces nothing. This is the mechanical reason the engine's core loop
has never done real build work: combined with the toothless `design`/`build` verify
("marker trust"), a no-op run still reached `DONE` and committed empty bookkeeping
(`.devsteward/events.jsonl` shows exactly this, later retracted).

The proven reference runner (`Theresa/run_batch.py`) launches `claude -p …
--dangerously-skip-permissions`. DevSteward dropped that flag. This REQ restores autonomous
action for headless runs and makes the strictness configurable, then lets the reality gate
(REQ-013) prove a real edit now lands.

## Decisions

| # | Decision | Rationale |
|---|----------|-----------|
| 1 | Always pass a permission flag for headless `claude -p`; default `dangerously-skip` | A headless session can't be approved interactively, so an autonomous default is the only thing that works; mirrors the proven `run_batch.py` |
| 2 | Make it configurable via `.devsteward/config.yaml` `claude.permission_mode` | A consumer in a less-trusted repo can soften to a `--permission-mode` value; strictness is a per-project call, like REQ-011's branch names |
| 3 | `_permission_argv` maps the setting to flags: `dangerously-skip`/`skip` → `--dangerously-skip-permissions`; a claude mode (`bypassPermissions`/`acceptEdits`/`plan`/`default`) → `--permission-mode <mode>`; `ask`/empty/None → no flag | One small, testable seam; `ask` keeps the attended/interactive path (and tests) flag-free |
| 4 | Thread the mode config → `build_executor` → `Executor.permission_mode` → runner call | The executor already owns how `claude` is invoked; this rides the same path as `argv_prefix`/`unattended` |
| 5 | The real "edits now land" proof is REQ-013's opt-in gate, not a mock | A hermetic test can only prove the flag is present; only a real run proves the behaviour. Hence AC1–AC3 are plumbing; the behaviour is the reality gate |

## Requirement

Headless `claude -p` runs with a permission mode that permits autonomous edits, defaulting
to `--dangerously-skip-permissions` and overridable per project:

1. `run_claude` appends permission flags derived from a `permission_mode` argument
   (default `dangerously-skip`); `_permission_argv` performs the mapping in Decision 3.
2. `Config` reads `claude.permission_mode` (default `dangerously-skip`); `build_executor`
   passes it to `Executor`, which forwards it on every runner invocation.
3. The stamped `config.yaml.tmpl` documents the knob; DevSteward's own config pins it.

Once landed, REQ-013's `test_real_claude_end_to_end` build/land steps can actually create
and commit `greeting.txt` (the remaining red there is account rotation, REQ-012).
