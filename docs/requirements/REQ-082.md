## Context

Anthropic's prompt cache is a rolling-TTL prefix cache: a Claude Code session stays
"warm" as long as consecutive API requests are less than one TTL apart (1 hour on the
operator's plan; the API can drop to 5 minutes after a usage-limit/overage). Returning to
an idle session past the TTL re-processes the whole conversation as fresh input — slow
and roughly 10× the cache-read usage for that one request. The operator repeatedly wants
to know *before* sending anything: is this project's session still warm, or should I let
it go cold / start fresh?

There is no Anthropic API to query cache state, and asking *inside* the session is
self-defeating — the question is itself a request that re-warms (or cold-pays) the cache.
But warmth is fully deterministic from the outside: Claude Code appends every event to
the session transcript under `~/.claude/projects/<slug>/<session>.jsonl`, so the newest
transcript's mtime is a faithful "last request" clock, readable from a second shell with
zero session impact. Today this is a hand-rolled `stat` one-liner that requires knowing
the slug encoding (absolute project path with `/` → `-`); a `steward cache` verb makes it
a per-project, no-thought check in every steward-managed repo. This advances REQ-001 as
operator tooling for the session economics the engine's attended workflows (validate,
rework, checkpoint) depend on.

## Decisions

| # | Decision | Rationale |
|---|----------|-----------|
| 1 | Newest session only | The question is "is my session warm"; a multi-session table is more surface for a rarer case. |
| 2 | Verdict against a 60-minute default TTL, `--ttl` override (minutes) | Matches the plan's 1-hour rolling TTL; the undetectable overage→5-minute case is handled by the operator passing `--ttl 5` when they know it applies. |
| 3 | mtime-only; prefix invalidation out of scope | Model switch / compaction kill the cache regardless of age, but detecting them means parsing Claude Code's transcript format — fragile coupling for a hint tool. The output prints the caveat instead. |
| 4 | Resolve the project as `git rev-parse --show-toplevel`, falling back to cwd | Claude Code slugs by its launch directory, which is normally the repo root; steward may be invoked from a subdirectory. |
| 5 | Projects root behind an env seam (`CLAUDE_PROJECTS_DIR`, default `~/.claude/projects`) | Lets the regression suite run against a temp tree in a clean checkout — no real `~/.claude` required, no environment-bound green (REQ-064). |
| 6 | Read-only, ledger-free, exit code carries the verdict | The verb never writes anything and never touches `.devsteward/`; scriptable: 0 = warm, 1 = cold, 2 = no transcript found. |
| 7 | Regression-only acceptance | The logic (slug encoding, newest-file selection, age math, verdict, exit codes) is fully testable against a fake projects tree; the tool is observed in daily use anyway. No validation phase. |

## Requirement

`steward cache` reports, for the project it is invoked from, how long ago the newest
Claude Code session transcript was written and whether the prompt cache is warm under the
assumed TTL — computed purely from the filesystem, so running it from a second shell
never touches the session or the cache itself.

Behavior:

- Resolve the project root (git toplevel, else cwd), encode it to the Claude Code
  project slug (absolute path, `/` → `-`), and locate the newest `*.jsonl` under
  `$CLAUDE_PROJECTS_DIR/<slug>/` (default `~/.claude/projects/<slug>/`).
- Print one line: session id (transcript basename), minutes since last write, and the
  verdict `WARM` (age < TTL) or `cold`, plus the standing caveat that the check is
  age-based and a model switch or compaction invalidates the cache regardless of age.
- `--ttl MINUTES` overrides the default threshold of 60.
- Exit 0 when warm, 1 when cold, 2 (with a clear message naming the directory it looked
  in) when the project has no transcripts.

## Notes

- **Out of scope (Decision 3):** detecting prefix invalidation (model switch, compaction)
  by parsing transcript contents; multi-session listing; any query against the Anthropic
  API. If Claude Code ever changes its transcript layout, this verb degrades to exit 2
  (not-found) — a visible failure, not a wrong verdict.
- The overage→5-minute TTL drop is undetectable from the filesystem; the `--ttl` override
  is the honest lever (Decision 2). The default stays 60 even if the plan's TTL changes —
  it is a threshold the operator owns, not a probed value.
- All acceptance oracles are self-contained against the `CLAUDE_PROJECTS_DIR` seam — no
  service, secret, network, or real `~/.claude` required in a clean checkout (REQ-064
  screen: pass).
- Origin: 2026-07-17 session-economics conversation — the hand-rolled
  `stat`-the-newest-jsonl one-liner this verb productizes.
