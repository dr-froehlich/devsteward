## Context

REQ-037 made the merge that carries a feature branch home atomic: a conflict aborts and
surfaces a recovery instruction instead of crashing. But it left one abort path — and one
git switch — outside the guarantee, and a live FlowSteward run rode the gap into the exact
unrecoverable split REQ-037 set out to abolish.

The mechanism, confirmed against the code:

1. `prepare_branch` (`executor.py:270`) detects a **diverged** feature branch, calls
   `self.ledger.append_event("branch_diverged", …)`, then **returns a surface message
   without committing**. Because `prepare_branch` only acts while HEAD is the integration
   branch, that append dirties the integration tree's tracked `.devsteward/events.jsonl` and
   leaves it dirty — a terminal step outcome that violates REQ-032's "every terminal outcome
   leaves a clean tree." It is the lone abort path that appends-but-never-commits: its REQ-037
   siblings `ready_validate_branch` (`reconcile_aborted`) and `_record_aborted_merge`
   (`merge_aborted`) both append **and** commit on the integration branch.

2. A **later** step's green land reaches `_merge_after_land` →
   `_return_main_tree_to_integration` (`executor.py:217`). That routine calls
   `clean_untracked_ledger()` — which is `git clean -fdq` (`git.py:133`), removing only
   *untracked* files, never a *modified-tracked* one — then `remove_integration_worktree()`,
   then `switch(integration)`, which is `git checkout <branch>` with `check=True`
   (`git.py:45`). Git refuses to overwrite the dirty tracked `events.jsonl` and exits
   non-zero → an **uncaught `CalledProcessError`**.

The crash is uniquely nasty because of *where* it lands: the worktree is already removed and
the land's ledger checkpoint already committed, so the repo is in a half-state no `steward`
verb targets — `recover` re-arms a step that never failed (validate passed), `checkpoint`
re-lands (risking ledger drift), and neither resumes "just the merge." Recovery is
hand-surgery. This is the same failure class as REQ-037 Decision 2 (atomic topology ops that
abort rather than crash), simply not yet extended to the divergence-surface path or to the
close-out's pre-switch tree.

Scope is **prevention only** (no `steward recover --resume-merge`): close the two seams so
the half-state can never be reached. No repo is currently stranded — the reporting session
recovered by hand — so there is no live-rescue obligation here.

## Decisions

| # | Decision | Rationale |
|---|----------|-----------|
| 1 | **The divergence-surface path commits its diagnostic on the integration branch before returning.** `prepare_branch` appends `branch_diverged` (and any sibling `branch_*`) **and** commits the ledger (the `_commit_ledger_close` shape its REQ-037 siblings use) so the surfaced refusal leaves a clean tree and a durable record. | Removes the dirty tracked write at the root, satisfies REQ-032 for this terminal outcome, and makes the three abort paths (`reconcile_aborted`, `merge_aborted`, and now the divergence surface) uniform. **Rejected:** *don't persist the event when about to abort* — simpler and also leaves a clean tree, but it drops the divergence breadcrumb from the durable ledger and makes this path behave differently from its two committing siblings. |
| 2 | **The topology close-out treats a dirty integration tree as a handled, surfaced precondition — never a raised `git checkout`.** `_return_main_tree_to_integration` / the switch detect an uncommitted tracked `.devsteward/` change before switching and, rather than letting git refuse and crash, abort-and-surface a precise recovery instruction (and park when `DEVSTEWARD_UNATTENDED=1`), leaving the repo intact. REQ-037's atomicity guarantee is thereby extended to "no uncommitted writes outside the transaction exist before switching." | Decision 1 removes the *known* producer of pre-switch dirt; this is the defense-in-depth floor so any *other* future producer surfaces as a recoverable precondition instead of re-opening the unrecoverable-split crash class. Mirrors the REQ-037 D2 abort-and-surface pattern exactly. |

## Requirement

Close both seams so the divergence-then-land sequence can no longer strand the repo:

- When `prepare_branch` refuses a diverged feature branch, the integration working tree is
  **clean** at the surface (no uncommitted `.devsteward/` change), and the `branch_diverged`
  diagnostic is **committed** on the integration branch.
- The topology close-out switch back to the integration branch never raises an uncaught
  `CalledProcessError` on a dirty tree: an uncommitted tracked `.devsteward/` change is
  detected and handled as a surfaced (attended) / parked (unattended) recoverable
  precondition, with the repo left intact.
- End to end: a real run that surfaces a diverged feature branch and then lands a *later*
  step completes the close-out without crashing, and the integration branch is clean at rest.

## Notes

- **Real-git teeth (the REQ-037 / plan 0021 lesson):** all ACs run against a real `git init`
  repo with the real `GitCli`; only `claude -p` and the interactive bring-up are faked. A unit
  fake that keeps one in-memory ledger and never reflects a dirty tracked file on a switch is
  exactly what would hide this bug — the crash is a property of `git checkout` refusing to
  clobber a tracked modification, which only real git exhibits. Tests live alongside REQ-037's
  in `tests/test_plane_split.py`.
- **Process declarations:** defaults — fused develop, no concept phase, **no DevSteward lab**
  (`lab: []`): ACs run on synthetic real-git repos in a temp dir. No `manual` AC — the live
  FlowSteward witness that motivated REQ-037 already covers the close-out at large; this is a
  targeted prevention fix with decoupled real-git oracles.
- **Out of scope:** a `steward recover --resume-merge` verb for an already-crashed half-state.
  Prevention closes the only known producer (Decision 1) and adds the defense-in-depth floor
  (Decision 2), so the half-state stops being reachable; a recovery verb is unnecessary once
  it cannot occur. If a future, unforeseen producer of a crashed pre-merge half-state is found,
  a recovery verb is its own follow-on REQ.
- **Relationship to REQ-037:** finishes Decision 2 for the two paths it did not reach — the
  divergence-surface abort and the close-out's pre-switch tree. No REQ-037 behaviour changes.
