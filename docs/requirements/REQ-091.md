## Context

REQ-090 moved every model identifier out of engine Python and into the stamped config —
correctly: a model string in a module couples DevSteward's releases to Anthropic's, and it
made the *global* default invisible while the per-step overrides were configurable, which is
backwards. What it did **not** do is reconcile that move with the configs already on disk.

The deleted constant was not decoration. `devsteward/config.py` (pre-`93ad820`) held:

```python
STEP_CLAUDE_DEFAULTS = {
    "develop":  {"model": None,                 "effort": None},
    "repair":   {"model": "claude-sonnet-4-6",  "effort": None},
    "validate": {"model": "claude-sonnet-5",    "effort": None},
}
```

Every already-stamped project inherited that tier **without naming it** — the config files
carried the `steps:` block only as a *commented-out example*. Deleting the constant deleted
those projects' repair/validate policy with it. `Config.step_claude("validate")` now returns
`(None, "high")`, `core/claude.py:241` omits `--model` on a falsy value, and the session
spawns on claude's own default. The stamped template
(`devsteward/templates/.devsteward/config.yaml.tmpl:49-55`) and devsteward's own config were
updated in the same commit; **nothing else was**.

**Found live in `~/projects/recipes`:** `steward validate` spawned the System Tester on Opus.
A sweep of every `.devsteward/config.yaml` under `~/projects` found devsteward itself to be
the **only** repo with the new `claude:` block. Twelve consumers — DriveSteward,
MobileSteward, THermo, Wandthermostat, ai-service, clauder, devsteward-test-lab, docsteward,
flowsteward, hausverwaltung, memzy, recipes — carry `permission_mode` and nothing else. Every
develop, **repair** and **validate** session in all twelve has been spawning on claude's
default since 2026-08-10. The `repair` half is the quieter, costlier one: a cold restart that
was deliberately cheap is now the top model, and no one saw it because nothing said so.

That last clause is the real defect, and it is not the migration. **The engine spawned a
session on a model nobody chose and reported nothing.** REQ-090's contract — "unset means
claude's own default" — is a legitimate behaviour; it becomes a trap only because it is
*silent*. The same silence is what let a hardcoded model string outlive the model itself by
two generations (REQ-090's own Context). A config value that changes what every session costs
must be visible at the moment it is used, not inferable only by reading engine source — which
consumers are explicitly forbidden to do (`[[devsteward-is-a-black-box-to-agents]]`). The
reporter here could see *that* Opus ran and could not see *why*; that asymmetry is the bug.

Scope discipline: the fix is **surfacing plus a one-time migration**, not new config
machinery. `steward sync` refreshes *engine-owned* artifacts (skills, `STEWARD.md`,
`_templates/req.md`); `config.yaml` is consumer-owned — "this file is yours to edit" — and
teaching sync to write it would trade a visible one-time debt for a permanent ownership
ambiguity. A config-schema/version checker is the same trade at larger scale. Both were
considered and rejected at intake (Decision 1).

### The same blind spot, one layer over: the attribution trailer

REQ-090's other half was the commit trailer, and it has the identical shape — *the engine is
the party writing a claim it has no way to make true.* The history:

| | Trailer the engine stamped | Why it was wrong |
|---|---|---|
| pre-REQ-090 | `Co-Authored-By: Claude Opus 4.8 <noreply@anthropic.com>` | Hardcoded, and stale by construction. Sessions driven by other models committed under a model that was not there; the models themselves flagged the trailer they were being asked to write as false. |
| today (`executor.py:63`) | `Co-Authored-By: Claude` | **Worse.** GitHub only parses `Co-authored-by:` when it carries an angle-bracketed address it can resolve to an account, so the bare form is not attribution at all — while still phrasing itself as an authorship claim. |

Three defects are tangled in that line, and REQ-090 only subtracted the third:

1. **The engine does not know who drove the session, but it is the party writing the trailer.**
   Only the session knows. Any string the engine hardcodes ages out. (For a step the engine
   *spawned*, this is now false — see below; that is what makes the fix cheap.)
2. **`Co-Authored-By:` asserts co-authorship, and the assertion is false.** A model holds no
   copyright, signs no CLA, and cannot certify a DCO. Which model name sits in the field does
   not change that.
3. **The email was never meaningful** — it existed only to satisfy GitHub's parser, for an
   account that does not exist.

The ecosystem settled this during 2025-2026, and settled it *against* `Co-authored-by`. The
convention is a **disclosure** trailer, `Assisted-by:`, which takes no email:

- **Linux kernel**, `Documentation/process/coding-assistants.rst` (landed 2025-12-23, out of
  the 2025 Maintainers Summit): `Assisted-by: AGENT_NAME:MODEL_VERSION [TOOL1] [TOOL2]`, e.g.
  `Assisted-by: Claude:claude-3-opus coccinelle sparse`. The same document is explicit that an
  AI agent **MUST NOT** add `Signed-off-by:` — only a human can certify the DCO.
- **OpenTelemetry**: `Assisted-by: Claude Opus 4.5`.
- **LLVM**, **Fedora**: `Assisted-by:` recommended, exact shape left to the contributor.

Disclosure is a claim the engine *can* make truthfully: assistance is an observable fact about
how the commit was produced, unlike authorship. The human stays the sole `Author:`.

**Why this folds into REQ-091 rather than becoming REQ-092.** Defect 1 above is the same
defect this REQ already exists to fix, read at the commit boundary instead of the spawn
boundary — and REQ-091's cure supplies its answer. Once the engine resolves and surfaces the
`(model, effort)` it spawns with, that resolved value *is* an accurate trailer for every
headless step, from the call site this REQ already touches. Filing it separately would mean a
second REQ re-deriving the same resolution, and two sweeps over the same twelve consumers.
REQ-091's develop step had not started when the fold was decided (2026-08-15), so nothing
in-flight is widened.

**The scope beyond the engine's own commits.** `CLAUDE.md` is stamped from
`devsteward/templates/CLAUDE.md.tmpl`, whose house-conventions section currently *mandates*
the `Co-Authored-By: <modelname>` form (line 42-43; DevSteward's own `CLAUDE.md:51-52` is the
same text). Fix only the commit path and every newly stamped project is still born instructing
its sessions to write the retired trailer. FlowSteward has already changed its own `CLAUDE.md`
by hand, ahead of the engine.

## Requirement

### The engine names the model it spawns with

Every Claude session the engine starts — `develop`, `repair`, `validate`, and the guided
interactive bring-up — reports the `(model, effort)` it resolved **before or as** it spawns,
on the progress stream and in the ledger event, in terms a consumer can act on without
reading engine source. When no model is configured, it says *that*, naming the key and the
file (`claude.model` in `.devsteward/config.yaml`) rather than printing a blank or a
plausible-looking default.

"Configured" means resolved from config **or** from the explicit `--model` CLI flag; a flag
override is a deliberate choice and is not warned about.

### An unattended run refuses to spawn a model nobody chose

When a run is headless/unattended and the resolved model is `None`, the engine **refuses to
spawn** and surfaces the fix (the key, the file, and the step kind that was about to run). It
does not fall back to a hardcoded identifier — REQ-090 stands: no model string enters engine
Python, including in an error path's suggestion text, which names the key rather than a value.

An attended invocation with no configured model **warns and proceeds**, preserving REQ-090's
contract for the interactive case.

### The twelve stamped consumers are migrated

The develop session performs the migration itself (it is mechanical, and it is fixable in
place — it does not belong in the fixless System-Test phase, REQ-089). For each consumer repo
listed in Notes: add the template `claude:` block, replacing the stale commented-out
pre-REQ-090 example where present; commit `.devsteward/config.yaml` alone on that repo's
integration branch with a message naming REQ-091 and the engine-generic co-author trailer; do
not push. Leave no repo dirtier than it was found. Skipped repos (Decision 6) are reported by
name with the reason, in the session's closing summary and in this REQ's Notes.

### The engine discloses assistance instead of claiming co-authorship

Every commit the engine writes — the code/checkpoint commit and the ledger commit alike —
carries `Assisted-by: <agent>:<version>` and **no** `Co-Authored-By:` line and **no** email
address. For a step the engine spawned, `<version>` is the model it actually resolved and
passed to that spawn (the same value Decision 1 surfaces — read from that resolution, not
re-derived). No model identifier enters engine Python to produce it: the agent half is a
constant (`Claude`), the version half comes from config or the environment.

For an attended commit (`steward checkpoint` / land invoked from inside a session), the
version comes from `DEVSTEWARD_ASSISTED_BY`, which the session exports. A session's *own*
commits carry the same trailer, naming its own model — which is accurate by construction,
because a session knows what it is.

### Unknown is said out loud, and never blocks

When no identity reaches the engine, the commit is written anyway, with the version stated as
explicitly unknown (`Assisted-by: Claude:unknown`). The engine never emits a bare agent name
with the version silently dropped, and never suppresses the trailer to hide a gap. A commit is
never refused for want of an identity.

### The trailer is one boolean away from off

A project that does not want AI trailers in its history sets a single key in
`.devsteward/config.yaml` (default: trailer on). With it off, engine commits carry no
attribution trailer of any kind — not an empty one, not an `unknown` one. The key, format and
agent name are otherwise fixed; there is no per-project format seam.

### Newly stamped projects are born correct, and existing ones are told

`devsteward/templates/CLAUDE.md.tmpl`'s house-conventions section mandates the `Assisted-by:`
form (with the `Signed-off-by:` prohibition), and DevSteward's own `CLAUDE.md` says the same.
No engine-owned template, doctrine text or handbook page still instructs a session to write
`Co-Authored-By:`. Already-stamped projects are addressed by a migration note (handbook +
this REQ's Notes) stating the old form, the new form, and that it is a one-line house-rules
edit each project makes for itself — **no** consumer `CLAUDE.md` is edited by this REQ.

Every committed config was then re-read **through the engine's own loader** from

resolve to a model in all ten. Two repos are **skipped and reported** per Decision 6:

- **`recipes`** — needed nothing: its interim fix was already committed, and its `.devsteward/`

- **`MobileSteward`** — **not a git repository** (no `.git`). A config edit there could be
  neither reviewed nor reverted, so none was made. It is the one repo still carrying no
  model, and after this REQ its unattended spawns will *refuse* — self-explaining, since the
  refusal names `claude.model` and the file. **Operator action:** add the template block by
  hand, or put the directory under git first.

**A defect the migration itself surfaced, worth recording.** The first pass wrote the template
block into `flowsteward` mechanically and produced a **duplicate `steps:` key** — flowsteward
already had an active `claude.steps:` block (its own `develop: opus/medium`,
`validate: sonnet/medium`) further down the file, below a long comment, which the "does it
already declare a flat `model:`?" check did not see. ruamel then refused to load the file at
all, i.e. the migration briefly broke the repo it was fixing. Caught because the verification
re-parsed every committed config through the real loader instead of trusting the diff; the
commit was reset and flowsteward was migrated **by hand** (`936a1c0`), filling only its two
actual gaps — the flat default and a `repair` override — and leaving its deliberate
develop/validate choices alone. The general lesson, and the reason Decision 4's "identical
block everywhere" needs a caveat: *a config file a consumer owns may already answer the
question you are about to answer for it, in a place a shallow check will not find. Verify by
loading, never by diffing.*

**Not in scope:** a config-schema or config-version checker; teaching `steward sync` to write
`config.yaml`; any change to how `(model, effort)` is *resolved* (REQ-090's precedence —
`claude.steps.<kind>` → flat `claude.model` → unset — stands unchanged); any `steward lint`
rule about attribution (Decision 15); any per-project *format* seam for the trailer
(Decision 12); any edit to a consumer project's `CLAUDE.md` (Decision 13). This REQ adds
visibility, one refusal, an honest trailer, and pays one migration debt.

### Migration note for already-stamped projects

Projects stamped before this REQ carry a house-conventions rule mandating the retired
co-author trailer. Nothing is broken — sessions there keep committing as instructed — but the
form is a false authorship claim with an address for an account that does not exist. To
adopt the current convention, replace that bullet in the project's own `CLAUDE.md` with:

> **Attribution trailer** on commits is a *disclosure*, not an authorship claim:
> `Assisted-by: Claude:<model-id>` naming the model actually driving the session — no email
> address, and never a hardcoded model string. Engine-made commits (`steward checkpoint`)
> carry the model the engine resolved for that spawn, or `Claude:unknown` when the identity
> genuinely did not reach it. The human stays the sole `Author:`. Neither a session nor the
> engine adds `Signed-off-by:` — the DCO is a certification only a human can make.

Sessions that commit by hand export `DEVSTEWARD_ASSISTED_BY` (or write the trailer directly,
which is accurate by construction — a session knows its own model). FlowSteward made this
change by hand ahead of the engine; the other eleven adopt it when they next touch their house
rules. Upstream references: Linux `Documentation/process/coding-assistants.rst` (2025-12-23),
OpenTelemetry, LLVM, Fedora.

**The doctrine this leaves behind:** removing an engine-side default that stamped projects
silently inherited is a *migration*, not a refactor. The same shape would recur for any future
key that moves from code to config — the guard against it is Decision 1's surfacing (the
engine says what it resolved), not a new subsystem.

**And the second doctrine, from the folded-in half:** when the engine must write a claim it
cannot verify, the cure is to *change the claim*, not to blank the field. A bare
`Co-Authored-By: Claude` was the blanked field — it removed the stale part and kept the false
part. `Assisted-by:` works because assistance is an observable fact about how the commit was
produced, and `Claude:unknown` works because a stated gap is information while a silent one is
a trap. Same rule as Decision 1, one layer up.
