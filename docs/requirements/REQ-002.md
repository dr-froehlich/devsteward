## Context

The house format must be machine-readable enough for tools to drive it, yet keep the
prose density that makes a requirement worth reading a year later. The answer is hybrid:
schema-validated YAML frontmatter + a single parseable acceptance block, with the
Context/Decisions/Requirement/Notes prose untouched.

## Decisions

| # | Decision | Rationale |
|---|----------|-----------|
| 1 | YAML frontmatter validated by `req.schema.json` | Make the format a contract, not a convention |
| 2 | One fenced ```yaml acceptance``` block, every AC has `id`+`test` | The verifier can run and track criteria |
| 3 | `status:` inside acceptance is engine-owned | Pass/fail is a fact the engine records, not prose |

## Requirement

A REQ parser reads frontmatter, prose body, and the acceptance block. A linter
schema-validates every REQ, resolves `depends_on`/`supersedes`, detects cycles, checks
index↔REQ status sync, and requires every active/done REQ's acceptance criterion to name
a test.

```yaml acceptance
- id: AC1
  text: parse_req reads frontmatter and the yaml-acceptance block into structured data.
  test: "python -m pytest tests/test_reqfile.py"
  status: pending
- id: AC2
  text: The linter flags schema violations, unresolved deps, cycles, and index drift.
  test: "python -m pytest tests/test_lint.py"
  status: pending
```
