## Context

REQ-058 delegated the engine's budget gate to the sibling tool **clauder** — the provider
shells `clauder gate --threshold T --json` at every step boundary and admits on the
*combined* 5h budget of all accounts. That is the right default, and adopting it let REQ-058
delete DevSteward's hand-rolled per-account cswap machinery. But REQ-058 Decision #5 dropped
something on the way out: the old slot-pin (`--use N`, REQ-025 D6), on the bet that
combined-budget selection supersedes per-account pinning. The Decision flagged its own bet —
"*revisit if slot-pinning is still wanted.*"

It is wanted, for the reason clauder REQ-006 spells out: the combined-budget gate optimises
the shared **5h** pool and is blind to the accounts' **7-day** windows, which reset at
*different* times. 7d budget is use-it-or-lose-it — an account whose 7d window is about to
reset carries remaining budget that simply evaporates if it is not spent first. The operator's
recovery is to **pin** a batch to the about-to-reset account and drain it before the boundary
hits. REQ-058 removed the operator's ability to do that.

The seam was left half-built. `steward advance`/`run` still expose a `--use N` flag and thread
a `use` parameter through `build_executor → build_accounts` — but REQ-058 made
`build_accounts` accept `use` and **silently drop it** (`core/accounts.py` never receives it).
So the flag is a dead control: it parses, it documents "Pin a claude-swap account index", and
it does nothing. clauder has since closed its half (clauder REQ-006, **done**): `clauder gate`
gained an opt-in `--pin N` that judges admission on account N alone — `proceed`/`switch` if N
clears the threshold, `wait` on N's *own* 5h reset otherwise, never falling back to another
account. This REQ reconnects the dead seam to that new clauder capability.

The naming collision REQ-058 noted forces a clean-up, not a workaround. clauder's `--use`
already means *expected burn percent*; DevSteward's `--use` meant *slot index*. Same word, two
meanings, across two tools the same operator drives. Rather than preserve the divergence behind
an internal translation, this REQ **renames** DevSteward's flag to `--pin N` so the word means
the same thing on both command lines. Choosing *which* account to pin (e.g. the soonest-to-reset
one, readable from `clauder usage`'s 7d figures) stays the operator's call — this REQ honours an
operator-supplied index; it does not add a selection strategy.

## Requirement

Reconnect the engine's account-pin seam — dead since REQ-058 — to clauder REQ-006's
`clauder gate --pin N`, and rename the operator flag to `--pin` so it agrees with clauder.

- `ClauderAccountProvider` accepts an optional `pin: int | None` (default `None`). When set,
  every step's gate invocation is `clauder gate --threshold T --pin N --json`; clauder judges
  admission on account N alone and performs any switch to N. When `pin is None`, the invocation
  is the REQ-058 combined-budget gate unchanged (no `--pin` argument is added).
- The verdict handling is unchanged from REQ-058: exit 0 (`proceed`/`switch`) → `ok=True`;
  exit 75 (`wait`, with `wait_seconds`) → interruptible sleep then re-gate; exit 69
  (`unsatisfiable`) → `ok=False`. With a pin, clauder's `wait`/`unsatisfiable` already reflect
  N alone (REQ-006) — DevSteward adds no fallback of its own.
- `steward advance` and `steward run` expose **`--pin N`** (the old `--use` flag is removed),
  threading `pin` through `build_executor → build_accounts → ClauderAccountProvider(pin=N)`.
  All account interaction still routes through the single `clauder gate` chokepoint; the
  provider makes no direct `cswap` call.
- The **handbook** (`devsteward/handbook/_02-engine.qmd`, "Account / quota") documents the
  optional `--pin N`: the per-step gate forwards it as `clauder gate --pin N` to drain a single
  account's 7d window before reset. **STEWARD.md (the agent manual) is unchanged** — the
  operator-facing batch flags are out of its scope (Decision 7).

## Notes

- **clauder readiness — an external prerequisite, tracked in clauder's own ledger.** clauder
  REQ-006 (`gate --pin N`) is **done** and all-regression-validated on its side; this REQ
  consumes that CLI contract as a black-box external tool (the encapsulation principle,
  `[[devsteward-is-a-black-box-to-agents]]`, applied to clauder per `[[clauder-owns-budget-policy]]`).
  clauder is discovered on PATH like before; it is **not** a package dependency, so it is not a
  DevSteward `depends_on` — REQ-006 readiness is a fact, not an edge. The DevSteward edge is
  REQ-058 (which built the provider and dropped the pin this REQ restores).
- **No fallback is clauder's, not DevSteward's.** clauder REQ-006 guarantees a pinned gate never
  switches to or selects a non-N account; DevSteward forwards `--pin N` and trusts that contract.
  The provider adds no compensating logic — it would be the wrong layer (clauder owns budget
  policy).
- **Why regression and no lab.** The wiring is a pure function over an argv: `pin=N` ⇒ `--pin N`,
  `pin=None` ⇒ no flag. clauder honouring the pin is decided by clauder's fixtures; the live
  "drain N before its 7d reset" is the operator's policy (which account, and when), observable
  only through the operator's own multi-account environment, and signed off once already as the
  live gate↔monitor coexistence in REQ-058 AC3. Nothing here needs a real-environment human
  oracle, so there is no `manual` AC and the `process:` block is omitted (fused develop, no
  concept phase).
- **Choosing which account to pin is out of scope (a possible future REQ).** Auto-selecting the
  soonest-to-reset account from `clauder usage`'s 7d figures re-opens REQ-058 Decision #5's
  selection question and would re-introduce usage-reading into DevSteward. This REQ honours an
  operator-supplied index; it adds the knob, not a strategy.
- **`--pin` composes with `--threshold`,** it does not replace it: `--pin` selects the account,
  `--threshold` still gates its headroom (and so does clauder's own `--use` burn-percent, which
  DevSteward does not currently pass — that stays out of scope as in REQ-058).
- **Localization:** developer-facing CLI flag and delegation seam; all English, no localized UI
  strings.
