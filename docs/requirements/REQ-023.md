## Context

Plan [0005-memzy-onboarding](../plans/0005-memzy-onboarding.md) Piece 2 surfaced a destructive
edge in the [[REQ-010]] converter that its own acceptance suite did not catch (the fixtures had
no surrounding prose to lose). `convert_corpus` writes `build_index(...)` over the **entire**
`REQUIREMENTS_INDEX.md`. memzy's index is not just a REQ table — it also carries a **Planned**
table (its `REQ-028s`/`REQ-014a–d` roadmap entries) and a **Scenarios** section. Running the
converter in place, as Piece 2 requires, would silently **discard** those sections.

This is a real safety defect for the in-place migration: a converter that is advertised as
"idempotent and non-destructive" ([[REQ-010]] Decision 7) must not destroy a maintainer's index
prose. [[REQ-010]] preserves *REQ-file* prose byte-for-byte but overwrites the *index* wholesale —
an inconsistency that only bites a real project with a richer index than the fixtures.

The operator chose to **splice** rather than relocate: teach the converter to replace only the
generated REQ-table region of an existing index and leave everything around it untouched. This
keeps the project's own structure intact and makes "run the converter in place" genuinely safe,
rather than pushing a manual "move your Planned/Scenarios elsewhere first" precondition onto
every onboarding.

## Decisions

| # | Decision | Rationale |
|---|----------|-----------|
| 1 | **Splice** the generated REQ table into an existing index, replacing only the table region; preserve all surrounding prose verbatim | Non-destructive in place is the contract [[REQ-010]] Decision 7 already claims for prose; the index must honour it too. Splicing keeps a project's Planned/Scenarios/intro intact without an onboarding precondition |
| 2 | Identify the REQ-table region by the columns the converter emits (the `\| ID \| … \|` rows lint matches), not by section heading text | Heading wording varies per project; the machine-generated table is the only thing the converter owns and may rewrite. Replace exactly that contiguous block (and its header/separator), nothing else |
| 3 | When **no** index exists (or it has no REQ table), emit a whole file as today | Back-compat: greenfield conversion and the existing [[REQ-010]] fixtures (which have no surrounding prose) must behave unchanged. Splice is an addition for the in-place case, not a rewrite of the happy path |
| 4 | **Idempotent and byte-stable** — splicing the same corpus twice leaves the file unchanged, including the preserved prose | A migration step run more than once (by [[REQ-024]]) must converge; the preserved regions must not drift |

## Requirement

The [[REQ-010]] converter, when writing `REQUIREMENTS_INDEX.md`, replaces only the
machine-generated REQ table within an existing index and preserves every other section
verbatim; with no pre-existing index it emits a whole file as before; the operation is
idempotent.

### Behaviour

- Given an existing index containing a REQ table plus other sections (e.g. a Planned table, a
  Scenarios section, intro prose), convert splices fresh REQ rows in place of the old table and
  leaves the other sections **byte-for-byte** unchanged.
- The spliced table's rows remain matched by `lint._index_rows`, with each REQ's status synced
  to its frontmatter.
- With no pre-existing index (or none containing a REQ table), the converter emits a complete
  file exactly as in [[REQ-010]] (existing fixtures stay green).
- A second conversion over the same corpus is a no-op (byte-stable, preserved prose included).

### Out of scope

- Converting the **content** of the Planned table or Scenarios — those stay as living docs
  (plan 0005 scope decision); the splice only protects them from deletion.
- The seeder ([[REQ-022]]) and the onboarding orchestration ([[REQ-024]]).

## Notes

- **Why this is a fix, not a feature.** [[REQ-010]] already promised non-destructive,
  idempotent conversion; the whole-file index overwrite quietly broke that promise for any
  index richer than the fixtures. This closes the gap rather than adding new capability.
- **Unblocks running in place.** With the splice, plan 0005 Piece 2 (`convert_reqs.py
  docs/requirements docs/requirements` over memzy) is safe; without it the operator would have
  to relocate memzy's Planned/Scenarios first — a manual step on every onboarding.
