## Context

The engine's bookkeeping contract is that `.devsteward/state.yaml` and
`.devsteward/events.jsonl` are the cursor and the audit log — but three engine paths end
an operation with those files **dirty in the working tree**, so the repo is not clean at
rest and the audit boundary leaks into whatever happens next:

1. **Post-merge (the named REQ-018 wart).** `_merge_after_land`
   (`devsteward/core/executor.py`) commits the trailing ledger write on the feature
   branch, switches to the integration branch, merges `--no-ff` — then appends the
   `branch_merged` event and returns without committing it. Its own docstring promises
   "the integration branch is clean at rest with an auditable boundary"; it isn't.
   Recorded as a known wart at REQ-018 (2026-06-10); the week of 2026-06-11 produced
   five manual `ledger close — branch_merged event` commits (REQ-030, REQ-031,
   FlowSteward REQ-008/005/001).
2. **Deferred develop close.** A develop step with a validate sibling (`lands=False`,
   REQ-030) commits the work as `develop_committed` — then the trailing ledger write
   (step `done` + event) stays dirty on the feature branch (hand-committed as
   `REQ-031: ledger checkpoint`, 95b01bd).
3. **Red / parked outcomes.** A red validation (or a parked decision) appends the red
   event, the park, and leaves new evidence files uncommitted (hand-committed after
   REQ-031's first validate run, 8186ae6).

Attended, each is a papercut a human notices. Unattended it is a defect with teeth: a
multi-REQ `steward run` proceeds to the next eligible step after a land *or a park*, so
step N+1 creates its feature branch on a dirty tree and step N's ledger writes ride
inside step N+1's commits — mixed provenance, exactly the audit-boundary leak the
`--no-ff` merge discipline exists to prevent. This REQ is the explicit gate before the
first multi-REQ batch night on FlowSteward (plan 0011, step 6 — re-earning batch mode).

Scope decision (Peter, 2026-06-11): fix the **full invariant**, not just the named
wart — every terminal step outcome leaves the ledger (and any evidence files) committed.

## Decisions

| # | Decision | Rationale |
|---|----------|-----------|
| 1 | The invariant: **after any terminal step outcome — green land+merge, deferred develop close, red validation, parked decision — the working tree is clean**; ledger writes and evidence files are committed before the executor returns or proceeds. | The batch loop's safety property; partial fixes (this week's hand commits) demonstrably don't hold the line. |
| 2 | The post-merge `branch_merged` event is committed as its own follow-up commit on the integration branch (message shape `REQ-NNN: ledger close — branch_merged event`), matching the five hand-made precedents — never by amending the merge commit. | Amending would change the hash the just-recorded events point at (the standing reinterpret-never-rewrite rule); the follow-up commit is the proven, auditable shape. |
| 3 | Park/red commits ride the step's own branch context: on the feature branch when one exists, else the integration branch — using the existing engine committer (which already refuses the production branch). | The ledger is declaration and lives where the engine already commits; no new branch semantics. |
| 4 | No empty commits: paths that have nothing to commit (e.g. a land that never branched, a refused/ineligible step that wrote nothing) commit nothing. | Noise-free history; the invariant is "clean tree", not "a commit per event". |
| 5 | Out of scope: reworking the event model, squashing ledger writes into the land/merge commits, auto-committing *user* edits left in the tree (a dirty tree from non-engine files still fails loudly where it does today). | Keep the fix at the committer seam; foreign dirt is a human question, not the engine's to absorb. |

## Requirement

After any engine-driven step reaches a terminal outcome — mechanical land with `--no-ff`
merge, deferred develop close (`develop_committed`), red validation, or a parked
decision — `git status` on the active branch is clean: every `state.yaml`/`events.jsonl`
write and every captured evidence file is committed, with the post-merge `branch_merged`
event in its own follow-up commit on the integration branch, and no empty commits on
paths that wrote nothing.

## Notes

- All criteria are honest `regression`: the oracle is real git state in fixture repos
  (the `test_branch_lifecycle.py` / `FakeRunner` + real-git pattern), decoupled from no
  external system — no lab, no System-Test phase.
- The five hand-made commits this week are the postmortem evidence; their message shapes
  (`ledger checkpoint`, `ledger close — branch_merged event`) are the de-facto contract
  Decision 2 codifies.
