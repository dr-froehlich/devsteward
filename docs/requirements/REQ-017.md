## Context

**THermo is the live trigger.** A `/onboard ../THermo` run on 2026-08-01 stopped at §1 without
touching the target: THermo (an ESP32-S3 room-climate firmware, branches `main`/`dev`) holds its
12 requirements in the legacy **prose** dialect — a `### REQ-NNN: Title` header followed by a flat
bullet list — and `scripts/convert_reqs.py` is a *frontmatter* dialect normalizer whose
`convert_req_text` raises `missing YAML frontmatter` on the first file and every one after it.
The onboarding cannot proceed until a prose front-end exists. This REQ is that front-end.

It preserves the original REQ-010 intent that the memzy work superseded in practice but not in
need. When REQ-010 was drafted it assumed legacy projects held REQs in prose; memzy turned out to
have crossed the frontmatter threshold on its own, so REQ-010 narrowed to a dialect normalizer and
the prose parser was split out here as a backlog draft — held for **ExamEngineer**, which is still
mid-upscale and still not the right first prose retrofit. THermo arrived first. The REQ is
therefore retargeted from one repo to the **dialect**: it is built and proven against THermo's
corpus, and ExamEngineer becomes its second known consumer if and when its upscale concludes.

**The input is regular, and that is the load-bearing fact.** A field census over THermo's corpus
shows all 12 REQs carry exactly the same 8 field bullets — 12/12 for each of `- **Status:**`,
`- **Added:**`, `- **Completed:**`, `- **Verified by:**`, `- **Depends on:**`,
`- **Description:**`, `- **Acceptance criteria:**`, `- **Notes:**` — with no ragged cases. This is
a **parser**, not a heuristic salvage job, which is why the acceptance criteria below can be
written honestly at intake and no concept phase is warranted.

Three concrete hazards the census also surfaced, each answered by a decision below:

- **Look-alike bullets in the body.** The Description prose contains its own bold bullets
  (`- **MAC address**`, `` - **`FactoryReset()`** — delete … ``). A parser that matches "bold
  text at the start of a bullet" would eat them. Only the eight known field names, at top level,
  are fields.
- **Title drift between the header and the index.** Two of twelve already disagree: REQ-002 is
  "Message and MessageQueue (thread-safe)" in the file but "Message & MessageQueue (thread-safe)"
  in the index; REQ-011 is "Python CLI tool for device deployment and maintenance" in the file
  but "Python CLI tool (thermoctl)" in the index. Conversion regenerates every index row from
  frontmatter, so exactly one of the two survives.
- **A template stub in the corpus.** `REQ-xxx.md` is a copyable template, not a REQ.
  `reqfile.load_reqs` already skips it by name; `convert_corpus`'s `REQ-*.md` glob does not.

## Decisions

| # | Decision | Rationale |
|---|----------|-----------|
| 1 | Build a **prose front-end** on top of REQ-010's core, not a parallel converter | The normalization, faithful-verdict and index rules are identical once frontmatter exists; only the parse step differs. Carried over from the original draft |
| 2 | Inherit REQ-010's **archivist** stance | `[x]` → `passed`, `[ ]` → `pending`, criterion text verbatim. A format migration records the source's verdict; it never re-adjudicates another project's governance |
| 3 | Ship as a **second script**, `scripts/convert_reqs_prose.py`, importing the core from `convert_reqs.py` | Literally REQ-010 Decision 6's "a converter per project, shared core", and the reuse seam it named is a `scripts/`-level seam. Leaves the memzy script — which has already run on a live corpus — byte-untouched, so this REQ carries zero regression risk to it. Rejected: sniffing the dialect inside one script (can guess wrong silently) and a `--dialect` flag (same edit to a proven tool, plus a flag to get right) |
| 4 | **Light restructure** into `##` sections: Description prose → `## Requirement`, the checkbox list → `## Acceptance criteria` + the yaml block, Notes → `## Notes` | The output reads like a native REQ instead of a foreign dialect the project keeps forever, and it lands the acceptance block exactly where REQ-010's `_convert_acceptance` anchor (`^## Acceptance criteria`) already looks — so the core is reused rather than special-cased. Every `####` sub-heading and every word of prose rides through verbatim inside its new section |
| 5 | The **REQ file's header title wins** over the index row's, and every conflict is **reported** | The REQ file is primary and the index is its generated mirror — the same direction `splice_index` already resolves for memzy. Reporting rather than silently overwriting lets the operator rescue a case where the index genuinely had the better wording (REQ-011's "(thermoctl)" arguably does) |
| 6 | An unparseable file **aborts the whole run**; nothing is written | The corpus converts as one transaction, so there is no half-converted directory whose index disagrees with its files and no window in which `steward lint` is red. Rejected: skip-and-continue, which produces exactly that window |
| 7 | Known-benign input is handled **by name, not by tolerance**: `REQ-xxx` is skipped (the `load_reqs` rule), `–`/`-`/empty maps to `null` / `[]`, and the status vocabulary is a fixed table (`DONE`→`done`, `OPEN`→`open`, `IN_PROGRESS`→`in-progress`) | "Confidently parse or report" (the original draft's sketch) means an *enumerated* mapping. An unrecognized status token is an abort, never a guess — the alternative is a REQ silently imported under a status nobody chose |
| 8 | **Two oracles**: `steward lint` for validity, committed goldens for fidelity | They disconfirm different failures. `steward lint` predates this converter and knows nothing about it — a genuinely decoupled oracle — but only proves the output is *schema-valid*. Goldens prove REQ-012's 122 lines of prose survived byte-for-byte, but are authored alongside the converter and can only confirm what the author already believed. Neither alone is sufficient |
| 9 | Fixtures are **all 12 real THermo REQs**, captured verbatim; the suite never reads a THermo checkout | The corpus-shaped risk *is* the real corpus, so copying it wholesale captures that risk hermetically — the live-proof screen (§2a) is satisfied without coupling this REQ's green to another repo's state |

## Requirement

A standalone prose converter that reads a legacy prose-header requirement corpus and emits
DevSteward-schema-valid REQ files plus a synchronized index, **preserving every verdict and all
prose**, by parsing the headers into frontmatter and then handing off to REQ-010's normalization
core.

### The prose grammar it parses

One REQ file is:

```
### REQ-NNN: <title>

- **Status:** DONE
- **Added:** 2026-04-07
- **Completed:** 2026-04-07
- **Verified by:** flash + monitor on Rev B hardware 2026-04-07 — …
- **Depends on:** REQ-001, REQ-002        (or `–`)
- **Description:**

  <prose, may contain #### sub-headings, tables, fenced code and its own bold bullets>

- **Acceptance criteria:**
  - [x] <criterion>
  - [ ] <criterion>
- **Notes:**
  <prose>
```

Only the **eight known field names**, matched at top level, are fields; a bold bullet anywhere
else is body prose and is preserved (Decision 1 hazard list). The header line supplies `id` and
`title`.

### Output shape

Frontmatter in the canonical field order REQ-010's `dump_frontmatter` already emits — `id`,
`title`, `status` (mapped per Decision 7), `kind` (inferred by the existing `infer_kind`), `added`,
`completed`, `verified_by`, `depends_on`, `concept_refs: []`, `scenario_refs: []`,
`supersedes: null`, `tags: []` — followed by the body restructured per Decision 4. The
`### REQ-NNN: <title>` header line is **preserved** at the top of the body rather than deleted;
the source is never silently shortened.

The index is spliced by REQ-010's existing `splice_index`, so surrounding prose (THermo's
dependency graph and implementation-order sections) survives untouched and only the REQ table is
regenerated.

### Reuse boundary

`convert_reqs_prose.py` owns the **parse** step and nothing else. `normalize_frontmatter`,
`infer_kind`, `dump_frontmatter`, `parse_acceptance_checkboxes`, `transcode_acceptance_block`,
`splice_index` and `build_index` are imported from `convert_reqs.py` and are **not** duplicated,
reimplemented or modified. If a shared function needs a behaviour change, that is a change to
REQ-010's tool and must keep its own tests green.

### Out of scope

- **Running the converter on THermo's live repo.** This REQ ships the tool + fixtures; the
  retrofit is a separate act (see Notes).
- **Scenario (`SCN-*`) conversion**, `ROADMAP.md`, or any non-REQ doc — the same boundary
  REQ-010 drew.
- **Re-adjudicating any imported verdict** (Decision 2), including THermo's REQ-011/REQ-012,
  whose code has shipped but whose acceptance boxes are unchecked.
- **Modifying `scripts/convert_reqs.py`** beyond importing from it (Decision 3).

## Notes

**Where the live retrofit lives.** This REQ deliberately stops at the tool, mirroring the
REQ-010 → REQ-062 split (converter proven on fixtures; live run tracked separately). THermo's
actual migration is the follow-on act — either a tracked proof REQ or a plain operator
`/onboard ../THermo` run once this lands. Its four parameters are **already decided** (operator,
2026-08-01) and must not be re-interviewed: doc paths stay at `doc/requirements`,
`doc/requirements/REQUIREMENTS_INDEX.md`, `doc/plans`, `doc/concepts` (`doc/`, singular — it is
not a generated tree); REQ-011/REQ-012 are carried as-is and stay active, so §2's gate reads "no
*terminal* REQ has an active step" rather than a globally empty queue; and CLAUDE.md's drifted
Phase-5 status table is subtracted in favour of a pointer, per the one-source-of-status rule.

**A known cosmetic wart, recorded rather than hidden.** Decision 4 preserves the
`### REQ-NNN: <title>` header above the generated `##` sections, so converted files carry a
level-3 heading above level-2 ones. It is deliberate — fidelity over tidiness — and harmless to
every consumer (lint, the parser and the gates all read frontmatter and the acceptance block, not
heading depth). Deleting the header line instead is a one-line change to the writer if the
hierarchy ever grates.

Converted output has no `## Context` or `## Decisions` section, because the prose dialect has no
field that maps to either — the converter does not invent sections it has no source for. A
maintainer can add them by hand afterwards; that is authoring, not migration.

All eight criteria are `check: regression` and fully hermetic: the fixtures are captured files and
the oracles are `steward lint` plus committed goldens, so no service, secret, network or THermo
checkout is required (the §2b environment-bound screen is clean). Per REQ-068 every command is
authored as `python -m pytest …`.

`process:` is omitted — every value is the default (`develop: fused`, `concept: false`,
`lab: []`). No concept phase: the input format is fully enumerable (12/12 on every field bullet),
the gaps are named above, and the oracle already exists, so there is no risk to buy down and the
acceptance criteria are writable today.
