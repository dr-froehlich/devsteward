## Context

A live FlowSteward validation crashed `steward validate` on a **green** land: the
`git merge --no-ff` of the feature branch into `dev` hit an unresolvable conflict in
`.devsteward/events.jsonl` + `.devsteward/state.yaml`, the engine raised an uncaught
`CalledProcessError`, and the repo was left **split** — HEAD on `dev`, the fix stranded on
the feature branch, the ledger and cursor divergent, no `steward` verb able to complete or
undo it. The same crash had fired a cycle earlier on **red**. This is the failure a
production tool must not have.

Root cause is **plane confusion**, not the merge itself. The ledger (an append-only serial
log plus a cursor) currently *rides the feature branch* during develop/validate and is
carried home by the feature→`dev` merge. The moment `dev` and the feature branch have each
appended to the ledger since the branch was cut — **guaranteed** in a deferred-validate
world (REQ-030 D6, REQ-034: `dev` keeps advancing while a validation parks) — git faces two
independent histories of the same append-only file and cannot auto-merge them. The merge
conflicts; the unguarded `check=True` subprocess turns that into a crash.

Plan 0021 already named this and moved the **park** path's registry delta onto `dev`
(REQ-034 findings 60/70/80), but explicitly assumed *"the green path is fine — it converges
via the `--no-ff` merge."* The live crash disproves that assumption: the green path
conflicts too. The deeper truth is that the ledger has the **same nature as the
declaration** — serial, global, single-writer, registry — and the house rule already says
*the ledger lives on `dev`*. The implementation simply never honored it for the
code-carrying paths. This REQ finishes the job for **all** paths and makes the topology
operations that move code between branches **atomic and recoverable** so a residual surprise
is surfaced, never crashed into.

## Decisions

| # | Decision | Rationale |
|---|----------|-----------|
| 1 | **The ledger is written only on the integration branch (`dev`); a feature branch never carries a `.devsteward/` commit.** The engine records ledger events on `dev` (via a dedicated `dev` **git worktree**, or git plumbing — `commit-tree`/`update-ref` — to avoid switching the feature working tree) while the feature branch holds only code. Finishes plan 0021 for *all* paths, not just the park. | The ledger is a serial cursor; its single correct home is the one serialization point (`dev`). With the ledger off feature branches, a feature→`dev` merge *cannot* conflict on `.devsteward/` — there is nothing there to collide. This dissolves the crash class at the root. **Rejected:** a `merge=union` driver for `events.jsonl` — it silences git on the append-only log but mis-merges the cursor (`state.yaml`) and re-introduces the REQ-027 green-but-hollow risk ("git stopped complaining" ≠ correct). |
| 2 | **Every topology mutation is atomic and recoverable.** Merge / reconcile / switch: `fetch` first, detect divergence, attempt; on any residual conflict `git merge --abort` to leave the repo *exactly* as before (same HEAD, clean tree, intact ledger), then surface a precise, actionable recovery instruction and — when `DEVSTEWARD_UNATTENDED=1` — park a decision. Never raise an uncaught exception that strands the repo mid-merge. | A production tool must fail all-or-nothing with a recovery surface, not into an unrecoverable split. `fetch`-first also makes "behind remote" a *handled* case rather than a crash — required once a deploy host commits live fixes through the remote (REQ-038). |
| 3 | **The no-ledger-on-feature invariant is guarded.** The engine refuses to commit `.devsteward/` changes while HEAD is a feature branch, and `steward lint` flags a feature branch whose diff against `dev` touches the ledger dir. | A silently re-introduced ledger-on-branch commit is exactly what shipped green before (FakeGitTopology never reverted `.devsteward/` on a switch). A guard turns a regression of this design into a loud, early failure. |

## Requirement

Make the ledger a `dev`-only artifact and the branch-moving operations crash-proof:

- The engine records all ledger writes (events + cursor) on the integration branch, never
  on a feature branch — the deferred-develop close, the validation event, the park, the
  green-land checkpoint, and the `branch_merged` event all land on `dev`. A feature branch
  carries only implementation code and acceptance tests.
- A feature→`dev` merge therefore touches no `.devsteward/` path and cannot conflict on it.
- Merge, reconcile, and switch are wrapped so that a conflict or a behind-remote feature ref
  is detected, the operation is either fast-forwarded/incorporated or cleanly aborted, and
  the outcome is a surfaced recovery instruction (attended) or a parked decision
  (unattended) — never an uncaught subprocess error.
- The engine guards the invariant (no ledger commit on a feature branch) at write time, and
  `steward lint` reports a violation statically.

## Notes

- **Real-git teeth (the plan 0021 lesson):** all ACs run against a real `git init` repo with
  the real `GitCli`; only `claude -p` and the interactive bring-up are faked. The
  `FakeGitTopology` that kept one in-memory ledger and never reverted `.devsteward/` on a
  switch is exactly what hid this bug — a unit fake cannot certify "which branch did the
  ledger land on."
- **Relationship to REQ-034:** this completes the plan 0021 rework REQ-034 began. REQ-034's
  develop fixes (the park-records-on-dev half) stay; this generalizes the same principle to
  the green/code-carrying paths and adds the atomic-merge floor. REQ-034's own re-validation
  (its `manual` AC6) is the **real-world witness** that the land no longer crashes, and is
  scheduled after this REQ lands.
- **Out of scope:** the cross-host deploy channel (Finding 90) — that is **REQ-038**, which
  depends on this REQ (a deploy host committing live fixes through the remote relies on both
  the pure-code feature branch and fetch-first atomic merges). Choice of mechanism for the
  `dev`-only write (worktree vs. plumbing) is a develop-time decision; Decision 1 leans
  worktree.
- **Process declarations:** defaults — fused develop, no concept phase. **No devsteward lab**
  (`lab: []`): ACs run on synthetic real-git repos in a temp dir; the live witness re-uses
  REQ-034 / FlowSteward (consumer-repo reality, the REQ-030 AC8 precedent).
- **Localization:** engine/CLI text is technical English; no user-facing localized strings.
