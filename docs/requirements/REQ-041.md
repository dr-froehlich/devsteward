## Context

REQ-040 Decision 1 declared that *"every read resolves the live integration-branch ledger
from anywhere — including a feature branch"* and added the `Executor.live_ledger()` binding
accessor. But the **implementation only routed `steward status`** through it. The remaining
read-side call sites in `cli.py` were left reading the unbound `ex.ledger`, which on a
feature branch is the stale branch-cut snapshot:

- `steward validate REQ-NNN` — the develop-done **pre-flight** (`ex.ledger.status_of(...)`).
- `steward checkpoint` with no argument — the cursor read (`ex.ledger.cursor_step`).
- the checkpoint/validate **report** — `Cursor:` and parked-decisions lines.

The live symptom (2026-06-15 dogfood): `steward checkpoint REQ-036 develop` reported
*done* (it binds), then `steward validate REQ-036`, run seconds later in the same tree,
failed with *"REQ-036:develop is not closed yet"* — because the validate pre-flight read the
feature branch's local `.devsteward/state.yaml`, which has no `REQ-036:develop` entry, while
checkpoint had read/written the live `dev` ledger where it is done. Same `ex.ledger`
attribute, two different physical ledgers. This is REQ-040 Decision 1 left half-applied; it
is the exact orientation footgun REQ-040 set out to close, on a surface REQ-040 missed.

## Decisions

| # | Decision | Rationale |
|---|----------|-----------|
| 1 | **Route every read-side ledger access through `live_ledger()`** — `validate`'s pre-flight, the no-arg `checkpoint` cursor read, and the report's `Cursor:`/decisions lines — so a read resolves the live integration-branch ledger from any branch, exactly as `status` already does. | Completes REQ-040 Decision 1. An unbound read on a feature branch returns the stale branch-cut snapshot; the live cursor/status must be branch-agnostic or orientation is unreliable. |
| 2 | **Lock it with a real-git regression test that drives `steward validate` from a feature branch** whose snapshot is genuinely stale (develop done on the integration branch, absent from the feature snapshot), asserting the pre-flight passes the live ledger — *not* the "is not closed yet" stale-read error. | A unit fake with one in-memory ledger cannot certify *which branch's* ledger the read resolved — the precise gap that hid both this and the REQ-040 bug. The test is what makes the fix hold "for good." |

## Requirement

Make the engine's read path branch-agnostic on **all** user-facing read surfaces, not just
`steward status`:

- `steward validate REQ-NNN`'s develop-done pre-flight resolves the live
  integration-branch ledger, so from a feature branch a develop step that is `done` on the
  integration branch is seen as done (no false "is not closed yet").
- `steward checkpoint` with no REQ argument resolves the cursor from the live ledger.
- The checkpoint/validate report's `Cursor:` and parked-decision lines read the live ledger.

## Notes

- **Real-git teeth (REQ-037/REQ-040 lesson):** the AC runs against a real `git init` repo
  with the real `GitCli` and a real integration worktree; only `claude` and the interactive
  guided bring-up are faked. The bring-up is short-circuited by forcing the
  `in_claude_session` guard true, so the assertion isolates the pre-flight read: with the
  bug the command exits on "is not closed yet"; with the fix it gets past the pre-flight to
  the (now-reached) in-Claude refusal.
- **Out of scope:** the REQ-037 write topology (correct) and the REQ-040 idempotency guard
  (correct); no output-format changes beyond making the reads live.
- **Process declarations:** defaults — fused develop, no concept phase, **no lab**
  (`lab: []`): the AC runs on a synthetic real-git repo in a temp dir, reproducible
  headless, so there is **no validate phase**.
- **Localization:** engine/CLI text is technical English; no user-facing localized strings.
