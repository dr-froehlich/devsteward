## Context

The guarantee that keeps automation honest: a step reaches `done` only after the engine
itself re-runs the REQ's named acceptance tests and sees them green. A model claiming
success cannot advance the ledger past a red test.

## Decisions

| # | Decision | Rationale |
|---|----------|-----------|
| 1 | Verifier runs each acceptance `test:` as a shell command; all must exit 0 | Language-agnostic, matches how tests really run |
| 2 | No declared test ⇒ documented marker-trust fallback | Don't block steps that legitimately have none |
| 3 | Verify result logged to `events.jsonl` | Auditable proof of why a step is done |

## Requirement

`CommandVerifier` runs a step's `verify` commands and returns pass/fail. A failed verify
marks the step FAILED (not DONE) and stops the unattended run.

```yaml acceptance
- id: AC1
  text: A step whose acceptance test fails is marked failed and never reaches done.
  test: "python -m pytest tests/test_executor.py::test_verify_failure_blocks_done"
  status: pending
- id: AC2
  text: A step whose acceptance test passes is committed and advanced to done.
  test: "python -m pytest tests/test_executor.py::test_run_step_done_path"
  status: pending
```

## Notes

Verification is engine-owned by design — see REQ-001 decision 3.
