## Context

FlowSteward filed a bug from the consumer side: every `steward checkpoint` landing writes
`Co-Authored-By: Claude Opus 4.8 <noreply@anthropic.com>`, regardless of what is actually
driving the session. Five consecutive engine commits across REQ-144…REQ-148 carried that
string; a hand-made commit in the *same* Opus 5 session recorded the live model correctly.
That contrast is the load-bearing evidence — it rules out "the session really was 4.8" and
localizes the defect to the engine.

The report correctly ruled out consumer config (`.devsteward/config.yaml` had both `model:`
lines commented out) and stopped at the boundary, per the black-box rule
(`[[devsteward-is-a-black-box-to-agents]]`). Diagnosis from inside:

**Root cause — `devsteward/core/executor.py:58`:**

```python
_TRAILER = "Co-Authored-By: Claude Opus 4.8 <noreply@anthropic.com>"
```

A module constant, consumed at `executor.py:951` (the whole-tree code commit) and
`executor.py:996` (the trailing ledger commit). Nothing reads config; the `claude.model`
keys the reporter ruled out feed `claude -p --model` only and never touched the trailer.
Systematic on every engine-made commit, as reported.

**Three things invisible from outside the boundary:**

1. **The engine cannot learn an attended session's model.** A `steward checkpoint` invoked
   from inside a Claude session is a subprocess whose environment carries `CLAUDECODE=1`,
   `CLAUDE_CODE_SESSION_ID`, `CLAUDE_EFFORT`, `AI_AGENT` — and **no model variable**. So
   "name the model actually driving the session" is not a fix the engine can implement at
   all; only the session itself knows. Any design that has the engine emit a model string
   is either a hardcode (this defect), a config value that ages, or a self-report the
   session can forget. The only honest engine trailer is one with no model in it.

2. **DevSteward stamps the hardcoded convention.** `devsteward/templates/CLAUDE.md.tmpl:42`
   and DevSteward's own `CLAUDE.md:51` both literally read
   `Co-Authored-By: Claude Opus 4.8 <noreply@anthropic.com>`. FlowSteward's
   `CLAUDE.md:52-54` ("never a hardcoded stale model string") is a *local divergence* from
   the template. The engine was not violating the convention DevSteward ships — it was
   matching it. This REQ therefore fixes the convention, not just the code.

3. **The spawn path pins a model too — and it is not vestigial.** *(Corrected during the
   develop phase; the intake draft named the wrong site and called it harmless.)* The
   binding pins are in `devsteward/config.py`: `Config.model` returns
   `.get("model", "claude-opus-4-8")`, and `STEP_CLAUDE_DEFAULTS` pins
   `repair: claude-sonnet-4-6` and `validate: claude-sonnet-5`. `Config.step_claude()` ends
   with `merged.get("model") or self.model`, so it **always** resolves to a concrete string
   and `--model` is **always** passed. Consumers whose config sets no model — which is all
   of them — have therefore genuinely been running headless sessions on an obsolete model,
   not merely committing a stale trailer. `claude.py`'s `DEFAULT_MODEL` and the
   `cli.py:607`/`cli.py:1043` help text are the cosmetic instances of the same mistake.

   The **asymmetry** this creates is the deeper defect: a project could override the model
   **per step kind** via `claude.steps.<kind>`, but the **global** default was invisible —
   hardcoded in Python and only a commented example in the stamped config. Being able to
   override a default one cannot see, and cannot set, is backwards.

The reporter's unverified lead about other provenance sinks is **partly real and narrower
than feared**: `.devsteward/events.jsonl` records a `"model"` field in exactly one event
type, `repair_started`, and that one is *accurate* because it names the model the engine
itself spawned. Checkpoint and validation events record `driver` and no model. There is no
single stale source feeding everything — there is one hardcoded trailer constant plus a
stale spawn default, which is why both are fixed here.

The unifying rule, in the owner's words: **the code should be generic and not mention any
specific model, or we would need to sync our code with Anthropic's release schedule.**
Model identifiers belong in `.devsteward/config.yaml`, which the consumer owns and edits.

Out of scope by design: rewriting the already-landed misattributed commits in any consumer
repo — that is history rewriting on someone else's `dev` and is that project's call.

## Decisions

| # | Decision | Rationale |
|---|----------|-----------|
| 1 | The engine's trailer names **no model**: `Co-Authored-By: Claude`. | The engine genuinely cannot know what drives an attended session (no model env var exists). Every alternative — hardcode, config value, session self-report, reading Claude Code's private transcript — either ages or can lie. Subtraction removes the failure mode instead of maintaining it. |
| 2 | The trailer carries **no email address**. | `noreply@anthropic.com` routes nowhere and never did. Accepted cost, weighed explicitly: GitHub parses `Name <email>` for co-author attribution, so DevSteward-driven commits will no longer render a co-author badge and strict trailer parsers see a malformed trailer. The owner chose honesty over the badge. |
| 3 | The **convention stays in CLAUDE.md**; only the specific model leaves it. | Removing the bullet entirely would leave sessions with no stated rule. Keeping it with a `<modelname>` placeholder gives the rule a home that cannot go stale, because no concrete model is written down. |
| 4 | Hand-made (session) commits **do** name the model; engine commits do not. | This is not an inconsistency, it is the principle: whoever knows the model states it. A session knows its own model, so its trailer is accurate by construction and can never be stale — that is precisely what produced the one correct row (`e80f021`) in the bug report. The engine does not know, so it stays silent rather than guessing. |
| 5 | Every model identifier is **deleted from Python**, not bumped — `DEFAULT_MODEL`, `Config.model`'s fallback, and `STEP_CLAUDE_DEFAULTS`' per-step pins. | Bumping `claude-opus-4-8` → `claude-opus-5` would fix today and re-create the same ageing class tomorrow. In the owner's words: *the code should be generic and not mention any specific model, or we would need to sync our code with Anthropic's release schedule.* |
| 6 | The stamped `.devsteward/config.yaml` ships an **active** `claude.model` **and** an active `claude.steps` block. | A model must be nameable somewhere; config is where it belongs, because the consumer owns and edits that file. Shipping *both* levels visibly is what fixes the asymmetry — the per-step policy (REQ-029 D4 / REQ-030 D2: a cold repair restart and the System Tester's procedure-following don't need the top model) survives as configuration instead of as a Python constant. It ages, but in the consumer's file, which is theirs to change. |
| 7 | Existing consumers are **not** retrofitted, and no CLAUDE.md drift check is added. | `CLAUDE.md` is stamped once at `steward new` and project-owned thereafter; the engine never rewrites it. A drift check would fight that ownership. The template change reaches new projects; existing projects change theirs when they choose. |
| 8 | Acceptance is a **repo-wide scan**, not a line-58 assertion. | A test pinned to the one call site would pass while a new commit path, the template, or the handbook reintroduced a model string. The scan is the root-fix shape for a defect whose essence is "a model identifier appeared in a place that cannot maintain it". |
| 9 | No concept phase; `develop: fused`; no lab. | The acceptance criteria are fully writable at intake and every oracle is static or a real git commit in a temp repo. Nothing here needs risk buy-down or a lab asset. |

## Requirement

### The trailer

Engine-made commits — both the whole-tree code commit and the trailing ledger commit —
carry exactly:

```
Co-Authored-By: Claude
```

No model identifier, no email address. This applies to every commit the engine authors:
`steward checkpoint`, `steward advance`, `steward run`, and the ledger-close commit.

### Model identifiers leave engine source

No file under `devsteward/` (Python source, templates, handbook) contains a concrete Claude
model identifier, with the single exception of `devsteward/templates/.devsteward/config.yaml.tmpl`,
which is consumer-owned configuration. Concretely:

- `DEFAULT_MODEL` is removed from `devsteward/core/claude.py`; `run_claude`'s `model`
  parameter defaults to `None` (falsy → the `--model` flag is omitted, which is the
  existing documented behaviour).
- `devsteward/config.py` carries **no** model: `STEP_CLAUDE_DEFAULTS` is deleted (the
  `claude.steps.<kind>` seam remains, reading config only), the `Config.claude` default dict
  drops its `model` key, and `Config.model` returns `str | None` — the configured value or
  `None`, never a literal.
- `--model` help text in `devsteward/cli.py` no longer advertises a specific model.
- `devsteward/templates/CLAUDE.md.tmpl` states the convention without naming a model, in
  the placeholder form `Co-Authored-By: <modelname>` — and DevSteward's own `CLAUDE.md`
  says the same thing.
- `config.yaml.tmpl` is exempt because that file *is* the config — naming models there is
  the answer to this REQ, not an exception to it.
- The handbook's "defaults Opus-high, repair Sonnet" statements become false once the values
  live in config, and are restated in terms of the config keys.

`DEFAULT_EFFORT` is unaffected — an effort level is not a model identifier and does not age.

### The spawn model moves to config

The stamped `.devsteward/config.yaml` ships an **active** (uncommented) `claude.model` key
naming a current model, **and** an active `claude.steps` block carrying the per-step
overrides, alongside `permission_mode`. Both levels are visible in the one file the consumer
owns — a project can now set the global default it was previously only able to override.
DevSteward's own `.devsteward/config.yaml` is updated the same way, since it dogfoods the
stamp.

A project whose `claude.model` is absent or empty spawns with **no** `--model` flag, so
`claude`'s own default applies. This is a **behaviour change**, not the status quo: the same
project previously inherited a model hardcoded in `config.py`. It is the honest meaning of
"unset", and it can never go stale.

### Frozen artifacts are exempt

`.devsteward/evidence/**` holds captured, hash-recorded validation artifacts (e.g.
`REQ-057/*/CLAUDE.stamped.md`, which contains the old trailer text by design). These are
frozen evidence of what was true at capture time and are never rewritten — the scan must
exclude them, or it would demand the falsification of recorded evidence.

```yaml acceptance

  text: >
    No `Co-Authored-By:` trailer anywhere in the repository's live source, templates,
    handbook, docs or root CLAUDE.md names a Claude model identifier or carries an email

    placeholder form `Co-Authored-By: <modelname>`. The scan excludes `.devsteward/evidence/**`
    (frozen captured artifacts) and `.git/**`. A model token (Opus/Sonnet/Haiku/Fable or a
    `claude-*-N` id) or an `@` address on a trailer line fails the test, wherever it appears —
```

## Notes

- **Reported by** FlowSteward (`/home/peter/projects/flowsteward`), commits `15bdbd6`,
  `40b95b7`, `4cc1e92`, `3a1e456`, `aac6b64` (engine, all wrong) against `e80f021` (hand,
  correct) across REQ-144…REQ-148.

- **Already-landed misattributed commits are left alone**, in every repo including this
  one. Correcting them means rewriting `dev` history in a consuming project; that is the
  consuming project's decision, not the engine's.

- **FlowSteward's CLAUDE.md becomes wrong when this lands.** Its lines 52-54 currently
  demand "the model actually driving the session … never a hardcoded stale model string",
  which under Decision 1 is unsatisfiable for engine commits. Resolving that is
  FlowSteward's own commit — the engine does not reach into consumer repos (Decision 7).
  The same applies to memzy, THermo, ExamEngineer and DocSteward, which carry the old
  stamped bullet verbatim.

- **The GitHub co-author badge is knowingly given up** (Decision 2). If it is ever wanted
  back, the minimal change is a synthetic non-Anthropic address such as
  `<claude@localhost>` — recorded here so the option is not rediscovered from scratch.

- **`repair_started` keeps its `model` field** in `events.jsonl`. It is accurate (the
  engine spawned that model) and is the one place engine-side model provenance is honestly
  recordable. No new provenance machinery is added; the reporter's lead is answered by
  this note rather than by code.

- **Consumers see a spawn-model change the moment this lands.** FlowSteward, memzy, THermo,
  ExamEngineer and DocSteward all leave `claude.model` unset and share one pipx engine, so
  their headless runs move from the (obsolete) hardcoded models to `claude`'s own default,
  without them editing anything. That is an improvement and the honest reading of an unset
  key — but it is visible, so it is recorded here rather than discovered. Any project that
  wants a specific model adds one line to its `.devsteward/config.yaml`; the stamped
  template shows the shape.

- **Not a follow-on, deliberately:** there is no remaining known defect in this area. The
  spawn model and the convention text are both fixed here rather than deferred, at the
  owner's direction.
