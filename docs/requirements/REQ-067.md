## Context

DevSteward's concept phase (REQ-039) is the lightweight, leading land-gate on the front of the
V: `process.concept: true` makes the single develop step attended, and the develop land refuses
unless `docs/concepts/REQ-NNN.md` exists and the REQ's `concept_refs:` names it. Its stated
doctrine (REQ-039 **Decision 4**) is absolute: *"Spikes/prototypes are throwaway — run to learn,
then discarded, never committed. Only the architectural conclusion survives, in the concept doc."*

That absolute is wrong for a whole class of concept phase, and FlowSteward **REQ-055** is the
first to hit it. FL-G (a folder-management operator console) declares `concept: true` precisely
because its unknown is **empirical, not architectural**: *"does this surface match how I actually
want to manage the tree?"* — a question that **cannot** be answered by a REQ description or a
wireframe. FlowSteward has reworked every net-new UI for exactly this reason (ASCII mockups too
fuzzy; unattended builds missed operator intent — `docs/concepts/ui-feedback.md`). The only thing
that buys this risk down is **building a real, browseable prototype and looking at it** — and that
prototype is not disposable exploration: it is the **contract** the build then wires to the
backend. Discarding it and keeping only a prose conclusion throws away the one artifact the
concept phase existed to produce. The risk the concept phase addresses — *securing the operator's
consent to a concrete UI* — is only discharged by the UI itself surviving as the frozen reference.

So REQ-039 D4 is too narrow. A concept phase has two legitimate shapes: a **throwaway spike**
(architectural/feasibility risk — only the conclusion survives) and a **durable prototype** (the
prototype *is* the deliverable, committed and frozen, the build wires it). The owner's call
(intake 2026-06-26): drop the absolute and let the **concept-phase author decide per REQ** whether
the prototype is kept — no engine-enforced criterion, just a sanctioned choice.

On top of the doctrine, there is a **concrete engine block**. REQ-055 points its `concept_refs:`
at `docs/concepts/REQ-055/concept.md` — a **bundle directory**, the natural home when a concept
phase produces several artifacts (a concept writeup + a prototype walkthrough alongside the
committed prototype code). The `ConceptArtifactGate` (`devsteward/profiles/req/checkpoint.py`)
hard-codes the **flat file** `docs/concepts/REQ-NNN.md` for *both* its existence check
(`self.concepts_dir / f"{req_id}.md"`) and its link check (`f"{req_id}.md" in str(ref)` — which is
false for `REQ-055/concept.md`). So REQ-055 as written would be **refused at the develop land**.
The owner notes this `docs/concepts/REQ-NNN/…` directory reference keeps **recurring** in
FlowSteward — it is the convention the project naturally reaches for, not a stray mistake. The
right move is to **accept it natively** rather than force every concept bundle into one flat file.

This is subtraction, not machinery: we widen one over-absolute sentence and one over-narrow
existence check. Committing a prototype is already just committing code — once the doc-gate is
satisfied the engine never strips it (REQ-063 made the land non-destructive). Nothing new is built;
no step, verb, or skill is added.

## Requirement

The concept phase (REQ-039) must support a **committed prototype as a first-class deliverable**,
and the develop land-gate must accept a concept **bundle directory** — without adding any step,
verb, or skill.

- **Doctrine.** REQ-039 Decision 4's "spikes/prototypes are throwaway — never committed" absolute
  is **amended**: a `concept: true` REQ MAY designate a **durable, committed, frozen prototype** as
  its concept deliverable (the build wires it), or keep the prototype **throwaway** (only the
  conclusion survives). The concept-phase author decides per REQ; the engine enforces no criterion.
  The concept document still captures the architectural conclusion in either shape.
- **Gate.** `ConceptArtifactGate` admits a `concept: true` REQ when **either** the flat file
  `docs/concepts/REQ-NNN.md` exists **or** a non-empty directory `docs/concepts/REQ-NNN/` exists,
  **and** the REQ's `concept_refs:` contains an entry that names the flat file or points inside the
  directory. With neither present, or with the artifact present but unreferenced, it still refuses
  (mirroring the existing existence + link discipline, one altitude up from `docs/plans/`). A REQ
  without `process.concept` is untouched.
- **Documentation surfaces** (same commit): REQ-039 carries a Note recording the D4 amendment and
  cross-linking this REQ; the handbook concept text and `STEWARD.md`'s concept-gate description name
  the bundle-directory form and the committed-prototype option; the `/intake` skill §2c `concept:`
  guidance states both the bundle-directory layout and that a prototype may be kept. (The `/intake`
  skill is hardlinked to its stamped template — one edit covers both.)

## Notes

- **All ACs are hermetic regression** (§2b screen): the oracle is the `ConceptArtifactGate` return
  value over a `tmp_path` req_dir + concepts_dir constructed by the test (`conftest.write_req`); no
  service, secret, network, or lab — coupled gate logic, fast, every gate forever. No
  environment-bound `regression`, no validate phase.
- **develop: fused (default).** This is an *additive* existence-check generalization plus doc edits,
  not a change to the destructive land path — contrast REQ-063, which split because it reworked the
  core path that had lost work. Nothing here can lose work.
- **Change-set surfaces** (one commit): `devsteward/profiles/req/checkpoint.py`
  (`ConceptArtifactGate` existence + link checks widened to file-or-non-empty-directory),
  `tests/test_concept_phase.py` (the three ACs; `conftest.write_req` already accepts `process=` and
  `concept_refs=`), `docs/requirements/REQ-039.md` (a Note amending D4 + cross-link), the handbook
  concept text (`_02-engine`, `_03-workflow`, and the `_01-format` inline comment),
  `devsteward/templates/STEWARD.md` (concept-gate description), and the `/intake` skill §2c
  (`.claude/skills/intake/SKILL.md`, hardlinked to its template). No engine step/verb/skill added.
- **Why no engine enforcement of the doctrine:** committing a prototype is committing ordinary
  tracked code; the land is already non-destructive (REQ-063) and never strips it. The doctrine is a
  documented *option*, not a mechanism — the engine's only concept teeth stay the existence + link
  gate. The "author decides, no criterion" choice (Decision 1) deliberately keeps it that way.
- **Out of scope — the test-role taxonomy gap.** The 2026-06-26 FlowSteward REQ-022 postmortem's
  "process gap (DevSteward)" section (durable live-regression vs one-time validation; fail-hard not
  skip on a missing required resource) is a **separate** engine REQ, to be `/intake`-d on its own. It
  shares nothing mechanically with the concept-phase doctrine and is tracked as a follow-up, not
  folded here.
- **Consumer impact:** unblocks FlowSteward REQ-055 (FL-G), whose `concept_refs:` already point at
  `docs/concepts/REQ-055/{concept,prototype}.md` and whose plan commits a real frozen prototype the
  build wires. After this lands, that REQ's develop land is admitted and its committed prototype is
  doctrinally sanctioned.
- **Localization:** engine/skill/handbook/manual text is technical English; no user-facing localized
  strings introduced.
