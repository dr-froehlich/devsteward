## Context

REQ-037 moved every ledger write to the integration branch so a feature branch carries
**pure code** and the feature→`dev` merge cannot conflict on `.devsteward/`. The close-out
merge is `GitCli.try_merge_no_ff`: on a residual *code* conflict it aborts (restoring the
repo byte-identical) and surfaces a recovery instruction — *"Resolve by hand: `git merge
--no-ff <feature>`, fix the conflicts, commit, then re-run."* That instruction bakes in one
assumption: **an aborted merge means the feature carries unlanded work the operator wants.**

On 2026-06-16 that assumption was false and the guidance was actively harmful. REQ-034's
human validation passed with a green sign-off, but its feature→`dev` merge aborted on
conflicts in `cli.py`/`executor.py`/`git.py`. The branch's engine code turned out to be a
**stale parallel implementation** — REQ-034's behaviour had already been delivered on `dev`
incrementally through the later reworks REQ-037 / REQ-041 / REQ-043, and `dev` already
carried the current implementation with its green tests. The branch was *superseded*, not
ahead. Following the recovery instruction (`git merge --no-ff`, resolve conflicts, commit)
would have **spliced obsolete code back into `dev` and regressed it** — and indeed a trial
merge broke three `dev` tests. The operator had to diagnose this by hand, then hand-edit the
ledger to append a `branch_superseded` event and delete the branch (commit `28dbc1a`).

No `steward` verb expresses "this branch's work is obsolete — close it *without* merging,"
and the only recovery the engine names is the one that regresses `dev`. The branch here had
**divergent** code (not an empty delta vs `dev`), so no purely mechanical signal can tell a
superseded branch apart from a genuinely-ahead one — that call is a human judgment. This REQ
codifies the hand-recovery as a first-class, human-invoked verb and stops the close-out from
steering an operator down the regressing path.

## Decisions

| # | Decision | Rationale |
|---|----------|-----------|
| 1 | Add `steward supersede REQ-NNN`: append a `branch_superseded` event to the integration-branch ledger, delete the unmerged feature branch, leave a clean tree — never merge the branch's code | Codifies the proven hand-recovery (commit `28dbc1a`) into one auditable verb |
| 2 | **Human-only** — the engine never auto-supersedes; an aborted merge still parks/surfaces and waits for an explicit verb | The branch carried *divergent* (not empty-delta) code; "obsolete vs unlanded" is a semantic judgment, and a wrong auto-close silently drops real work |
| 3 | The `try_merge_no_ff` abort recovery instruction names `steward supersede REQ-NNN` as the explicit alternative to the `git merge --no-ff` hand-merge | Stops the engine from steering a superseded-branch operator into regressing the integration branch; offers both the land-the-work and close-as-superseded paths |
| 4 | The `branch_superseded` event captures the abandoned branch's unique-commit shas (vs the integration branch); the verb refuses cleanly (non-zero, no ledger write, no deletion) when its preconditions don't hold | A superseded close is reversible-by-record — the audit trail shows exactly what was dropped — and a misfire can never strand the repo or silently lose work |

## Requirement

A human-invoked verb closes an already-superseded feature branch without merging its code,
and the merge close-out offers that verb instead of steering the operator into a regressing
hand-merge. The engine never decides supersession on its own.

## Notes

Explicitly out of scope: auto-detecting an empty-code-delta branch (the "provably already
fully merged" case) and closing it automatically. The human-only decision (Decision 2) is
deliberate because this REQ's motivating case was a *divergent* branch where no mechanical
signal is safe; a later REQ could add a guarded auto-close for the empty-delta case alone.

First hand-made instances of the `branch_superseded` event live on `dev` from the 2026-06-16
REQ-034 settle (commit `28dbc1a`) — this REQ turns that recovery into engine code. Touches
`GitCli` (the supersede primitive + the `try_merge_no_ff` recovery text), the `req` profile,
and `cli.py` (the verb). Regression-only, real-git ACs in the spirit of `test_plane_split.py`
(the plan-0021 hollow-fake lesson); no System-Test phase.
