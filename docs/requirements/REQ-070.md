## Context

REQ-068 Decision 2 made the develop full-suite gate **deselect** every one-time
`artifact`/`manual` acceptance node-id by id, so a one-time validation of an already-done REQ
never gates a later REQ's develop. The deselect set is built by `build._validation_nodeids`,
which calls `core.verify._pytest_targets(ac.test)` for every `artifact`/`manual` AC. The
docstring already promises *"Manual ACs carry no pytest node-id and contribute nothing"* — but
the code does not enforce that, and it is false.

Two compounding defects make the derivation harvest **garbage** targets from acceptance-criterion
**prose**:

1. `core.verify._is_pytest_command` returns `True` when **any token equals `pytest`**. A
   `manual:` AC is human prose, and a perfectly ordinary one mentions the tool — e.g.
   `manual: run `python -m pytest -m not live` and confirm a `0 skipped` summary`. That trips
   the predicate, so the prose is treated as a pytest command.
2. `core.verify._pytest_targets` then `shlex`-splits the prose and keeps **every token that
   does not start with `-`** as a "target". From the example above it harvests `run`,
   `confirm`, the marker value `not live`, and fatally the bare word **`tests`** — plus, for a
   pytest command that legitimately carries a `-m <marker>`, the **marker value** itself (the
   flag `-m` is dropped, but the value after it is not).

`build._validation_nodeids` feeds those tokens straight into the gate as
`--deselect <token>`. `pytest --deselect tests` deselects the **entire `tests/` directory** —
so the full-suite gate selects **0 of N tests** and reports `N deselected`. That is a
false signal indistinguishable from a zero-match marker expression (`-m regression`), and it
silently turns the standing suite into a no-op: a broken behaviour could now sail through the
gate, the exact hollow-green hole the REQ-028/063/068 line exists to close.

Reproduced against FlowSteward (`steward 0.2.0`, the shipped engine) the moment its config used
the canonical one-flavor `python -m pytest` (REQ-068 / FlowSteward REQ-060): the engine's
computed `exclude_nodeids` contained `tests`, `live`, `manual:`, `run`, `confirm`, `not live`,
and other prose words alongside the legitimate node-ids — and `--deselect tests` emptied the
539-test suite. It went unseen earlier only because a project-supplied `-m` marker in the
`full_suite` command happened to pre-shape selection; the canonical plain command exposed it.

This is a pure engine-logic defect with a coupled oracle — fully provable by regression.

## Decisions

| # | Decision | Rationale |
|---|----------|-----------|
| 1 | A `manual:` AC contributes **zero** deselect targets — make the docstring's promise real. | A `manual:` test string is human prose with no collectible node-id; it must never reach `_pytest_targets`. The convention (`test:` starting with `manual:`) is the signal. |
| 2 | `_pytest_targets` emits **only genuine node-ids/paths** — a token must look like a test target (contains `::`, or ends in `.py`, optionally with a `::` selector) to be kept. | A deselect target is a collectible node-id, never a bare word, a marker value, or prose. This also fixes the `-m <marker>` value leak for legitimate commands. |
| 3 | Fix at the derivation layer (`_pytest_targets` / `_validation_nodeids`), not by tightening `_is_pytest_command` alone. | `_is_pytest_command` legitimately gates per-test *outcome* parsing elsewhere; the deselect-set derivation needs its own node-id discipline regardless. Belt and suspenders: skip `manual:` AND filter to node-ids. |
| 4 | No change to FlowSteward or any consumer; no change to REQ-068's contract. | Consumers author honest `check:` values and ordinary prose; the engine must not weaponize that prose. The canonical `python -m pytest` stays correct. |

## Requirement

When this is done, the develop full-suite gate's deselect set is derived only from real,
collectible test node-ids:

1. `_validation_nodeids` derives **no** target from a `manual:` acceptance criterion (its
   `test:` string is human prose, by convention prefixed `manual:`).
2. `_pytest_targets` returns **only** tokens that are genuine pytest node-ids/paths — a token
   is kept only if it ends in `.py` or contains `::` (a file, a node-id, or a path::selector).
   A bare word (`tests`, `run`, `confirm`), a marker value (`not live`, `regression`), or any
   prose token is never returned.
3. Consequently the full-suite gate never injects `--deselect tests` (or any non-node-id
   deselect), so a project whose REQs include prose-bearing `manual`/`artifact` ACs runs its
   real suite — the gate selects the suite minus exactly the one-time validation node-ids.

```yaml acceptance
- id: AC1
  text: >
    A manual acceptance criterion whose test string is human prose that mentions pytest
    (e.g. "manual: run `python -m pytest -m not live` and confirm a `0 skipped` summary")
    contributes ZERO targets to the develop-gate deselect set: _validation_nodeids over a
    fixture REQ-set containing such a manual AC yields no token derived from that prose — in
    particular never the bare word `tests`.
  test: "python -m pytest tests/test_verify_deselect_nodeids.py::test_manual_prose_ac_contributes_no_deselect_targets"
  check: regression
  status: pending
- id: AC2
  text: >
    _pytest_targets returns only genuine node-ids/paths. Given a real artifact command
    (`python -m pytest tests/test_x.py::test_y`) it returns exactly `tests/test_x.py::test_y`;
    given a command carrying a `-m <marker>` it never returns the marker value; given prose
    tokens it returns none. The kept set is exactly the tokens that end in `.py` or contain `::`.
  test: "python -m pytest tests/test_verify_deselect_nodeids.py::test_pytest_targets_emits_only_real_nodeids"
  check: regression
  status: pending
- id: AC3
  text: >
    End-to-end on the derivation: for a fixture project whose acceptance criteria mix real
    artifact node-ids, a prose-bearing manual AC, and a `-m` marker command, the exclude set
    _validation_nodeids produces contains ONLY the real artifact node-ids and never a bare
    `tests`/marker-value/prose token — so the gate command built from it cannot empty the suite.
  test: "python -m pytest tests/test_verify_deselect_nodeids.py::test_exclude_set_is_pure_nodeids_no_suite_wipe"
  check: regression
  status: pending
```

## Notes

- Sibling to the gating-integrity line: REQ-028 (a skip is not green; the named behaviour
  must run), REQ-063 (a capture-gap preserves a paid-for green, no reset), REQ-068 (deterministic
  routing by `check:`). This closes the deselection-derivation hole REQ-068 opened.
- Out of scope: changing `_is_pytest_command`'s use in per-test *outcome* parsing; any consumer
  change; the `live`/`artifact`/`manual` taxonomy itself.
- A regression already shipped through this hole would have to be re-checked once the gate runs
  the real suite again; that re-run belongs to the consumer's next develop, not this REQ.
