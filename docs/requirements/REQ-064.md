## Context

The left-shift complement to REQ-063. The same FlowSteward REQ-043 incident
(`docs/postmortems/2026-06-23-req-043-capture-gate-discarded-session.md`) had **two** roots
in **different** repos. REQ-063 fixes DevSteward's *cure* — the engine must never destroy
verified work, and an environment skip is not a capture gap. This REQ addresses the
*prevention* of the **other** root, Defect 1, which is FlowSteward's to fix in its own repo
but whose **category** any consumer can reproduce: an acceptance criterion written so its
"green" silently rides hidden environment.

The specimen: an AC file that is **entirely `pg_required`**, classified `check: regression`,
whose green depends on a lab Postgres selected by a gitignored `.env`. Such a test can only
ever **skip-or-pass** depending on whether that hidden environment is present — its green is
environment-bound, which is exactly the property that tripped the capture gate. It was filed
`regression` (a self-contained, headless Build-phase test) when its oracle behaves like a
lab/environment-bound one.

This is the same disease REQ-027 was built to cure — *a coupled or hidden oracle that cannot
disconfirm, slipping past classification* — one layer deeper. REQ-027 made `check:` a
first-class routing key and put the quality judgment where a human is present: **the
`/intake` interview** ("the music is in the intake skill"). It already forbids the *downgrade*
direction (§2b "Honest deferral": never downgrade an `artifact`/`manual` check to `regression`
to make it runnable today). What it lacks is the **detection** of an AC that is *already*
(perhaps unwittingly) a `regression` whose oracle needs a service / secret / network absent
from a clean repo checkout. This REQ adds that screen, and routes the resolution by the
taxonomy's own rule — **oracle coupling** (REQ-027 Decision 2).

Crucially, this does **not** forbid environment-bound `regression` ACs: REQ-063 makes the
engine *tolerate* an environment skip (it is not a capture gap), so such ACs are allowed to
exist. The point is to make the author's choice **deliberate and honest** — not a silent
default that surfaces only when a paid-for session is lost.

Per REQ-027 Decision 5, this stays **out of `steward lint`**: lint validates only that each
AC declares a valid `check:`, never test quality, and DevSteward is tech-agnostic — it cannot
statically recognise a consumer's `pg_required` / `skipif` / env-read patterns. The guardrail
lives where a human is present: the intake interrogation and the handbook taxonomy.

## Decisions

| # | Decision | Rationale |
|---|----------|-----------|
| 1 | **Intake interrogation + handbook prose — no lint rule, no schema field.** | REQ-027 Decision 5: lint enforces `check:` presence/enum only; test quality is intake's job. DevSteward is tech-agnostic, so a static "is this env-bound?" check is infeasible across consumers; the owner already rejected a per-check schema flag (REQ-063). Enforce where a human is present — the seed. |
| 2 | **Screen every `check: regression` AC, then route by oracle coupling.** The screening question: *does this regression's oracle need a service / secret / network absent from a clean repo checkout?* On yes, apply REQ-027 Decision 2: a **decoupled** oracle (a live service / golden output) is really `artifact` → reclassify and declare the owning lab in `process.lab`; an oracle **coupled** to the code that merely needs a runtime stays `regression` **and** the required environment is recorded in the REQ. | Reuses the taxonomy's own logic rather than inventing a new axis. Complements REQ-027's "never downgrade artifact→regression" with detection of an already-downgraded AC. It steers, not forbids — consistent with REQ-063 making the engine tolerate env-skips. |
| 3 | **A kept-`regression` AC's required environment is recorded in the REQ prose** (Context/Notes — "required environment: …"), not in a new frontmatter field. | No schema growth (Decision 1). It is operator/batch-lane documentation, not a routing key the engine consumes; prose is the honest home for "this green needs Postgres + creds wired up." |
| 4 | **Dogfood the taxonomy (mirrors REQ-027 Decision 8): regression-presence ACs + one `manual` sign-off.** Regression tests assert the screening guidance is present in the intake skill file and the handbook taxonomy; one `manual` AC has a human run `/intake` on a deliberately environment-bound idea and confirm the screen fires and the result is classified honestly. | The behavioural proof — *does the screen actually change how an AC gets classified?* — has a genuine human oracle; a presence-only proof would be the "hollow green" REQ-027 exists to kill. The REQ practises the discipline it ships. |
| 5 | **Scope: the `/intake` SKILL.md (repo + stamped template, kept identical) and the handbook taxonomy (`_01-format.qmd` / `_03-workflow.qmd`).** Not the engine, not the operate-the-engine black-box manual, not lint/schema. | The guardrail belongs at the *authoring* surface; the engine *cure* is the sibling REQ-063; the black-box manual is for operating the engine, not authoring ACs. |

## Requirement

- `/intake` (§2a–§2b) gains an **environment-binding screen**: every `check: regression`
  criterion is screened against the question *"does its oracle need a service / secret /
  network absent from a clean repo checkout?"*
- On a positive screen the skill **routes by oracle coupling** (REQ-027 Decision 2): a
  **decoupled** oracle → reclassify the AC `artifact` and declare the owning lab REQ in
  `process.lab`; an oracle **coupled** to the code that merely needs a runtime → keep it
  `regression` **and record the required environment** in the REQ prose. The skill never
  leaves a silent environment-bound `regression`.
- The handbook taxonomy documents the **environment-bound-`regression` smell**, the screening
  question, and the oracle-coupling routing, with the FlowSteward REQ-043 case as the worked
  example.
- The repo `/intake` skill and the stamped template skill stay **identical**.
- No `steward lint` rule, no schema field, and no engine change are introduced (the engine
  side is REQ-063).

## Notes

- **Sibling, not dependency.** REQ-063 (engine cure) and this REQ (intake prevention) are
  independent fixes from one postmortem; either can land first. The handbook prose should read
  consistently with REQ-063's land-time behaviour (an environment skip is not a capture gap),
  but that is editorial consistency, not a build-order dependency.
- **Does not forbid environment-bound regression.** The screen makes the choice deliberate; a
  legitimately coupled test that needs a runtime stays `regression` with its environment
  recorded, and REQ-063 ensures the engine tolerates its skip in the bare extract.
- **Out of scope:** the FlowSteward-side fix of the actual REQ-043 AC (theirs); any
  `steward lint` heuristic that tries to *detect* env-binding statically (infeasible /
  tech-specific — Decision 1); engine behaviour (REQ-063).
- **Localization:** all skill/handbook text is technical English; no user-facing localized
  strings introduced.
- **Surfaces touched:** the `/intake` SKILL.md (the repo's `.claude/skills/intake/` and the
  stamped `devsteward/templates/.claude/skills/intake/`, kept identical) and the handbook
  (`devsteward/handbook/_01-format.qmd` / `_03-workflow.qmd`). Lint, schema, the engine, and
  the black-box manual are explicitly **not** touched.
