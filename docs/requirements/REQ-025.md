## Context

REQ-008/REQ-012 left the account provider a *switcher only*: `precheck()` runs
`cswap --switch-to N` (when pinned) and a throwaway `cswap --status`, then always returns
`ok=True`. There is **no numeric quota gating, no rotation, and nothing printed** — a
`steward run` gives no sign that cswap exists, which account is active, or how much of the
5h/7d budget is spent. The only quota reaction is reactive: the engine notices a usage
limit *after* `claude` already burned a turn hitting it (REQ-016), then stops the whole
run. Peter cannot watch his utilization, and an unattended run cannot survive a reset.

The proven reference, `Theresa/run_batch.py` (evolved from
`examengineer/convert/run_batch_conversion.py`), already solves this and was never used as
the model the first time — the cause of REQ-001's lament about diverging copies. Its
machinery: read cswap's cached `usage.json` (refreshed by `cswap --list`) for per-slot
5h/7d percentages; *before each step* ensure the active account is below a gate, **staying
on the current account until it saturates** (no flapping), swapping to the lower-7d
account when it does, and **waiting interruptibly** for the soonest reset when all are
saturated; print every decision. Plus a two-level graceful stop: one Ctrl-C finishes the
running step (or ends a quota wait immediately) and exits; a second kills the child.

That reference also fixed two bugs from the ExamEngineer original that DevSteward must not
re-introduce: **(a)** Ctrl-C was forwarded to `claude` because the child shared the
parent's process group — fixed with `start_new_session=True` so the engine owns the
signal; **(b)** a quota wait was a plain `sleep`, so a Ctrl-C during the wait was only
honored *after* the (possibly hours-long) sleep returned — fixed with an interruptible
sleep that polls the stop flag. DevSteward's `run_claude` today spawns `claude` **without**
`start_new_session=True`, so it carries bug (a); and it has no quota wait at all.

This REQ ports that machinery onto the engine seams, deliberately **excluding the adaptive
gate** (the reference's `current_gate`/cost-history tightening): the threshold here is a
plain fixed fraction (default 70%), overridable per-run and per-project. It also threads
the model/effort and threshold through the CLI, defaulting to **Opus / high effort**, and
keeps the whole thing optional and self-degrading so consumers without cswap are unaffected.

## Requirement

When `accounts.provider: cswap` and cswap is usable:

- **Visibility.** Before each step the engine prints a one-line utilization summary
  (active slot + every slot's 5h%/7d%); every account switch and every quota wait prints a
  line naming the slot, the percentages, and the reset clock/ETA.
- **Fixed gate.** No step starts while the gating account's 5h usage is at or above the
  threshold (default 70%, fraction or percent; overridable by `--threshold` and
  `accounts.threshold`). The gate never tightens adaptively.
- **Rotation / pin.** With no pin, the engine stays on the current account until it
  saturates, then switches to the lower-7d below-threshold account; with `--use N` it pins
  to slot N and never swaps.
- **Wait through reset.** When all eligible accounts are saturated the engine waits
  interruptibly for the soonest reset and resumes — it does not end the run.

Graceful stop (any provider): a single Ctrl-C during a `steward run`/`advance` finishes the
currently running step and then exits cleanly; a Ctrl-C while the engine is waiting for
quota ends the run immediately (not after the wait). A second Ctrl-C kills the running
`claude` child and exits. The `claude` child never receives the engine's Ctrl-C directly.

Model/effort: headless runs default to `claude-opus-4-8` at `high` effort, overridable by
config (`claude.model`, `claude.effort`) and `--model`/`--effort`.

Degradation: `provider: single`, or `cswap`/usage data absent, runs plain `claude` on the
current account with the gate skipped and a logged notice — never a hard failure.

## Notes

- **Out of scope:** the adaptive/cost-history gate (`current_gate`, `batch_job_costs.json`),
  a `STOP_BATCH` file marker (Ctrl-C is the only stop trigger here), a configurable cswap
  binary path/name, and any rotation policy beyond prefer-current / lower-7d / pin-by-index.
- **Localization:** all engine console output is operational/technical English; no
  user-facing German strings are introduced.
- Architecture: usage reading + the gate-and-rotate loop extend `CswapAccountProvider`
  (`core/accounts.py`); the `StopController` (stop flag + active-child handle + SIGINT
  handler) is a small new `core` seam the run/advance drivers own and the executor loop +
  `precheck()` consult; `core/claude.py` gains `start_new_session=True` and model/effort.
- Reference for the exact shapes (do not diverge): `Theresa/run_batch.py`
  `usage_snapshot` / `pick_and_ensure_account` / `_interruptible_sleep` / `_sigint` /
  `stream_claude`. This REQ is the port REQ-001 always wanted.
