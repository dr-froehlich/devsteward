## Context

Stage C of REQ-047 (plan `docs/plans/0026-single-source-of-truth-trunk-based.md`),
layered on the trunk-based foundation (REQ-048) and the universal transaction boundary +
typed errors (REQ-049). Implemented **by hand**, not under `steward` — the engine has not
yet earned the right to drive its own repair.

This closes REQ-047 Decision 5 (it absorbs the old REQ-046-F2): **a recorded commit must
reproduce its own green.** The develop gate runs the named acceptance tests against the
*working tree*, which includes ``.gitignore``d / excluded / never-staged state the work
commit will not capture (``commit_code`` is ``git add -A`` minus ``.devsteward/`` — it
cannot stage an ignored file). So a green can rest on files the commit drops; the next
checkout of that commit fails the very test the engine certified. The land now refuses such
a green and names the gap, so nothing is certified that the commit cannot stand up alone.

The guarantee is narrow and deliberate: it does not make the build hermetic, it makes the
*recorded commit self-sufficient for the green it claims*.

## Decisions

| # | Decision | Rationale |
|---|----------|-----------|
| 1 | **Tightest form, post-commit** (`Executor._assert_green_captured`): after the work commit, re-run the step's named acceptance gate against a **clean extract of the commit** (`git archive <sha>` → a throwaway dir — only the commit's tracked content, no ignored/untracked working-tree state). A named test that no longer passes is a capture gap. | Directly verifies the property ("does the commit reproduce its green?") with no heuristic about which paths count as "source/test" — the plan's cheapest form (`git status --ignored` filtered by path) needs exactly that heuristic and would false-positive on `__pycache__`/`.venv`. |
| 2 | **No worktree for the extract** — `git archive | tar -x` into a tempdir, never `git worktree add`. | Trunk-based forbids linked worktrees, and INV-1 (REQ-049) actively refuses if one exists; an archive extract is just files, nothing for INV-1 to trip on. |
| 3 | **Explicit rollback, then a pass-through `PreconditionError`.** A `PreconditionError` passes *through* the transaction boundary **without** a rollback (REQ-049), so a naive "raise after the work commit" would strand the work commit — the half-state Stage C forbids. The check restores the pre-commit snapshot itself (`git reset --hard`), *then* raises the typed precondition naming the gap. | Yields **both** a clean tree (the work commit undone, the REQ flip reverted, the ledger writes wiped — `reset --hard` to the snapshot) **and** the gap-specific recovery line ("commit them or fix .gitignore"). A non-typed exception would roll back via the boundary but lose the precise recovery; a bare `PreconditionError` would keep the recovery but strand the commit. |
| 4 | **Real-git, named-tests-only, fail-open safety net.** No-op when there is no repo (the in-memory fake), no named tests, an unusable test env, or no extraction tooling. The interpreter is resolved against the *real* repo (the venv is environment, not commit content); only `step.verify` is re-run (not the full suite). | A self-check that cannot run must not brick a legitimate land; the environment's usability is the verifier's domain (`NoUsableEnvError`), not a capture gap. The named tests are what claim the REQ's behaviour — they are the green whose self-sufficiency matters. |

## Requirement

- After the work commit in the land path (`mechanical_land`) and the deferred-develop commit
  path (`commit_deferred`), the engine asserts the committed tree reproduces the step's named
  green; a green that depends on uncaptured (gitignored / excluded / never-staged) source or
  test state is refused.
- On a capture gap the work commit is **rolled back** to the pre-command snapshot and a typed
  `PreconditionError` (carrying a recovery line that names the gap and how to close it) is
  raised — nothing is certified, no `done` flip, no cursor move, no stranded half-state.
- A self-sufficient green (depending only on committed source) lands normally — the check
  raises no false positive.

```yaml acceptance
- id: AC4
  text: Land refuses to record a develop green that depends on uncaptured (ignored/excluded/uncommitted) working-tree state; the gap is named, the REQ does not flip done, and dev is left clean (no stranded work commit).
  test: "tests/test_commit_integrity.py::test_land_refuses_uncaptured_green"
  check: regression
  status: pass
```

## Notes

- **Divergence from the plan's literal wording.** Plan Stage C says "raise
  `PreconditionError(recovery=…)`" after the work commit. Taken literally that strands the
  commit (a pass-through precondition gets no rollback under REQ-049). The build honours the
  plan's *intent* (a typed precondition naming the gap, nothing advanced) by rolling the
  commit back **first**, then raising — the plan's "tightest form needs (b)" resolution. The
  plan's "Stage C — as built" note records this.
- **Editable-install caveat (does not affect the live path).** Re-running tests against the
  archive imports the package under test from the extract — *unless* the package is
  pip-editable-installed and shadows it on `sys.path` (the `[[req-test-command-python-m]]`
  footgun). That only bites a project testing *its own* editable-installed code (DevSteward
  dogfooding itself, which Stage C is hand-driven precisely because the engine isn't yet
  sound enough to self-drive). Consumer projects (FlowSteward) aren't editable-installed, so
  the archive extract is authoritative there; AC4's synthetic repo isn't editable-installed
  either.
- REQ-051 (lab fixtures upstream; the System Tester never improvises) is the remaining
  REQ-047 stage (AC5); it is independent of this one and depends only on REQ-048.
